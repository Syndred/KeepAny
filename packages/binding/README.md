# 账户绑定消费端（阶段 3 验证切片）

本包消费 KeepAnyAdm 的人工设备码挑战和短期签名票据。商业仓库保持独立；这里未复制其源码，也没有连接生产账号。当前接口依据 2026-09-28 读取到的商业侧本地代码和合同，商业侧 P-256/DPoP 续期改动尚未提交，联调前应重新核对字段。

## 已实现的边界

- 本地实例生成随机 `instanceId` 和不可导出的 P-256 私钥；Dexie 存储私钥 `CryptoKey`、公钥、待轮询设备码、精确 `bindingId` 与商业 `sub`。默认仅申请 `sync:read`，调用方额外申请 `sync:write` 必须在产品 UI 明确展示。
- 固定 issuer 必须是 HTTPS 或本机回环 HTTP；JWKS 路径固定。`bindingTicket` 校验 RS256、签名、`kid`、issuer、`aud=keepany-binding`、`scope=binding:complete`、`iat/exp≤60s`、实例哈希、请求范围，以及轮询响应中的精确 `bindingId`/`sub`。新绑定与本地挑战、商业主体切换在 Dexie 事务内判定；重复同一 ID 幂等，其他主体需要显式切换参数。
- 首次轮询如收到设备绑定的刷新凭证，和绑定关系同一事务持久化。续期用本地设备私钥为商业 `/refresh` 签 `dpop+jwt`，校验返回的 `aud=keepany-sync-bound` 访问令牌后按同一 `requestId` 原子替换刷新凭证。请求超时可在 25 秒内重试同一 ID；结果超过该窗口时停止自动续期，避免错误重放撤销凭证族。访问令牌只在调用返回值中，不持久化。
- `/state` 查询使用设备证明、精确绑定和主体校验；明确返回撤销后清除本地凭证。网络失败不推断为已同步或仍有效。

## 威胁与未完成

本地 IndexedDB 中刷新凭证仍是敏感数据。不可导出私钥限制原始密钥导出，但同源脚本被控制时仍可能调用签名；浏览器数据清理会丢失身份和凭证。此实现没有证明能抵抗 XSS、恶意浏览器扩展或本机恶意软件，不把 `CryptoKey` 当硬件安全模块。

商业接口没有向任意跨源浏览器开放 CORS。本包的 `BindingTransport` 必须由固定 issuer 的可信服务端或受控同源桥调用；直接在静态 PWA 中实例化不会完成远端绑定。核心 Web 绑定 UI、可信桥、商业端真实账号回读、生产 JWKS/凭证管理和设备撤销传播均待联调。同步服务接受绑定访问令牌的服务端验签仍是独立工作，绑定票据不能作为同步 Bearer。

未对真实 KeepAnyAdm 账号申请、批准、续期或撤销；测试使用本地 RSA/EC 签名 fixture 和 fake IndexedDB。正式官方云同步上线前还需完成权限、撤销状态、密钥配对、冲突 UI 和加密附件的端到端验收。
