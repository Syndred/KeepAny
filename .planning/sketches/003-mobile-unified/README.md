# 资产与账号整合草图 v2

用户要求：原稿功能覆盖不足；普通账号与密码整合展示；项目、域名、订阅、实物集中到资产，卡片可看年限、任务进度、到期与费用。不是批准把密码写入普通数据库。

## 导航与两版

- 底栏：概览／资产／账号／待办／更多。没有第二个重复账号列表或独立密码库底栏。
- A：分类资产卡片，重点展示该类型的时间、费用与进度。建议A，仍待用户确认。
- B：同样的完整入口，换成紧凑资产清单，保留全部指标。

默认三屏：资产汇总、账号与密码、资产详情。第三屏可在项目／域名／订阅／实物／账号间切换。支持简中／英文、360／390／430／桌面、空资料／缺日期／密码保存失败状态。

## 可检查的交互

- 资产类型筛选与搜索；项目待办进度随勾选变化；域名定位所属项目；订阅按距续费显示；实物购入年限与金额。
- 账号列表原位解锁，多组凭据、附加标识、密码显示／隐藏、统一编辑与历史入口；锁定移除解密详情和私密条目。
- 账号和登录资料各自删除范围；示例新增账号；账号保存成功但登录资料失败时明确分开并提供重试。
- 更多保留收录、账本、集合、分类标签、资料引用、安全管理、备份、回收站、AI、助手与同步设置。项目详情另保留改名／收尾、外链、宣传资料，实物保留借还／维护／图像票据。

这些是示例流程，菜单末级的细节并未全部展开。**不能把已有入口／模拟反馈当作功能移植完成。** 完整功能的正式实现与验收去向见 `docs/mobile/手机功能整合与完整覆盖-v2-20261027.md`。

## 数据边界

全部样本在当前页内存，刷新重置。日期固定以2026-10-27举例；不读取真实资料、不打开或修改真实KDBX、不写数据库／文件／剪贴板、不调AI，不修改原4180。

“账号＋密码”只整合界面和入口；密码仍属独立KDBX。“域名”是原项目域名的派生行，不新增domain kind，不重复计资产。费用分币种，并区分账本、购入金额和预计费用。原 `.ka1`／KDBX合同保留。
