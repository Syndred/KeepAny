# 用户身份体验与验收记录模板

2026-10-28，用户明确要求固化为各项目的交付规则。KeepAny的强制约束在根AGENTS.md；本机全局AGENTS.md也已追加通用规则，供后续本机项目读取。全局文件不会随本仓库推送到其他设备，迁移环境时需保留这份通用要求。

## 判定原则

验收以需求和用户能完成的任务为起点。功能可用、视觉正常、代码边界正确、主控本人实际体验和独立复核分别记录；通过数量不能代表覆盖完整。主控必须亲自体验最终候选，独立复核不代替本人体验。只讨论/调查时遵守用户要求，不擅自恢复产品修改。

每项只允许记录：通过、失败、未验、阻塞、证据不足、不适用。只有不适用并给出可核对理由的项可排除；范围内其他非通过状态均阻断“本轮验收完成”。不得把未知、未验、工具就绪或HTTP200写成业务成功。

## 开工和候选信息

- 用户需求/验收范围；明确哪些旧区域只保留历史证据。
- 源码提交、分支、工作区本地修改、fetch/安全同步结果。
- 实际候选来源与摘要；本机地址、入口脚本/资源摘要；源码和编译包证据分别标注。
- 浏览器/设备、语言与宽度、隔离资料、公开接口和准备方式；工具降级或缺失如实记录。
- 实现者、主控体验者、独立复核者与职责；缺少独立复核不可填写已完成。

验收合同在实施前由需求建立。新增发现追加ID，不用当前错误实现当正确预期。纯文档变更说明无用户流程/视觉影响，只核对内容、引用、事实和diff；后端任务使用公开API/CLI及状态合同，UI项目保留真实UI路径。

## 覆盖表

每个需要独立判断的入口/状态/数据/尺寸组合各占一行。支持拆分场景组，但各组ID、预期和未覆盖组合必须可追踪，不能仅用“8项通过”代替表格。

|验收ID/需求|入口与操作|前置资料|状态|语言/尺寸|需求预期|黑盒/白盒/视觉方法|实际结果|证据|消费版本|判定|
|---|---|---|---|---|---|---|---|---|---|---|
|待填写|正常导航入口及逐步动作|空/单/多、长短资料|适用状态|实际环境|先于实现确定|各面分开记录|执行后填写|回执/日志/已查看截图|提交/候选摘要|未验|

状态清单：默认、hover、focus、pressed、展开/收起、选择/清除、加载、禁用、成功、失败、取消、重新进入/刷新。每个入口说明适用项；不要求不存在的状态，不允许无理由跳过适用状态。

数据清单：空/单条/多条、完整/极简、长标题/长网址/长备注、缺失可选资料、必填/非法输入。组件进入新容器、网格或嵌套时独立列场景，原独立组件通过不代表组合通过。

布局变更按项目语言和断点检查；KeepAny为zh-CN/en与390/768/1280/1920，并补用户实际宽屏。改变布局的交互状态必须有实际截图检查，不用默认页面截图代替。

## 三种验证与主控用户体验

**黑盒**：使用最终候选，从可见入口完成正常、取消、异常、保存与重新进入/刷新回读；副作用与拒绝后的无变更均核实。使用虚构账号、密码和模型数据；测试准备可采用标明的夹具或备份，不能把内部注入伪称按钮操作。保留每步预期、实际和业务最终结果。

**白盒**：追踪路由、事件处理器、状态转换、输入规则、权限/持久化边界、共享组件调用位置和CSS作用范围。运行针对性单元/集成/回归检查；不以行覆盖率或编译通过代替正确性。注意外层stretch、宽度分配、min-width、弹层遮挡和异步状态变化。

**视觉**：实际打开每张用于判断的截图；核对操作前后、滚动/遮挡、文字可读性、换行、对齐、相邻元素高度、菜单/浮层边界、焦点和手机触控。元素存在、数量正确、截图已生成均不是视觉通过条件。记录所查看的状态，避免重新登录/解锁/刷新后状态已收起却仍标为展开态证据。

**主控用户体验**：亲自用最终候选从导航入口走完任务；记录“我做了什么→看到了什么→任务是否完成”，检查用户是否能发现入口、理解反馈、恢复错误和找回保存结果。不得只通过源码理解推断体验，也不得用代理总结替代。

## 独立复核与修复闭环

非实现者/独立代理从需求和冻结合同独立判断，重放关键用户路径并确认失败/未验项。主控汇总时保留分歧和未覆盖范围，不以代理“完成”通知直接将项目标为通过。

每个缺陷记录：原合同ID、有效修前复现、实际影响/根因、修复提交、同输入重放、邻近回归、最终候选和前后证据。准备失败不算产品失败；保留其原因，不通过删用例、降标准、改预期或重试凑绿隐藏问题。代码/样式/组合改变使相关旧通过项失效；最终消费输入变化后必须补验，历史结果仍保留并标注版本。

## 自动检查与完成报告

可自动检查的合同ID与结果完整性、证据文件存在/摘要、候选身份和相关测试退出码应接入项目检查或CI。机器不能仅靠截图存在证明人工看过，也不能仅靠覆盖表填写完整证明需求已覆盖；这两项仍需实际体验和独立复核。

**当前能力边界**：本次只固化规则、模板和已发现失败记录；现有CI继续检查既有单元/构建/特定流程与便携包。本次没有新安装“状态覆盖完整性”CI门禁，也没有声称CI能自动证明全部视觉状态。后续产品交付必须记录自动门禁是否已接入；未接入时人工完成条件仍逐项适用。

最终报告固定分列：

- 功能：通过/失败/未验及具体合同ID。
- 视觉：实际查看的状态、尺寸、资料组合及问题。
- 白盒：检查路径、针对性测试和影响范围。
- 主控体验：真实任务路径与最终结果。
- 独立复核：复核者、实际候选、分歧及缺项。
- 剩余问题、证据不足、阻塞与未覆盖范围。
- 候选版本、提交/推送/本机部署/公开发布状态。

范围内仍有失败或未验，结论必须为“未完成”。修复、测试、文档固化和产品验收是不同结果，不互相替代。不得承诺零缺陷；完成结论仅限合同中有证据的范围。
