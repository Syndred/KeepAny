# KeepAny 组件与样式选型调研

2026-10-28。用户最新要求：先调研主流组件库、CSS方案并确认选型，再继续这批 UI 修复。此前草图仍待确认，本轮没有安装新依赖、修改正式应用或更新 4180。

## 当前代码的实况

- React、TypeScript、Vite 已有。
- package.json 已安装 Tailwind CSS 4.3.3 与同版本 Vite 插件；apps/web/vite.config.ts 已注册插件。
- apps/web/src 内未找到 Tailwind CSS 入口导入、@theme 或 @apply；现有主样式以全局类名和自写 CSS 为主。不能把“安装 Tailwind”描述为“已经统一使用 Tailwind 设计体系”。
- 没有 components.json。Button 源码只声明参考 shadcn/ui 组合方式，实际由 Radix Slot、CVA 和全局 .button 样式构成。Select / Dialog 使用 Radix 的真实交互原语，但并未建立完整统一的上层组件体系。
- 日期为原生 input[type=date]；个人工作区点击只调用同名 toast。已发现问题的修复不需要额外代码修改许可。此前自动审批拒绝的是额外浏览器探查命令，并非修改产品源码。

## 社区使用依据

[State of React 2025 的 UI Libraries 调查](https://2025.stateofreact.com/en-US/libraries/component-libraries/)指出，在该调查样本里 MUI 使用率领先，shadcn/ui 快速增长并接近。相同调查的 CSS Tools & Libraries 一节中，Tailwind CSS 和 CSS Modules 分别列在前两位。这是受访者使用经历，不是整个市场份额，不据此宣称“所有人都用某库”。

## 候选比较

|方案|上游提供的内容|样式路径|对 KeepAny 的判断（工程评估）|
|---|---|---|---|
|shadcn/ui|统一组件源码、默认外观及组合规范；原语可选 Radix / Base UI|Tailwind CSS 4 + CSS主题变量|适合保留 KeepAny 的黄色纸面、描边、椭圆按钮与自定义卡片；可沿用已有 Radix 交互。源码由项目持有，后续更新和定制仍需维护|
|Mantine|core 组件、日期、菜单、弹窗、表单等同一生态组件包|官方推荐 CSS Modules + MantineProvider主题|现成组件较完整，统一行为成本较低；若优先直接使用完整成品库，这是备选。需要替换现有基础控件并适配其主题|
|Ant Design|面向企业 Web 应用的成套组件、表单和日期组件|ConfigProvider、设计tokens / CSS变量|表单与账本适配自然；现有个性主题需要系统定制，迁移不应再混用其他基础组件|
|MUI|Material Design 的成品组件与主题系统|默认 Emotion + ThemeProvider|成熟应用体系；如果采用则应统一采用其主题/组件路径，现有纸面主题需要较多视觉适配|

库名数量不能判断体系是否统一。React、组件库、交互原语、样式方案和图标各有职责；真正需要约束的是同一职责只能有统一来源与入口，而不是每页分别决定尺寸、圆角、状态和菜单行为。

## 推荐（待用户确认）

**根据用户继续追问统一采用最新版的方向，修订建议：保留 React / TypeScript / Vite，UI统一采用当前 shadcn/ui 的 Base UI 路线，CSS统一使用 Tailwind CSS 4 与一个主题变量入口。尚未开始正式迁移。**

这项推荐基于现有品牌与迁移风险，不把流行度当作自动适配证明。

此前建议 Radix 主要为了减少已有控件迁移，并非 Base UI 存在不可使用的障碍。2026-07 shadcn 将新项目默认改为 Base UI；官方明确 Radix 仍全面支持。两者是独立的交互基础库，不是同一库的新旧版本。此次重整 UI 可以将上层组件统一迁至 Base UI，迁移中逐组替换，收尾清理本项目直接使用的旧 Radix 控件。

2026-10-28 已查询 npm latest 元数据：@base-ui/react 1.9.0、tailwindcss 4.3.3、shadcn CLI 4.23.0，均声明 MIT。Base UI peer 允许 React 19，与当前 React 19.3.0 的声明范围相容；这只是声明兼容，实际构建、交互和表单仍需验证。shadcn 4.23.0 是 CLI 版本，生成的组件源码另记录上游来源，不把 CLI 版本冒充所有组件的版本。实施时采用最新稳定版并锁定，不使用 canary。

正式迁移后的边界：

- components/ui：官方组件源码经必要主题适配，保留可追溯来源、许可证与原有测试；不再以“参考组合模式”的自写样式冒充正式接入。
- 一份主题：颜色、字体、间距、文字按钮椭圆形、图标按钮尺寸、卡片圆角、阴影、焦点、弹层层级。
- 页面布局：Tailwind 的统一断点、grid/flex/gap/max-width；有特定图形需求的少量样式采用局部作用域，避免全局选择器串改控件。
- Button / Input / Select / Dialog / DropdownMenu / Popover / Calendar / Tabs / Sidebar / Card 等统一进口与用法。日期采用官方 Calendar + Popover 的组件路径。
- 保留 TanStack Router、RxDB、i18next、KDBX、dnd-kit 等不同职责的现有实现。该选型不构成数据模型/密码库/兼容协议迁移授权。

如果用户优先要求“从包里直接导入整套已维护成品组件，减少本项目持有的 UI 源码”，则建议选择 **Mantine + CSS Modules**，不再另外叠加 Tailwind / shadcn。两条路线择一。

## 确认后的执行

1. 锁定单一组件路线及样式入口，记录组件来源与版本；先做真实基础组件展示页，验证按钮、日期、菜单、弹窗、Tab和各状态。
2. 将草图换为所选真实组件，确认主题效果；此时不把静态 HTML 草图当实现截图。
3. 按控件和页面逐组迁移，随迁移删除已替代的旧全局规则，不长期保留同职责两套 UI。
4. 修复本批已列问题，做中英文、窄屏/宽屏和真实 hover / focus / dragging / open / disabled 及保存回读检查，再按真实候选执行 QA 与设计验收。
