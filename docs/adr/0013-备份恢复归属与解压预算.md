# ADR 0013：备份恢复归属与解压预算

日期：2026-09-30。状态：本机实现、固定包及隔离PostgreSQL验收通过；生产与完整安全审查未关闭。

## 问题与决定

ADR0004和ADR0006已限制一个浏览器数据集只绑定一个端点／账号／工作区／scope，但原普通恢复只合并记录，没有同时校验或保存归档来源。已绑定B的资料可恢复A归档，之后被当作B的待传记录；未绑定资料恢复后又可认领另一来源。修复前专用归属回归5项中4项失败，见[反例](../evidence/2026-09-30/backup-boundaries/restore-identity-before.json)。

普通恢复必须服从同一归属规则：

1. 已绑定目标只接受四项来源完全一致的备份；其他来源或无来源旧归档，在图片、日志和记录写入前拒绝。
2. 未绑定目标可恢复无来源旧归档；有声明来源时，来源绑定、图片和恢复日志在同一FileStore事务中提交。RxDB记录仍通过既有可重放恢复日志写入，不声称FileStore和RxDB存在跨库原子事务。
3. 认领来源和恢复共用原有`withRenewalLock`。存在恢复日志时禁止新认领；重放继续核对日志来源与持久绑定。已经绑定且无法证明来源的旧日志保留待处理状态，不静默并入当前范围。
4. 跨来源走现有显式迁移：核对来源与目标、目标服务预检、目标备份下载并重新选择验证、逐项冲突选择，再本机合并／同步。普通恢复不能替代该决定流程。

`sourceBinding`是归档内的自声明信息，不是服务签名、授权或完整云端同步证明。备份不复制凭据、工作区密钥、epoch、远端游标、同步队列或冲突状态；恢复后需另行完成同一来源的授权和密钥配置。

## 输入与解压

继续复用已有Web Crypto和fflate，不新引入密码或ZIP库。

- 归档输入最大100MiB，加密容器最大100MiB＋36字节头＋16字节AES-GCM标签。加密／解密在导入密钥、PBKDF2和AES前检查；正式文件选择在`arrayBuffer`前检查`File.size`，用双语文案提示。
- 先通过fflate只读ZIP元数据，过滤路径、重复项、压缩类型、项数和声明总输出；`filter`返回false，不按不可信的原始长度分配解压缓冲区。
- 用fflate流API每次输入4096字节压缩数据，核对实际每项与总输出，300MiB／10003项上限；声明长度与实际长度不一致立即失败，不返回截断内容。最终沿用manifest、记录和附件的既有校验。
- 正式v1只写普通单磁盘、非ZIP64、已知本地长度的`zipSync`归档。未知长度descriptor容器明确不支持。按普通EOCD确认本地记录结束位置，只传入本地段和4字节已验证的中央签名作尾部空项的必要前瞻；不把中央CRC或目录元数据送入本地记录扫描器。合法附件含PK头或中央CRC恰好为PK头仍能恢复。

采用的接口来自[fflate官方文档](https://github.com/101arrowz/fflate)，普通EOCD字段来自[PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)。实现使用已安装依赖，未复制新的第三方业务源码；该适配层不是通用ZIP阅读器，也不构成完整安全审计。

## 验证与限制

归属7项、加密7项、ZIP11项回归均通过，含中断／重开、身份认领交错、事务失败回滚、未知旧日志、合法PK内容、合法中央CRC与尾部空项。合成301MiB输出、声明2字节的归档在第一个压缩块产生约3.93MiB输出后拒绝，未继续解压或返回部分内容，见[审查报告](../evidence/2026-09-30/backup-boundaries/archive-review.json)。精确100MiB密码边界使用受控密码原语避免不必要的大规模AES计算；真实小文件的加密／解密、错误密码和篡改回归保留。正式文件选择另用真实稀疏超限文件验证早退，不把巨量载荷提交仓库。

固定Web包41项包含中英普通恢复与显式迁移；另外2项以同一固定包连接真实本地HTTP同步服务和PostgreSQL，验证数据归属、冲突、墓碑、丢应答重试和加密原图。对象存储是本机合成服务，浏览器是隔离上下文，不代表生产云桶或物理双设备。全部444项单测使用独立PostgreSQL测试环境通过。[汇总](../evidence/2026-09-30/backup-boundaries/checks.json)。

真实低存储／浏览器清理、物理断电、生产账号／HTTPS／对象存储／双设备、完整安全和法律审查仍有独立门槛。暂停的密钥epoch工作未恢复，独立商业仓库未修改。
