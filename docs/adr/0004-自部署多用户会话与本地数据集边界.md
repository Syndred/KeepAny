# ADR 0004：自部署多用户会话与本地数据集边界

日期：2026-09-28。状态：本轮实施决策，阶段 3 的其余退出条件不因此自动完成。

## 决定

1. 新增独立的 `self-host-session` 模式，采用固定版本 Better Auth 1.7.6 的官方 Hono handler、PostgreSQL 适配器和邮件地址/密码登录。保留现有 `self-host` 静态单主体 Bearer 与商业 `bound` 模式，三种模式的凭据互不接受。Better Auth 用户 ID 加 `selfhost:` 前缀后才成为同步工作区成员主体；绝不按邮箱与商业身份合并。密码哈希和会话令牌只由 Better Auth 处理，核心不自制密码协议。
2. Better Auth 四张核心表由其同版本生成的 SQL 固定为新迁移 007，不改 001–006。复用现有工作区成员表、PostgreSQL 事务内的读写检查，以及本机数据集的 `endpoint/accountId/workspaceId/scope` 原子绑定。客户端先从服务端会话获取稳定主体，再构造同步 scope；每次预检须与该主体一致。退出登录后本地资产仍可离线查看和导出；同一浏览器本机数据库不自动切到另一账号，错误账号不能认领或推送原数据集。
3. 支持拓扑限定为生产环境中 Web 静态资源与 Hono API 共用一个 HTTPS origin，由反向代理转发 `/api/auth/*` 和同步 API；本机开发只允许回环 HTTP 同源代理。`baseURL` 与可信 origin 显式配置，不信任任意转发头，不启用跨子域 Cookie。会话 Cookie 为主机专属，在 HTTPS 下 Secure、HttpOnly、SameSite=Lax；Web 请求使用浏览器 `credentials: include`，服务端对改变状态的同步请求要求精确 Origin，并让 Better Auth 自身校验认证路由来源与 CSRF。生产 session 模式不开放跨源 CORS。自托管静态 Bearer 原有精确 Web origin CORS 路径保持独立。
4. 自部署注册由显式环境开关控制，默认关闭；需要新增账号时由部署者短时开启。当前不发送验证邮件、不提供找回密码，因此不能称为邮箱已验证或具备账户恢复。只用隔离合成账号验收，部署者负责 HTTPS、密钥、备份与账号管理。

## 依据与影响

- 官方 [Hono 集成](https://better-auth.com/docs/integrations/hono)直接挂载 Web `Request` handler，并通过 `auth.api.getSession({ headers })` 读会话；[PostgreSQL 适配器](https://better-auth.com/docs/adapters/postgresql)支持 `pg.Pool` 与迁移；[配置选项](https://better-auth.com/docs/reference/options)包含固定 baseURL、可信 origin 与关闭注册；[Cookie 文档](https://better-auth.com/docs/concepts/cookies)说明主机专属 Cookie 及 Secure 属性。
- 复用项目 [01 技术决策](../01-技术栈与架构决策.md)已选的 Hono/Better Auth/PostgreSQL 与现有 React 设置页。依赖精确版本、许可证、锁文件和 SBOM 在实施提交中记录；未复制上游业务源码。
- 现有 `self-host-owner` 数据集属于旧静态模式，不能靠邮箱或令牌平滑改绑到新主体；用户需另用隔离浏览器资料，除非后续有显式迁移设计。真实邮箱投递、真实双设备、生产 TLS、商业身份桥接及官方云同步仍未验收。
