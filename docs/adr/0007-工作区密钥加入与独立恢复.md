# ADR 0007：工作区密钥加入与独立恢复

日期：2026-09-29。状态：本机软件纵切；正式云与真实设备待验。

## 背景与复用

当前 RxDB 是资产唯一数据源，工作区密钥只在设置页内存中使用；本地同步元数据仅保存密钥 SHA-256 指纹与 epoch。`.ka1` 是记录和原图的加密归档，不含工作区密钥。`packages/crypto` 已有 32 字节随机 `ka1_` 恢复凭据、XChaCha20-Poly1305 认证包装和设备公钥授权原型；`packages/sync-client` 已有精确账号／工作区预检、首次拉取解密门禁和本地绑定。本方案复用前两者，暂不建立第二套资产仓库、明文密钥存储或设备私钥状态机。

依赖选择：沿用已锁定的 `libsodium-wrappers@0.8.4` 和现有 `wrapForRecovery`／`unwrapRecovery`；不复制上游业务源码。libsodium 官方 [XChaCha20-Poly1305 文档](https://libsodium.gitbook.io/doc/secret-key_cryptography/aead/chacha20-poly1305/xchacha20-poly1305_construction)允许每次使用随机 192 位 nonce，并对 AAD 和密文做认证。现有包装的 AAD 固定格式版本、工作区 ID 与密钥 epoch；错误凭据、工作区或篡改均在本机解密时失败。登录密码和 Better Auth 会话只证明账号权限，不能推导工作区密钥。

## 决定

1. **独立恢复**：已有密钥的浏览器在完成该工作区同步后，本机生成高熵恢复凭据、用其认证加密工作区密钥，将密文包装写到该工作区的服务端。凭据只显示一次，用户在独立安全位置保存；服务器、商业端、请求日志和 `.ka1` 不接收凭据或明文密钥。一个工作区／epoch 只允许一个可领取的长期恢复包装。失去旧浏览器时，只要仍有账号访问权和该凭据，新浏览器可取密文包装并在本机解开。丢失全部工作区密钥及恢复材料时，服务器无法恢复已有密文。
2. **已有浏览器加入**：旧浏览器以同一包装算法生成另一把随机加入凭据和有效期 10 分钟的密文包装。目标浏览器在同一账号／工作区下输入包装 ID 和加入凭据，解密前后显示账号、工作区、指纹供用户与旧浏览器独立核对。它是短期交接，不是持久设备名册或单次领取；有效期内可重复读取。现有 `crypto_box` 设备授权原型未接入，因为设备公钥的独立可信配对、私钥保管和设备撤销合同仍待设计。账号绑定中的 P-256 DPoP 签名密钥也不能直接当作 X25519 解密密钥。
3. **服务边界**：新表只保存包装 JSON、随机包装 ID、`kind`、epoch、密钥指纹、创建/过期/撤销时间及工作区 ID。POST、列表、GET、撤销均复用现有认证、精确同源/DPoP/会话检查和 `sync_memberships` 读写权限；GET 过期或撤销包装失败关闭。密文包装格式、工作区和 epoch 经服务器校验，但服务器不尝试解密。`sync-client` 每次操作先做 `/sync/preflight` 并核对返回的账号和工作区。客户端再验证密文的 AEAD 和计算出的密钥指纹，用户确认后只填入原有设置页密钥输入，不自动执行同步或重绑。
4. **本机边界**：已有数据集绑定不匹配当前账号／工作区时拒绝填入；既有同步客户端继续负责绑定、密钥指纹固定、先拉后推、冲突与密文附件。空工作区没有远端密文可独立证明原密钥是否正确，创建首个包装前用户须从可信旧材料核对指纹。密码重置不改变加密能力。

## 撤销与剩余风险

撤销或过期让**之后从服务端领取**包装失败；领取后但尚未在 UI 使用时，客户端再次检查包装仍可领取。已领取的凭据和密钥无法从另一设备的内存、下载资料或历史明文中收回；同账号仍有访问权时可继续用已得密钥。真正阻止被撤销设备访问未来密文，需要单独的设备授权、服务端拒绝旧设备读写、工作区密钥轮换、旧 epoch 资料迁移及全部保留设备重新授权。这些不属于本次纵切，不能将“撤销包装”称为完整设备撤销。

恢复凭据是可解密密钥的高权限秘密，页面不会将其持久化到 localStorage、RxDB 或日志。独立保存的凭据若泄漏，攻击者仍须取得有效工作区访问权或保存的密文包装；服务端与浏览器遭入侵、XSS、用户把两份材料存同处等风险不由包装算法消除。服务仍能观察账号、工作区、领取时间与密文大小。正式开放前需专项安全审查、真实物理双设备和 HTTPS/对象桶验证，以及后续密钥轮换设计。
