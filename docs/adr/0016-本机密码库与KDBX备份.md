# ADR 0016：本机密码库与 KDBX 备份

日期：2026-09-30；本机验收完成：2026-10-01。状态：本机密码功能已完成，生产与真实设备另验。

## 用户要求与范围变更

用户明确要求“把密码功能跑通”。本决策取代早期仅保存密码库引用、首期不保存密码的范围限制。原有 `kind=vault` 资产仍表示外部密码库引用，不改写旧资料；同一密码库页面增加真正的本机加密密码管理。账号详情可进入其关联密码条目。

本轮提供主密码创建／解锁／锁定、密码生成与复制、登录条目编辑与搜索、历史还原、回收站恢复、修改主密码、KDBX 导入／导出，以及 `.ka1` 完整备份携带加密密码库。主密码遗失没有后台重置能力。浏览器自动填充、外部 Bitwarden/Vaultwarden 登录服务、跨设备密码同步和多人共享不属于这一实现。

## 上游复用

直接安装 npm 包，不复制或改写上游密码算法源码：

| 包 | 固定版本／上游发布 commit | 原实现路径／许可证 | KeepAny 适配 |
|---|---|---|---|
| [keeweb/kdbxweb](https://github.com/keeweb/kdbxweb) | 2.1.1 / `9b86a035a53f1827e427a0fc081bdcccc24f4f1b` | `lib/format/kdbx.ts`、`lib/format/kdbx-entry.ts`、`lib/crypto/crypto-engine.ts`；MIT | KDBX 创建、读写、历史、回收站及导入合并由上游实现；本机 session/CAS/限制由 KeepAny 包装 |
| [Daninet/hash-wasm](https://github.com/Daninet/hash-wasm) | 4.12.0 / `373b796205ab55fb4a657374dad6ea589bf75815` | `lib/argon2.ts`；MIT | 使用上游 WASM Argon2 callback，不自制 KDF |

发布 commit 由 npm 元数据 `gitHead` 读取，包完整性由锁文件固定。密码算法源码修改：无。`patches/kdbxweb@2.1.1.patch` 修改原 `lib/format/kdbx-format.ts`、`lib/utils/xml-utils.ts` 与实际使用的 `dist/kdbxweb.js`：三个 gzip 解包点改用 fflate `Gunzip` 的小块输入与累计输出预算（XML 最多 32 MiB、压缩 binary 合计最多 32 MiB），避免由未信任的 trailer 直接分配大内存。保留原 MIT 许可证与原实现，其余上游算法、历史和格式逻辑未更换。

原 npm 包不附完整测试套件，不能声称已运行其全部上游测试；本仓新增真实 KDBX3/4 压缩正常往返、压缩 XML／binary 超预算、错误主密码、历史与回收站、主密码轮换、同秒编辑后合并、并发写入与锁定竞态的适配测试。kdbxweb 旧 XML／压缩间接依赖分别通过 pnpm override 使用 `@xmldom/xmldom 0.8.15`、`fflate 0.8.3`，由实际读写测试验证兼容性。0.9.12 的 `onError` 接口不兼容此版 kdbxweb，因此使用仍提供安全修复的最新 0.8 分支；不回退原 0.7 依赖。许可证／NOTICE／SBOM 随最终依赖更新。

## 存储与边界

- 新库采用 KDBX 4、Argon2id，64 MiB／3 轮／并行度 1。引擎通过成熟上游执行密码派生和认证加密；创建时不压缩。
- KDBX 密文字节存入现有 Dexie FileStore 的 `passwordVault` 表（schema v12），普通资产仍由 RxDB 提供。该表不会生成资产、全局搜索、AI 或 MCP 的密码明文数据，也不会加入常规同步 outbox。
- 条目与资产的关联 ID 位于 KDBX 受保护字段。解锁后条目元数据只在 session 中用于密码库内搜索；锁定清除 session 与 UI 草稿、显露密码、主密码输入。JavaScript 环境不能保证物理内存被完全擦除，不作此承诺。
- 更新使用 revision compare-and-swap。不同标签页的旧状态不能覆盖新密码库；变更通知／重新读取触发重新解锁。慢速解锁、导入、加密写入不能在锁定后恢复已解锁状态。
- 导入限制 16 MiB。Argon2 导入预算限制内存 128 MiB、10 轮、并行度 4；不接受不支持的 KDF 参数。共享公开头检查同时核对 KDBX3 密文长度及 KDBX4 头摘要区、HMAC块边界与终止帧，备份预检也拒绝仅含魔数或截断的文件；真正验证密文认证仍需主密码解锁。错误、日志与通知只使用固定错误码和双语文案。

## 备份与恢复

`.kdbx` 是受密码库主密码保护的独立备份。`.ka1` 在原资产／附件／审核内容基础上携带 `password-vault.kdbx` 和加密字节哈希、大小及 revision；外层备份密码与密码库主密码分别使用，恢复后仍需原密码库主密码。旧 `.ka1` 没有密码库时继续兼容。

普通恢复只将密码库写入空密码库；相同密文字节保留当前本机 revision，不同现存密码库拒绝覆盖。恢复 journal 和证明 token 包含密码库密文指纹；中断后继续／放弃沿用现有恢复流程。资产迁移／合并不能静默丢弃新或不同的密码库，需明确拒绝并先独立备份处理。导出同时检查资产快照和密码库 revision，避免混合两个时间点。

## 验收要求

1. 真实引擎创建、保存、重新加载，错误密码失败且不改原文件；密码不出现在存储记录／outbox／普通搜索。
2. 真实 UI 创建条目、生成／查看／复制、编辑、锁定／刷新／解锁、历史还原、回收站恢复、主密码修改。中英 390／1280 页面检查布局、主题组件和无横向溢出。
3. 同源与异源 KDBX 导入，密码保护导出往返；损坏文件／超预算输入失败后原库仍能使用。
4. `.ka1` 下载、干净环境恢复、原主密码解锁后条目／关联／历史一致；现存不同密码库恢复冲突不写入，旧备份仍通过。
5. 过期 revision、在途锁定、恢复 gate、多标签页状态更改有针对性验证。最终固定包和用户原 Ego 入口的加载文件一致。

完成情况、失败项和证据在 `docs/08-项目进度交接.md` 记录，不以计划或安装成功代替验收。
