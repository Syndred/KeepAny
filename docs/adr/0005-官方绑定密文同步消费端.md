# ADR 0005：官方绑定密文同步消费端

状态：2026-09-29 实施中。范围只到合成 Plus、本机隔离浏览器与临时 PostgreSQL；不开放购买或生产官方同步。`binding-http-v1.0.0` 与 `bound-state-feed-v1.0.0` 保持冻结，商业源码留在同级独立仓库。

## 现有接口映射

| 需求 | 现有实现 | 本切片接法 |
| --- | --- | --- |
| 用户批准 | `BindingPanel`、`packages/binding` 的设备码/票据/JWKS/本地凭据 | 新增明确标识“官方同步读写”的申请动作，请求 `sync:read` 和 `sync:write`；原只读动作不扩权，旧只读绑定需用户自行撤销旧授权并重新批准。商业账号页现有双语写权限警示及最终确认继续生效。 |
| 短令牌 | `refreshAndStoreBoundAccess`、不可导出 P-256 私钥、DPoP 刷新 | 读写绑定才可获取并验证含 `sync:write` 的短令牌；按资源请求方法和固定 URL 签新 DPoP。令牌只作服务鉴权，不派生或替代工作区密钥。 |
| 密文队列 | `SelfHostSyncClient` 的预检、单数据集绑定、加密 outbox、冲突、幂等、附件先行与恢复日志 | 给同一运行器和附件传输注入受限的逐请求 bound 鉴权与本地绑定存活检查；不另建资产状态源或队列。预检返回的商业主体须与绑定主体精确相同，数据集仍绑定 endpoint、主体和工作区。 |
| 资源服务 | `sync-server` 的 bound JWT/DPoP、scope、共享 PostgreSQL 状态租约及可信 feed | 官方 Web 和资源 API 共用固定 origin；开发用现有回环 Vite 代理，生产须同源 HTTPS 反向代理。`KEEPANY_SYNC_PUBLIC_ORIGIN` 是浏览器实际 origin，不开放任意跨源 CORS。 |
| 用户界面 | 设置页已有自托管同步六态及本机备份入口 | 明确区分本机保存、自托管同步和官方连接；官方 endpoint 固定配置，不由用户任意输入。只在显式加入后创建/选择工作区并输入独立密钥，密钥仍只在本次页面内存。 |

## 顺序与失效边界

1. 读写票据和商业当前状态成立后，先用设备证明查询 `/sync/identity`；创建工作区或对已有工作区 `/sync/preflight` 时再核对返回主体与工作区，然后才允许本地数据集认领、加密 push/pull。只读绑定、错误密钥、跨账号或另一 endpoint 在传资产前失败。
2. 每次资源请求前检查当前本地 binding ID、主体和读写 scope；网络响应后、任何队列确认、附件计划清除、拉取应用或数据集认领前再次检查。移除/换绑使旧异步响应不能改变本地状态；服务器已收到的写仍按持久操作 ID 幂等重试，不承诺撤销能回滚已提交写。
3. 网络、权益到期、商业撤销或可信状态租约失效时，云端拒绝并显示失败/待同步；本机 RxDB CRUD、图片和 `.ka1` 导出/恢复继续可用。绑定刷新凭据和工作区解密密钥分离，私钥不离本机。

## 验收门槛

固定商业提交的合成 Plus + 独立桥 + 临时 PostgreSQL bound 服务 + 两份隔离浏览器数据集：显式批准读写、预检、密文记录和原图首次 push/pull、短令牌续期、断网重试/去重、错误密钥/跨账号拒绝、到期/撤销后云拒绝而本机操作与实际 `.ka1` 恢复继续正常。另用确定性暂停测试旧应答与本机移除。商业仓库移动端审批按钮裁切是独立待修缺陷，严格跨仓窄屏验收仍失败，不能由核心本切片掩盖。
