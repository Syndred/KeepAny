# 0003 商业绑定状态可信写入

状态：2026-09-28 决定实施。范围仅为 KeepAny 核心资源服务读取商业端 `bound-state-feed-v1.0.0`；设备绑定 HTTP 合同及独立 KeepAnyAdm 仓库不改动。

## 信任边界

核心资源服务持有专用 RSA reader 私钥，按绑定 ID 签发短时 `bound-state-reader+jwt`，仅向固定商业 origin 的单条状态 GET 发送。设备私钥、浏览器 Cookie、refresh token 和普通权益 JWT 不充当服务身份。商业状态响应由固定 issuer 的 RSA 公钥验签；仅 `keepany-bound-state-writer` audience、精确 `typ`/claims、合法 scope/status、时间和绑定 ID 可进入数据库。公钥可预置多个不同 `kid` 轮换；缺少或错误配置使 bound 模式拒绝启动。

首次无本机状态行时，只有商业 bound access JWT 与设备 DPoP **均已完整验签**，才按其中绑定 ID 触发一次受并发和速率限制的按 ID 拉取。后台每不超过 5 秒刷新已知未撤销绑定，包括暂时 inactive/expired 的行，以便合法恢复。请求有超时、响应字节上限、单 ID 去重；关闭进程时取消未完成请求。未知 ID、网络故障、503、超时、错误签名或数据库故障均不产生新租约。

## 持久状态与顺序

新迁移替换既有 PostgreSQL guard，不改 001–005 校验和。数据库行以绑定 ID 唯一，CAS 拒绝旧 epoch、旧观测覆盖新租约、同 epoch 改身份/状态/scope/cutoff、新 epoch 不提升 cutoff，以及任何 `revoked` 墓碑复活；不可删除墓碑。租约到期时间取 JWT `exp` 和签名 `state_expires_at` 的较早者，保留商业 `state_observed_at`，不能按 HTTP 到达时刻重算十秒。访问令牌 `iat` 必须严格大于 `token_valid_after`。多进程用 PostgreSQL 行冲突和 guard 收敛，不依赖单进程内存缓存作权威状态。

## 验证与边界

随机 schema 的真实 PostgreSQL 验证初次写入、正常续租、乱序/重放、跨绑定/伪签名、同 epoch 非法改变、撤销后高 epoch 复活、慢 HTTP 旧状态不续新窗口、故障过期、恢复、重启和双写入器竞争。独立商业 HTTP fixture 只使用合成 Plus 绑定验证正向与撤销后资源拒绝，不把它当真实付费账号或正式官方同步。Web 仍是手动 self-host 模式；本 ADR 不把 bound 模式开放给用户。
