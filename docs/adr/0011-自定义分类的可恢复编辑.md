# ADR 0011：自定义分类的可恢复编辑

日期：2026-09-30。状态：本机实现；最终构建及验证结果见项目交接顶部。

## 保留身份与引用

复用现有 Category、资产 `category` 文本和 `categoryOrder-kind` 偏好，不引入第二资产来源。编辑保留分类 ID、kind 和 order；打开管理时捕获同 kind 全部资产快照，包括墓碑。改名迁移旧名称引用，所选有效成员移入新名、原未选成员清空；墓碑只迁原名称，恢复后仍属于同分类。分类删除清空有效与墓碑成员的旧名、移除排序名称并保存分类墓碑。

规范化名称仍使用既有领域函数。同 kind 重名排除自身，内置分类及中英译名不可占用；原名称释放后可重新创建不同 ID 的分类。内置分类只管理成员，不提供改名。

## 可恢复写入

FileStore v11 新增 `categoryEditJournal`，每 kind 最多一条。先在短 Dexie 事务中核对完整分类／资产快照和其他未处理恢复记录，再持久保存精确 before／after，随后使用 RxDB storage CAS 分步应用；不是跨数据库原子提交。

意图保存后同 kind 资产、分类和排序写入受日志表门闩保护，无 Web Locks 时仍由 IndexedDB 排他事务约束。重开／HMR 重放按 before／after 判定；后续版本冲突保留日志，不覆盖。备份、恢复、迁移和同步不能接收半成品。关联、历史和无关 kind 资料仍可读取。

撤销先持久写入 `rolling-back` 方向，再对全部行预检并反向 CAS，重开继续撤销；新版本冲突时不能清日志。界面显示继续保存或撤销动作。人工重试／撤销须携带当前 operationId，旧标签不得处理后来创建的另一意图。

## UI 与验证边界

沿用冻结稿的内联分类管理、现有 React 组件、设计变量和双语 key；选中分类按 ID 追踪。迁移过程中旧／新名过滤归属同一分类，避免部分落盘时成员消失。

定向测试覆盖名称与成员、墓碑恢复、排序、旧快照、无 Web Locks 两句柄、写入失败、重开、重试／撤销、后续版本冲突和旧 operationId。固定构建以真实 UI 创建、改名、选择成员、实际下载加密备份并在干净环境恢复；次数与证据见[项目交接](../08-项目进度交接.md)。合成样本、注入写故障不作为真实配额错误、断电或物理双设备证明。
