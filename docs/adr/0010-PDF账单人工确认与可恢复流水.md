# ADR 0010：PDF 账单人工确认与可恢复流水

日期：2026-09-30。状态：本机软件已实现；当前固定包和验证次数见项目交接。

## 数据和复用

继续复用 pdfjs-dist 本机文字提取、现有财务 `History`／最小货币单位和 `FinanceEntryFields`，不引入自动解析器或第二资产来源。每份 PDF 一个候选，用户显式选支出并确认现有账号或订阅。计划续费金额不变；这条历史代表用户记录的支出，不证明外部扣款。

候选增加可选审核模式、账单草稿及固定历史 ID；旧资产候选与归档继续兼容。草稿采用有界字符串校验，可以保留空值或错误金额等待修正；确认时才按领域金额、日期、币种和目标规则严格校验。历史 ID 为完整文件 SHA-256 派生的 `pdf-expense-…`，重试与同字节改名重传沿用同一 ID。

## 持久意图及恢复

复用文件仓库 `importJournal`，先冻结当前候选与用户确认的流水，再写 RxDB，最后在文件仓库事务中保存已确认回执并清日志。不是一笔跨数据库原子事务。Dexie 短事务、`waitFor`／`ignoreTransaction` 与版本比较约束无 Web Locks 的两个文件仓库句柄，防止旧编辑覆盖或重复流水。

重开和 HMR 尝试重放；目标已删除、候选或同 ID 流水冲突时保留日志，不覆盖新资料。审核入口显示重试和相应错误。`pendingReviewedExpenseConfirmations` 依据真实历史判断是否已写入：未写可取消，清意图而保留草稿；已写则完成原回执。后者不能删除已经产生的真实流水来假装取消。无关资料仍可读。

冻结意图与恢复／合并门闩在同一文件仓库事务内复查。备份最后核对记录／候选指纹和日志；存在未解决意图时拒绝导出、恢复、合并或同步半成品。候选继续只在本机及加密归档，不作为云端资产上传。

## 加密归档

沿用 ADR 0009 的可选 `intake-review.json`、数量与 SHA-256 合同。已确认账单必须引用真实历史及目标资产，并逐字段核对 action、金额、币种、日期、来源、备注和标题。历史资产墓碑仍允许备份。未确认且目标缺失的草稿可以恢复后重新选择，不能据草稿凭空创建流水。

## 验证边界

单测覆盖无效输入、归档兼容／篡改引用、过期快照、两个文件句柄、流水前后故障、重开、取消和导出门闩。隔离源码浏览器显式注入写入失败，正式 UI 回读只一笔历史并清理日志；这不是真实断电或配额故障证明。

固定构建中英 390／1280 经实际加密下载、干净恢复、草稿修正、确认、计划金额不变、流水筛选、再下载恢复及改名重传验证。当前次数、截图与原 Chrome 入口在 [项目交接](../08-项目进度交接.md) 和 [检查记录](../evidence/2026-09-30/pdf-expense/checks.json)。扫描件 OCR、复杂版式、自动金额／日期解析和物理设备另列未完成。
