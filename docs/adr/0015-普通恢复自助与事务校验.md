# 0015 普通恢复自助与事务校验

日期：2026-09-30。范围为开源核心的普通本机备份恢复；不改变显式跨来源迁移协议。

## 用户流程

普通恢复中断后，收录与备份页显示归档记录、审核条目、已相同、尚未写入及内容差异的数量。用户可继续原恢复，或确认保留已经写入的当前资料并放弃尚未写入的部分。后者不回滚本机记录，不清除图片、真实财务回执或同步身份。

存在跨来源、来源不明、缺失引用或无法核对的真实回执时，相关动作继续拒绝。面板读失败允许重新读取。产品文案用中英文 key，不展示内部 journal、hash、scope 或私密资料。

## 实现与复用

复用 LocalRepository 的普通恢复 journal、Dexie 表与项目现有 Radix Dialog/Button，不引入第二套资产状态。只读元数据返回数量、能力及 opaque token；token 由 journalId、原始计划 hash 与数据集证明组成。每次动作在实际事务内重新核对 token、来源、引用和回执，过期面板不能消费另一项意图。

恢复、重开重放、HMR 恢复与手工处理共用原生 IndexedDB 写事务。RxDB 工作放在 Dexie.ignoreTransaction 内，并以 Dexie.waitFor 保持外层事务；FileStore 读取留在外层事务。同步预检查及实际 outbox、pull、附件与 key 提交都检查普通恢复 journal，关闭检查后竞态窗口。已经发出的网络请求不能撤回，保留原有队列、基线与游标供恢复结束后按幂等协议继续。

普通本机编辑仍允许。历史、任务、删除恢复和导入回滚与恢复核对共用门闩，保证核对实际回执时不会被另一句柄穿透。统一 mutation gate 在执行 RxDB callback 前先发出 FileStore count 请求，确认拿到原生锁；仅进入 Dexie callback 不证明已经持锁。图片清理也先取得同一门闩，再读取实际记录与未完成意图，避免把旧资产快照与已经清除的恢复日志拼在一起误删新恢复图片。

## 验证

40 项普通恢复单测包含真实 restoreArchive 第二条写入故障、继续、第三版本冲突、保留当前、双句柄竞争、过期 token、来源拒绝、实际财务回执、同步实际提交竞态及恢复后继续同步。根 review 新增 9 项反例，先复现历史编辑穿透、清理误删图片及 native callback 提前执行，再修复。

冻结数据源码后，全仓真实隔离 PostgreSQL 测试 65 文件、484/484；源版恢复 2 项与预览、分类并发及保存中禁止关闭 9 项合计 11/11。这些故障是受控合成注入，不能作为真实断电、真实低存储或物理双设备证明。固定包、原浏览器及 CI 证据另见项目进度交接，不从源码测试推断。

## 边界

元数据是可变快照，附件可能在读回后失效，因此动作内仍检查实际字节。来源不明或引用不完整不能通过保留当前按钮强制清理；财务或订阅未完成意图不盲清。浏览器 UI 的 busy 与 generation 只保护交互，事务重验才是写入边界。
