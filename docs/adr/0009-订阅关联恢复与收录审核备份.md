# ADR 0009：订阅关联恢复与收录审核备份

日期：2026-09-30。状态：本机软件已实现，最终交付包验证见项目交接顶部。

## 订阅资料与关联

继续使用 RxDB 作为唯一资产和关系来源，不增加另一套资产状态。复用已有续费日志与 CAS 模式，在文件仓库新增 `subscriptionSaveJournal`：先持久保存一次操作 ID、固定关系 ID 和预期资产版本，再提交资产及其 `lastSubscriptionSaveId` 标记，最后补齐关系并清理日志。它是跨 IndexedDB 仓库的可恢复流程，不能宣称资产和关系是一笔数据库原子事务。

重开只补原操作尚未完成的关系，不重新覆盖名称、账期或后续编辑。关联目标被删除、关系被用户删除或版本不符时，日志继续保留。订阅编辑提供重试及放弃剩余关联；放弃保留已保存资产及已有关系，用户可以重新选择关联。未解决日志阻止备份／迁移导出和同步半成品。同步状态读取返回明确失败报告；无法恢复时不发送网络请求。

Web Locks 缺失时，用同一日志表的短 Dexie 事务序列化资产 CAS、重放和放弃；RxDB 调用使用既有 `Dexie.waitFor` / `ignoreTransaction` 模式。进入 CAS 前重查持久意图仍存在，避免另一标签已取消意图后写出孤立资产。日志在该事务之前独立持久，进程中断不会丢失已经接受的操作。

## 收录候选和决策

CSV/PDF 候选不是资产。待审草稿、原文、类型选择、确认／忽略状态继续存 Dexie，确认才写 RxDB。将候选表移入同一文件仓库，旧 `keepany-intake-review-v1` 非破坏复制；稳定文件摘要与行 ID 保持原样，旧数据库保留。迁移失败不阻断资产 CRUD，审核入口可重试；完成之前拒绝创建不完整备份。已确认候选必须引用真实存在的资产 ID，墓碑也保留此引用。

`.ka1` 现增加可选 `intake-review.json` 及数量／SHA-256 字段；未含此字段的旧归档仍可读。草稿可以保留尚未修正的名称／网址／描述，采用有界草稿校验；已确认记录必须符合资产规则。恢复先校验全部候选冲突和引用，再写持久恢复日志，按固定 ID 重放。不同草稿不会被静默覆盖。

跨远端合并把候选纳入目标指纹、逐条来源／目标选择及本机撤销日志。界面列出名称、类型、网址、描述、决策、原文和类型选择差异；变更后旧预览失效。候选合入目标浏览器，仍不上传同步服务器。PDF 仍是文字收录，每文档一候选，不是自动记账或 OCR；不保存原 PDF 文件。

## 验证与边界

新回归覆盖资产写后关系失败、进程 SIGKILL 后同测试 profile 重开、无 Web Locks 的跨标签交错、同步不发送半成品，以及实际加密下载／干净环境恢复／刷新／同字节改名重传、候选冲突选择与撤销。用例、当前次数和截图按构建记录在 [项目交接](../08-项目进度交接.md)，不把源码浏览器证明写成固定包或真机证明。

真实断电、浏览器清理、物理手机与生产云环境仍需各自验收。旧未解决恢复日志不能自动覆盖较新的资料；使用者应在独立环境检查备份并对账。
