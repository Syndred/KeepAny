# ADR 0008：设备撤销与密钥轮换门槛

日期：2026-09-29。状态：设备授权只读清单与撤销拒绝已实现；密钥轮换仍是未完成的代码工作。官方云入口保持关闭。

## 已能可靠识别和拒绝的范围

- 官方连接以商业签名令牌中的 `binding_id`、设备 P-256 公钥指纹 `cnf.jkt` 和每请求 DPoP 证明识别一个授权。资源服务只读取签名状态 feed 写入的 PostgreSQL 短租约及永久撤销墓碑；它不自行调用商业端的设备接口，也不修改冻结的 `binding-http-v1.0.0`。
- `GET /sync/devices` 仅在 `bound` 模式注册。当前仍有效的设备经 DPoP 认证后，只能列出同一商业主体最近验证的绑定 ID 与状态，不返回公钥、刷新凭据或密钥。过期的 active 租约显示“暂不可用”，不能显示成有效。设置页对照本机绑定 ID 标示“此浏览器”；撤销操作仍在账号页面完成。
- 当可信 feed 已写入撤销墓碑，或短租约过期且无法续租时，此绑定的新请求在认证层拒绝；范围包括工作区、密文记录 push/pull、包装和密文附件 GET/PUT。撤销传播受轮询和最多 10 秒状态租约限制，不能声称用户点击后瞬间阻止已进入处理中的请求；也不能抹去设备已取得的密文、明文或旧工作区密钥。
- 包装撤销与设备撤销是两件事。加入／恢复包装的撤销只影响之后领取包装；设备撤销依赖上述签名状态和 DPoP 服务端门禁。仅有账号权限并不证明另一个浏览器未持有旧密钥。

## 为什么不能把当前 epoch 1 直接改成 2

目前 `008_key_envelopes.sql` 固定 `key_epoch = 1`，`sync_workspaces.key_fingerprint` 只锚定一把密钥；`local-db.pinScopedKey` 在已有游标、基线、待推送操作或附件计划时拒绝更换指纹。客户端只接收一把页面内存密钥，拉取时用它解开全部历史变更，待推送队列保存已经加密的旧密文。附件表和对象键没有 epoch，且同一附件 ID 的内容不可覆盖。直接重设指纹或给页面生成一把新钥匙，会留下不可读历史、错误密钥的幂等重试、旧密钥写入的新记录或旧附件。因此本轮没有假造“轮换成功”按钮，也没有开启官方云。

## 下一实现切片与可验证完成条件

1. **服务端协议与迁移**：新增工作区轮换状态、单调 epoch、当前写入 epoch 和指纹的事务性 CAS；记录操作与附件元数据都携带 epoch。服务端在同一事务内检查写入 epoch，旧操作 ID 仅能按原已接受结果幂等回放，不能在切换后首次接受旧 epoch 新内容。附件上传须用独立对象 ID 或版本化键，绝不能覆盖旧对象；失败与断线保持旧对象可读。读请求仍按权限返回旧密文，由客户端以对应旧密钥解密。合同变更只在开源同步协议内，不修改冻结商业绑定合同。
2. **持久轮换日志与密钥保管**：在单一 RxDB/本机同步元数据体系内增加可重开的轮换阶段；先验证旧钥匙、工作区、完整恢复材料、现有队列、云端游标与附件清单，再生成新随机密钥。新旧钥匙均只在授权浏览器内存和用户显式保管的加密包装中出现；服务端只留不透明包装与指纹。保留设备或独立恢复须可解出所需全部 epoch。没有可验证的旧钥匙与恢复方案时拒绝切换。
3. **迁移与切换**：在受控写入屏障下处理本机待推送旧操作，或保留原操作 ID 完成服务端幂等回放后再转码；把当前文档和引用附件以新 epoch 重新认证加密并核对数量、摘要、引用和实际读回。历史 `sync_changes` 若保留，保留设备和恢复凭据仍须持有旧 epoch 钥匙；若压缩历史，必须有新设备从零恢复的可信快照与游标协议。全部检查通过后才原子切换未来写入 epoch；中断重开继续日志，不丢旧钥匙，不把“部分迁移”显示为完成。
4. **并发与撤销验收**：两台保留设备、一台已撤销设备分别验证：已撤销设备不能再请求任何资源；保留设备用新 epoch 写入且可读旧历史；离线设备重连先获得新钥匙、不能以旧 epoch 写新内容；并发轮换只成功一次；丢应答、服务重启、附件上传中断、备份/恢复和独立恢复后仍可读全部记录与原图。真实 PostgreSQL、多实例、HTTPS、对象桶、物理设备与安全审查是上线验收，不由单机合成测试替代。

粗估剩余代码与自动化：服务端 epoch CAS 和写入屏障 4–6 工程小时；客户端多密钥、队列与可恢复日志 8–12 小时；记录、历史及不可覆盖原图的迁移／保留 8–12 小时；断线、并发和独立恢复回归 6–10 小时。合计 26–40 工程小时，外部物理设备、正式 HTTPS／对象桶／数据库和安全审查另计。这是排期估算，不是已验证的完成时间；不得用 2026-09-30 18:00 倒推缩减验收或开放官方云。

任何一个步骤失败时，保持旧 epoch 资料与包装可读，轮换状态标为待恢复，继续阻止官方云开放。使用者的普通本机资产读写和加密 `.ka1` 备份不依赖此流程。
