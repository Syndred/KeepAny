# F23 手机配对协议分片

本片是共享协议和可信控制器，尚未接入手机界面/系统TLS监听/电脑CLI；不把C通过标成F23 Native连接完成。旧`keepany-mcp-local-request-v1`和Web桥未替换。

## 连接与审批边界

新`keepany-mcp-mobile-pairing-v1`文件包含本次手机前台实例的私网HTTPS endpoint、单张证书/SPKI、两分钟ticket及所选普通资料ID/字段/时长；严格schema、UTF8总文件≤64KiB。没有普通资料字段值、KDBX或主密码。证书真实性/SAN/信任及局部pin由Native IO与电脑严格TLS客户端分别验，本片只做格式/地址检查。

电脑`/pair`只能提案clientNonce/name；正确ticket也只得到202 pending和8位核对码，**不能自行发grant**。手机本机trusted `decideClient`须在票据有效、范围仍存在时明确批准才持久签发授权。相同电脑重复轮询不弹重复请求；不同nonce/name拒绝。批准后可重取一次未确认的响应，首个已认证`/mcp`交换消费ticket，之后拒绝复用ticket；grant仍按原时长与逐次写入审批运行。客户端名称只是提案，不作为证书或账号身份。

HTTP只接受同源精确`/pair`/`/mcp`与Native真实Host、POST、无Cookie/Origin；未知字段/替换scope/过期/拒绝/旧实例均失败闭合。只有本控制器本次issued grant能进入MCP；旧authority中其他grant不会因新端口可用自动获准。原四工具/只读投影、预览、手机逐次批准与operationId幂等继续由现有核心实现。

关闭即时使guard失败并关闭handler，再只撤销本次grant；不能用“关了socket”假装持久撤销已确认。暂停、销毁、启动reset及Native总deadline属于IO/运行时后续接线。调用者仍须在两分钟未配对或grant过期时停止listener；本片没有独立后台定时服务。

## 真红与验证

新增故障C复现了授权密文已写成功但ACK丢失时，原controller不知道尝试的grant ID，close没有撤销该孤儿授权（5绿/1红，`test-results/mobile-pairing-ack-red.json`）。虽然secret未返回且本次HTTP不接受它，持久状态仍不准确。

现有McpAuthority新增**可信调用方可选onAllocated(grantId)**，在持久化前仅交非秘密ID，不改变模型工具/旧客户端协议。手机控制器在清理时查询并仅撤销这个确切ID；真实提交后抛ACK错误的原C转绿，另一个独立授权保持可用，不猜范围或批量撤销别人。存储仍失败会保留未确认错误，不能伪报撤销成功；不重发授权提交。

本片6C与既有authority/SDK/server/bridge-race/HTTP/Native桥相邻共61项、0失败/跳过，`test-results/mobile-pairing-final.json`。正式SDK实际初始化/四工具、仅选字段/未选拒绝、无本机批准拒写、批准后一次/重复幂等、关闭后拒绝均跑；持久元数据无grant secret/字段值/私密备注。另验过期跨异步列表、stop跨真实grant提交、原Web kind误传/未知字段/公共地址/Cookie/Origin/不同client/显式拒绝和ACK红绿。定向lint与TypeScript通过。

没有端口/设备/私密fixture操作；Native双平台TLS、OS权限、文件传输、手机核对码和电脑完整CLI仍待真实整合验收。
