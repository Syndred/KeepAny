# iOS 项目首次保存与改名观察器回执（2026-10-28）

本片为离线 CI 验收工具，尚未在 macOS/iOS Simulator 执行。它补充 SQLite 首次保存 → 改名的独立观察，避免 WKWebView AX 无 href 时只凭最终 row 声称原 ID 保持。没有改产品、Swift、workflow、Native 存储或设备；没有 ADB/CDP、私密 fixture、云请求或新依赖安装，也没有 push/触发 Apple CI。

## API 与准确输出

```bash
node scripts/observe-ios-project-fixtures.mjs --app-data "$app_data" --output "$observer_output"
```

参数依次为 `--app-data`、`--output`。App data 必须为已存在目录；输出必须在 app data 以外，使用本轮独立目录。输出文件用独占创建，不覆盖已有 `fixtures.ndjson`/`summary.json`，不自动删除已有产物。

唯一源路径是 App data 下的 `Library/Application Support/KeepAny/databases/keepany-v1SQLite.db`；先确认其存在、为精确常规文件，不扫描其他 DB、不创建缺失 DB、不访问 KDBX/Prefs/控制库。OS 提供的 app data 基目录先规范化，DB 本身或其子路径指向其他位置则拒绝。

生产查询仅 `execFile('sqlite3', args, options)`，无 shell；参数数组含 `-readonly -batch -noheader -cmd '.timeout 200'`、精确 DB、固定 SELECT。每轮最多 128 条，额外第 129 条用于拒绝截断成功；子进程 1500ms、每流 maxBuffer 2MiB、默认轮询间隔 1000ms。SQL 首先限定 `records.type='asset'`、合法 JSON、`payload.kind='project'` 及两语固定前缀；JS 再要求完整名称：

```text
iOS simulator persistence fixture full-fields (en|zh-Hans) <8位大小写均可的hex>[ renamed]
```

SQL 原 `recordId` 必须是 `asset:<UUID>`，与 `payload.id` 完全一致；非法/多余 row 外层字段、其他项目名或类型不输出。观察器不猜缺失 ID，不修改/回放源 DB。

- `fixtures.ndjson`：每行只有 `{recordId,payload,observedAt}`，保留 SQL ID、完整自造项目 payload 和 ISO 观察时间。按 ID 的上一完整 payload 做属性顺序无关的去重；同 ID 改名会增加一行，同一快照持续轮询不会重复追加。
- `summary.json`：固定 schema/status、轮询/成功查询/匹配/追加/ID 数量、过滤/非法行数量、固定错误码计数、是否有观察、是否正常停止及下述 verification。没有源路径、参数、原 stderr、marker、recordId 或 payload。
- stdout：只输出 observing 与最终停止状态、追加数和错误数；错误仅固定 public meta。原错误/参数不传到 console。缺库、忙、坏 JSON、超预算、未知失败不会伪造空成功，后续仍可有界重试。

## verification 合同

`summary.verification.complete` 只有满足全部条件才为 true：两语各恰好一个严格 marker 基名；各自先观察到原名称，再观察到其 ` renamed`；从首次保存到改名的原 SQL ID/payload ID 完全相同；除 `name`/`updatedAt` 外，完整 payload 属性和值保持。对象字段顺序不影响比较，数组顺序仍有意义。不复刻 UI 的 14 个预期字段字符串，真实 UI manifest 与产物逐字段核验由主控 workflow 接续。

verification 只输出固定 status 和两语 marker/阶段快照数量。`none`、`partial`、`ambiguous-markers`、`identity-changed`、`payload-changed`、`invalid-sequence`、`observation-error` 均 `complete=false`，只有 `verified` 为 true。任何已记录的查询/非法行错误也不会被后来快照掩盖成 verified。`normalStop=true` 只表示正常收尾，不代表验收成功；CI 应单独断言 `verification.complete === true`。

## 子进程与 CI 收尾

SIGINT/SIGTERM 只触发本观察器 AbortController，停止新轮询；在途 execFile 只终止它自身创建的 sqlite 子进程。Abort 的 callback 可能早于进程 close，代码同时等 exact ChildProcess 的 close，之后才关闭自有输出并返回。不枚举 PID，不操作其他进程或用户目录。

主控应在 UI 测试前后台启动本命令、保存确切 `$!`；正常/失败的 EXIT 都向该 PID 发 TERM 并 wait。wait 后读取 summary，再判定 UI 结果与 verification；不要只 grep 最终 row，也不要将 stopped-with-observations 当 ID 保持证明。此 workflow 接线不在本片修改范围。
