# iOS观察器：主动取消子进程的真实CI失败与修复

## 原失败及根因

源114285bb，Ubuntu run40594143198/job122506320434实际单测1344通过、17跳过、2失败；不是原4组合默认5秒问题再次复述。失败均为已独立拆分的ready-state abort：SQLite与simctl子进程已安装忽略TERM的handler，主动取消后直到4500ms测试兜底SIGKILL才退出，因此`rescued`为true，原断言准确报错。deadline两条件及其他35项通过。没有取消、跳过失败断言或延长1500ms/4500ms。

本机实际Node v24.21.0内置`child_process`源码可核：execFile把signal交给spawn，却未把自己的killSignal交过去。其超时路径使用配置的SIGKILL，默认spawn的主动取消路径仍使用默认信号。这解释了POSIX下deadline成功而ready-abort仍需救援；Windows把TERM也强制终止，原本机绿色不能证明POSIX分支。上游固定版本源码：[Node v24.21.0 child_process.js](https://github.com/nodejs/node/blob/v24.21.0/lib/child_process.js)。

## 最小修复

两个只读CLI不再向execFile委托AbortSignal，改为显式监听本次signal，对精确owned ChildProcess调用SIGKILL。保留execFile原1500ms超时/SIGKILL、输出限制、shell-free参数、错误类别与callback及close双重完成条件。close移除本次abort监听；创建过程中已经abort的竞争也立即终止同一个child。不枚举、不信号其他进程。

这只改变测试证据观察器的取消收尾，不改变App、业务资料、SQL查询或身份校验。实际iOS功能失败仍独立记账。
