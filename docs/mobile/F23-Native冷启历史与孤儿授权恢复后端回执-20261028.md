# F23 Native 冷启历史与孤儿授权恢复后端

本片仅新增 `packages/platform-native/src/native-mcp-history.ts`、对应测试及本回执，不改provider、main、session、UI或现有authority方法，没有设备操作。主控当前冻结的Native UI第一包未因此获得冷启历史展示或恢复接线；F23持久历史不能凭私有文件存在或本片C测试核销UI。

## 明确API

`readNativeMcpHistory(datasetName, {storageFactory?})` 返回 `{entries, lastRevokedAt}`。entries为最近100条持久audit的追加顺序，显式只投影 `id/grantId/at/action/outcome/assetId?/fieldNames?/operationId?`；fieldNames独立复制。lastRevokedAt为该资料集持久grant.revokedAt最大值，没有则null，不在读取时生成时间，不称服务端撤销时间。没有返回secretHash、secret、patchHash、字段值、完整资产、preview或operation内容。

默认存储复用 `createNativeMcpAuthorityStorage`，先验证不可变datasetName；全状态沿用现有schema/字节预算校验，再投影。缺插件/存储不可用、损坏、越额和路径替换均固定 `mcp-native-history-unavailable`，不失败变空、不替成Memory/普通SQL、不改写或清空损坏状态。合法初始空状态仍是空历史，与失败不同。

`revokeNativeMcpOrphans(datasetName, assertNoListener, {storageFactory?})` 返回 `{revokedGrantIds, lastRevokedAt}`，**只供native bootstrap已成功reset且UI session factory尚未开放时调用**。调用者必须保证恢复结束前没有新listener，trusted assertNoListener在每个外部await前后、逐项更新前和update callback内部检查；它不是Native事务取消或回滚API。

恢复逐个持久撤销该资料集已有未撤销grant，包括已到期但尚未标记撤销的grant；写入时记录实际本机Date.now和标准revoke/allowed audit。与普通 `McpAuthority.revokeGrant` 的区别是：普通方法会清该grant previews，而本启动恢复**有意保留previews和operations原样**，包括pending不确定回执与预览批准metadata，供历史与后续核对；不调用普通撤销方法，不修改其既有语义。

每个持久写确认后才计入返回IDs；任何guard/读/写/结构/容量失败统一抛 `mcp-native-recovery-unconfirmed`，不会把部分执行当全成功。已提交而丢失ACK的第一项可能已经撤销，无法凭JS异常回滚；本片停止后续项、不自动重放，显式下一启动复扫跳过已撤销项，避免重复审计。最终再读全状态：发现晚到的未撤销grant则不报告全成功。只操作传入资料集，不遍历其他dataset。

容量满或私有状态故障不prune审计、不删pending/preview、不放宽既有限额。主控后续应仅把MCP标为不可用，让普通本地资产继续；本片没有导入生产main或阻塞应用启动。

## 实际C检查

新10项测试以真实 `McpAuthority` 生成grant、预览、批准、pending receipt及审计，再将真实 `MemoryAuthorityStorage` 作为DI存储。**这是共享C，非Android Keystore/SQLite或iOS平台验收**：

- 冷重开同一存储读回metadata，显式投影不含raw secret/secretHash/patch值；撤销时间只来自已持久值，后来读取不改成“现在”。
- 只取最新100条追加审计；修改返回fieldNames不会改持久状态。
- 无插件、缺factory结果、读故障、损坏状态和非法dataset固定失败，无降级/清库。
- 恢复只撤当前dataset，其授权凭据实际被authority拒绝；另一dataset状态及grant仍有效。
- pending receipt和preview逐字保留，第二次bootstrap结果空IDs、时间保持、审计不重复。
- listener已存在时在存储IO前拒绝；第一项提交期间guard失效时只保留该项可能已撤销事实，不触及后续grant。
- update排队后callback内guard失效，完整草稿回滚，无持久修改。
- 第二项写失败/第一项提交后ACK丢失都不假成功；显式复扫只补剩余项，不重复已完成revoke审计。
- audit容量满则固定失败、旧状态不变；不自动prune或放宽限制。
- 最后确认前出现新的未撤销grant，拒绝把旧快照扫描报告为全成功。

已实际运行10项定向C全过；只包含这两个新文件的临时tsconfig定向typecheck通过；两文件lint与差异检查按最终结果记录。没有为新增helper重复原Native OS测试、全仓套件或未受影响UI/密码流程。
