# iOS Core 会话叶严格信任测试接线（2026-10-28）

本片只修改 SwiftPM 测试客户端，尚非 Apple 执行结果，也不是生产 TLS 修复。已 fetch origin；主线无缺失，未 merge、push、操作设备或改生产证书。

## 原失败与证据边界

fe816 的已核附件仍保留原 17 Core 实际执行、2 通过／15 失败（14 unexpected）的结果。公有证书样本的自签／X509 和 OpenSSL 目的／IP 对照通过，但该样本不是每个失败 probe 当次随机叶证书；不能据此宣称已用同一叶证明 BoringSSL 根因。旧失败不被本片源码变更核销，详见 [实际回执](iOS-fe816-证书与UI实际回执-20261028.md)。

## 测试客户端改动

- 新 `SessionLeafTrust.swift` 仅接 `TLSProbe(trusted: true)`。先要求单一 peer 叶且 DER 精确等于本会话预期叶，再检查 tuple SPKI SHA-256、自签密码学签名、issuer/subject、当前有效期、CA:false、digitalSignature 与 serverAuth。
- 独立 `SecTrust` 使用 SSL server-purpose policy、只加入本次叶锚、`AnchorCertificatesOnly(true)`、`NetworkFetchAllowed(false)`；每个设置成功且 `SecTrustEvaluateWithError` 真正成功才回 `certificateVerified`。即使平台对锚略过某项限制，前述显式检查仍拒绝对应叶。
- Security 评估在 Dispatch 后台队列执行，不阻塞 NIO event loop。trusted 的 NIOSSL 根集合为空，不追加系统根；`fullVerification` 保留，原握手完成后的真实 peer IP SAN 检查及 wrong-IP 的 `failedToValidateHostname` 断言原样保留。`trusted: false` 不安装新 callback，仍走原正常验证失败路径。
- 未改生产 `EphemeralIdentity`、`McpTransport`、CA:false／KU／SAN、Node 客户端、UI 或 workflow。没有写入证书到系统信任库，没有 accept-all、关闭校验、异常放行或证书／私钥日志。

## 新用例与本机检查

新增 8 个独立安全用例，直接调用同一个异步 callback：真实生产生成叶与正常合成控制；另一叶／空链／额外链；错 tuple pin；过期／尚未生效；clientAuth-only；缺 digitalSignature；无效自签；坏 PEM／pin／多锚。负样本均为内存自造，证书通过现有 X509/Crypto API 签名，未复制上游实现或新增依赖。每 case 有 start/setup/teardown stage。

Windows 无 Swift 编译器，以上用例 **未编译、未执行**。本片实际只做 API 源码核对、diff review 与 whitespace 检查；脚本逐字比较确认 `TransportTests` 原 10 case 整个类保持不变（原 17 还含同 target 其他类）。没有运行无关全套测试，也不把源码断言当安全阴性通过。

下一 Apple 先运行 `swift test --package-path apps/mobile/ios/KeepAnyMcpTransport --filter SessionLeafTrustTests`，再按原 Core 条件执行正常 TLS、未知 CA、wrong-IP、预算与生命周期用例；须核实际 case/stage 与原断言。未验证前不宣称 17 Core 或手机 MCP 全绿。

## 官方 API 依据

- 固定 [NIOSSL 2.37.5 callback](https://github.com/apple/swift-nio-ssl/blob/2.37.5/Sources/NIOSSL/SSLCallbacks.swift) 支持异步整个 peer 链验证；[SSLConnection](https://github.com/apple/swift-nio-ssl/blob/2.37.5/Sources/NIOSSL/SSLConnection.swift) 与 [NIOSSLHandler](https://github.com/apple/swift-nio-ssl/blob/2.37.5/Sources/NIOSSL/NIOSSLHandler.swift) 保留 fullVerification 的后续 hostname 校验。
- Apple [SecTrust API](https://developer.apple.com/documentation/security/sectrust) 提供显式锚、禁系统锚／网络与实际评估；固定 [swift-certificates 1.21.1](https://github.com/apple/swift-certificates/tree/1.21.1/Sources/X509) 提供自签、有效期及 KU/EKU 读取。仅调用成熟公开 API，无上游业务代码复制。
