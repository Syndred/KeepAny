# F23 手机 MCP 面板共享 UI 回执（2026-10-28）

范围：共享 React 的 `McpPanel.tsx`、纯 `mcp-platform-copy.ts` 与独立 B 用例。没有操作 Android5580/CDP、iOS、Gradle、原资料库/密码库、CA 或远端服务。没有改 Native provider/session、authority、HTTP handler、mobile main 注册或私有存储。

## 完成

保留原 MCP 卡片、资料/可读/可写字段、时长和授权确认。只有 `runtime.native` 存在时，才显示手动本机私有 IPv4 输入，使用既有 field 控件（390/coarse 实测 16px、至少 44px）。地址放在现有准备动作旁，不扫描网络。

Native 准备只调用 `native.prepare(address.trim(), exactScope)`，不激活。准备完成后通过既有 `ExportFileLink` 系统交付原 ticket JSON；Native 使用紧凑 JSON，保持严格文件体积预算，Web 继续原格式。交付 opening、cancelled、failed 均不能激活；只有当前文件 saved/opened 的回执与 runtime.delivered 同时成立，才启用单独“开始等待电脑”。opened 仍只写“分享窗口已打开”，不声称文件保存。

输入地址、资产、读写字段、时长变化均失效旧 ticket；导出还须精确匹配当前地址、scope、TTL、file identity 与截止时间。旧分享的迟到回执不能启用新票据。preparing/activating/waiting/authorized 不展示旧导出，不重复准备。Native 不出现 Web 导入配对文件入口。

等待/准备/错误有 Stop，调用公共 revoke。停止未确认时提示可重试、禁新准备/导出/激活，不声称已经停止。已授权继续原确认式撤销组件，取消无写；状态为“已授权”，不以 socket 建立冒充授权。scope/write Dialog 由正式 Native provider 管理，本片不重新实现。

Web 原 request kind、自动下载、配对导入、按钮译文、proposal、逐次写批准和撤销路径保留。未注册 Native adapter 时仍走既有能力边界，不造模拟连接成功。

新增父任务指定的全部 `mcpNative*` 文案：准备/地址/票据/启用/等待/授权/停止/过期/失败、客户端和核对码、前台与临时凭据说明。另按主代理实际错误反馈补齐 `mcpNativeApprovalUnconfirmed`、`mcpNativeStateUnavailable`，使 Native 决策/状态失败不再提示检查桌面 launcher。实现类名、SQL、Keystore、Node 等没有进入用户 UI。

## 本轮真实 B 操作与结果

`tests/e2e/mobile-mcp-panel.spec.ts` 每个语言三条，在 390×844、hasTouch 的独立 Chromium context 新执行。注册 `PlatformMcpAdapter`，复用**正式** `prepareNativeMcpSession`/mobile pairing/controller、真实 Web RxDB canonical store 和官方 SDK。仅 transport 与 authority storage 为合成：没有监听 TLS、没有 OS 加密存储，所以这是 B，不是 N。

| 点击/操作 | 预期 | 本轮实际 |
| --- | --- | --- |
| 新建普通项目 → 更多 → 设置/助手 → 勾选该项目、填私有地址 → 准备 | ticket 可交付，但未监听/无 grant | prepare 后 activated=0、grant=0；没有 Native 文件导入控件 |
| 系统导出取消，再导出失败 | 当前票据不能激活，真实反馈 | 分别显示 cancelled/failed，Activate 均禁用 |
| 系统分享 opened | 只显示分享窗口打开，不假称保存或自动开始 | activated 仍为 0；用户点击 Activate 才进入 waiting，旧导出消失 |
| 官方 SDK join → 手机核对客户端/项目 → 明确批准 | 未批准前无 grant；之后才显示已授权，SDK 仅读选择范围 | pending 202/grant0；批准后 200，name 可读、notes 私密标记未回传 |

| 准备失败/启用失败/停止失败 → 显式重试 | 准确错误、无旧导出、未确认停止不可继续新准备 | 中英各路径通过；Stop 明确重试后解除错误；错误完整位于 viewport 内 |

## 初次失败与复验

1. 初轮英文进入 waiting，面板同时显示 Native 等待说明与原 Web “Connecting…” 两个 status。属于实际共享 UI 红；最小修复将原通用 pairing 状态限定 Web。保持原断言，后续两语单一等待状态绿。
2. 初轮中文在安装合成 adapter 的 evaluate 中页面被重载。自有 Vite 日志明确是首次导入官方 server/stdio 后依赖优化：`optimized dependencies changed. reloading`；该轮没有完成业务步骤，未计通过。预热后重启自有 4234，关闭 watch、记录消费文件 hash，再新 context 执行；没有把未知失败泛归 HMR。
3. 关闭后的 SDK 可能返回协议 error 或 transport reject，测试按“新读取被拒绝”验证，不把关闭后必须有 HTTP 回包当产品合同。

`test-results/mcp-panel-run1.json` 保留首轮；`mcp-panel-run3.json` 已有中英六项通过、0 skip，Stop viewport 加强两项也实际通过。随后 Native 输入移至动作旁/导出紧凑 JSON，并加载主代理最新 Provider/Stop/Modal error 修复，再按同六项和受影响 Web 三项重新验证，**9/9 通过、0 skip、0 flaky**。compact 导出实际 bytes 在交付 handler 中验证，不只看按钮；不删失败记录。
