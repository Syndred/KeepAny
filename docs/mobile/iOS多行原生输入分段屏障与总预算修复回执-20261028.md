# iOS 多行原生输入分段屏障与总预算修复回执

本片只修改 XCTest 输入辅助函数及 CI 总预算。它是待 Apple 实跑的测试层候选，不是产品字段／存储修复，也没有关闭原中文输入失败或补齐英文完整字段验收。

## 原始失败与已知范围

已读固定源 `ccdcfaf1d09884d07232f0f7ce759366212b11da` 的实际 Apple artifact `12788100518`；ZIP 保持在 `test-results/ios-ccdc-review/artifact.zip`，官方 digest／217 项路径检查沿原 `artifact-proof.json`。本片使用已提取的小文件，没有再次下载或解出 53MB runtime／231MB Session。

`contents-v3/ui-tests.log` SHA-256 为 `6249782d73e0f29620710f9d13c61d5743861c21579ac48cdf0d4d3e656729e8`。7669–7800 行记录中文“中篇介绍”真实 tap 后仅一次 `typeText`，等待 20 秒仍为：

```text
expected: Synthetic medium zh-Hans\nSecond medium line
actual:   Synthetic medium zh-H\nansSecond medium line
```

LF 左移 3 个 UTF-16 位置，其余字符顺序相同；这不是可以规范化的展示软换行。错误发生在 Save 前，原精确断言正确阻止保存。原件及原红不修改。

当前 textarea 将 `event.target.value` 原值写入 React 草稿，没有本地换行转换。现有证据能定位到输入阶段，不能进一步判定 XCTest 事件合成、WKWebView 光标／组合输入或 React 选择区同步中的具体根因；也不能推断当时启用了中文 IME。现有末张英文截图不能替代中文失败时的键盘／光标观测。

Apple 的 [typeText 文档](https://developer.apple.com/documentation/xcuiautomation/xcuielement/typetext(_:))要求元素或后代拥有键盘焦点，并未承诺原子替换多行内容。[selectedTextRange](https://developer.apple.com/documentation/uikit/uitextinput/selectedtextrange)定义零长度选择区为插入点；[UITextInput](https://developer.apple.com/documentation/uikit/uitextinput)说明输入系统维护选择区及 marked text。这些只支持调查机制，不能作为本轮实际光标位置的证明。

## 本片候选改动

`apps/mobile/ios/App/KeepAnyUITests/KeepAnyUITests.swift` 的 `replaceProjectText` 仅对含 LF 的值执行：首段原生输入 → 精确完整前缀屏障 → 单个 LF 原生输入 → 精确前缀屏障 → 下一段。使用 `components(separatedBy:)` 保留空行及末尾 LF；空段不虚造键盘输入。

各段使用同一 `ProcessInfo.systemUptime` 截止时间，共享 20 秒剩余等待预算，不为每段重新开始 20 秒。输入／取快照消耗的时间也会减少剩余预算；该守卫不抢占 XCTest 自身已经发出的同步键盘事件。任一阶段未达精确前缀，保留原截图／AX，新增固定阶段及 UTF-16 长度诊断，执行完整原 expected 精确断言并明确失败退出，不再发后续段。没有重打、修字、trim、JavaScript 赋值、剪贴板替代或段间重新 tap。

原 Select All／清空确认、单行输入分支、最终完整值精确断言及其后的 Done 行为保持。8 个正式用例、14 个字段的预期值、分类、真实保存／冷启／取消／改名流程、SQLite 首次保存至改名观察及完整 payload 校验均未改。

`.github/workflows/mobile-ios.yml` 仅改两数：job 60 → 90 分钟，Install/UI step 25 → 45 分钟。该 step 实际包含 simulator boot／install／签名／launch／10 秒等待／观察器就绪，以及 `xcodebuild test` 的 runner 构建与全部 8 个 UI 用例和后置证据。

本轮 step 从 02:09:38 UTC 开始，首 case 至 02:17:58 才开始，已耗约 8 分 20 秒；这包括多项前置，不能全部归为 boot/install。英文完整字段于 02:24:19 开始时，距原 25 分钟名义截止只余约 10 分 19 秒。UI step 02:34:52 结束后进入 cleanup，pid1252 的 signal9 在 02:35:42，不能据此声称应用自主崩溃。精确 runner timeout 错误行仍缺，不把时间吻合写成已证根因。新增总预算是有界工程候选，不放宽 case 内部超时／20 秒值屏障，不会修复中文错值，也不保证慢 runner 必然完成。
