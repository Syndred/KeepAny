# 手机设置持久化与 URL 收录差异

日期：2026-10-27。手机版实施分支 `codex/mobile-app`。本记录只核销本片设置能力，不代表23组或真实设备验收完成。

## 完成

- `platform-settings.ts` 提供白名单设置读写。Web仍读写原 localStorage 键，原同步 API 的成功／抛错行为保留；手机启动先由官方 Preferences 读取白名单，再注册已确认的内存快照，不双写 localStorage。
- 白名单仅语言、模型服务／地址／模型／密钥来源和KDBX条目引用、同步访问方式、服务地址及工作区选择。拒绝未知字段、密码、API Key、token、设备私钥等普通配置输入；长期密钥仍只存KDBX，会话密钥只在内存。
- 原生写入／删除 await Preferences 成功后才更新快照。AI配置在实际持久写完成后发布连接和成功文案；失败保留原连接与编辑稿，连续修改按顺序提交；等待期间锁库或清理会话不会在完成回调中复活旧密钥。
- 设置页语言和同步选择等待实际写入。记住同步位置失败单独提示设置问题，仍保留真实同步结果，不将已完成同步伪装为未发生。
- 手机与导出文案改为纯数据，由主 i18n 资源集中合入，保留严格中英文 key 测试，不使用循环导入或靠组件挂载时补 key。
- 存储卡按真实Capacitor平台区分。原生界面说明清除应用数据／卸载与独立备份，移除浏览器持久存储申请；Web原有卡与行为保留。

## 接入

原生入口在动态导入 i18n、页面或AI设置之前：

```ts
registerPlatformSettings(await hydrateNativePreferences());
```

`hydrateNativePreferences` 来自 `packages/platform-native/src/preferences.ts`；注册来自 `apps/web/src/platform-settings.ts`。插件不可用或读取失败向启动层抛错，不降级到浏览器保存。

依赖为本轮已锁定的官方 `@capacitor/preferences@8.0.1`，直接使用，无上游源码复制。其已安装README要求iOS的 `PrivacyInfo.xcprivacy` 声明 `NSPrivacyAccessedAPICategoryUserDefaults`，建议理由 `CA92.1`；工程与签名验证由原生构建片记录。

## URL 元数据确切缺口（未实现，不能核销）

`apps/web/src/intake-url.ts` 调用同源 `POST /__keepany_intake__/url-metadata`。该路由由 Vite／便携Node中间件 `scripts/intake-url-metadata.mjs` 提供；手机静态打包没有这个Node服务，不能沿用地址就宣称能抓取标题／摘要。

现有中间件的必要合同：

1. 仅HTTP／HTTPS、拒绝URL用户名密码；解析全部DNS答案，任一为私网／保留地址即拒绝，IPv6仅允许受限全球单播。
2. 将已核验地址固定到实际连接，同时保持原域名TLS证书校验和SNI；不能“先查DNS，再让HTTP库重新解析”。
3. 最多4次重定向，每跳重新核对URL与地址；整体8秒，HTML／XHTML与identity编码，流式实际读取最多1MiB，按声明字符集严格解码。
4. 不带用户Cookie、授权或任意请求头，保持同源调用入口约束；返回HTML继续用共享的惰性template解析，不执行脚本或载入图像。

已核对本机 `@capacitor/core/types/core-plugins.d.ts` 的 `HttpOptions`：有禁自动重定向、连接／读取超时及text响应，但没有自定义DNS解析／连接地址固定、流式字节预算接口。直接替换成 `CapacitorHttp` 不能证明保留上述限制，本片没有放宽限制或偷偷使用代理服务。

最小可复用方向为独立的受限原生元数据桥，只提供URL／取消请求，保留全部限制并复用现有JS解析与审核。Android可基于成熟HTTP库的可替换DNS实现逐跳固定地址；iOS也必须实际验证等价的解析／连接和TLS策略。接入前固定依赖版本和许可证，移植现有私网、DNS重绑定、重定向、超限／超时测试；普通原生HTTP调用或只在返回后检查长度不能作为等价完成。
