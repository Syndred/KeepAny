## 已核根因与原红

`page-intake.tsx` 只是 IntakeTools 包装；实际实现仍在 `workflows.tsx`。原来 Save 回调只把结果写入共享 `message`，`.intake-backup-status` 只依据 readyDownload 是否存在显示 Ready。结果 notice 位于恢复/资料集/备份位置与最近收录之后。QA大量候选资料集放大了距离，不能把9次滑动外推成所有普通用户距离；但局部 Ready 与远处结果分离是同一源码路径。

两语390×844/hasTouch、实际 coarse=true，在独立生产 fixture build 中先调用现公开 `registerFileDeliveryHandler`，再加载真实 React main。真实UI创建加密备份并点击Save，handler返回Saved后全局已有Saved，而近Save提示仍Ready。原2条受控生产红13.083秒与自然PNG保留在 `test-results/backup-delivery-feedback/red.json` / `red-output`。没有产品隐藏hook或mock UI/加密结果；这个注册替身只模拟交付返回，不等价于Native保存。

## 窄修

- 在现有 readyDownload 文件任务中加入 typed `FileDeliveryMessage`，复用全部现有 exportFile* 文案；同一 `.intake-backup-status` 槽显示本次 Opening/Saved/opened/cancelled/failed。
- 父回调只更新仍匹配所捕获 **url+name** 的任务；没有在functional updater里setMessage，不再用delivery回调覆盖CSV/恢复等共享消息。新建备份与改密码仍沿现有setReadyDownload(null)清旧任务状态。
- URL cleanup effect依赖实际URL，不能因delivery状态clone就撤销当前blob；换文件/失效/卸载仍释放旧URL。现有公共ExportFileLink mounted/source guard与in-flight不改。
- Web没有handler时仍是原真实download，不把点击/downloaded写成Saved；opened保留“返回不代表已保存”的原提醒。没有新增文案key、组件或协议。
