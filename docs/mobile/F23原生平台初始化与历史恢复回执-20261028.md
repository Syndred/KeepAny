## 接口与边界

```ts
const platform = createNativeMcpPlatform({ loadContext });
await platform.history(); // { entries, lastRevokedAt }
await platform.prepare(options); // NativeMcpSession，options无loadContext
await platform.cleanupUnreturnedPreparation(); // 仅本factory未交付partial资源
```

应由Native页面bootstrap在普通资产已加载后创建**一份**factory，再注册给MCP调用者；不能在每次React render/history读取时重建。构造同步、无IO。没有默认Memory/空历史/SQLite/Prefs fallback，不创建另一个资产源；当前片没有接入口，因此尚未证明正式应用中“可选MCP故障不影响资产界面”的实际UI路径。

可选DI为 `reset`、`readHistory`、`recover`、`prepareSession`、`storageFactory`，均沿用现有函数签名。默认复用 `resetNativeMcpTransport`、`readNativeMcpHistory`、`revokeNativeMcpOrphans`、`prepareNativeMcpSession` 与原生私有authority storage。NativeSession仍使用正式受限transport；测试只在显式DI中注入合成transport/MemoryAuthorityStorage，不在产品添加Memory分支。

1. 第一次history/prepare共享初始化Promise：reset必须严格返回true，才获取并固定dataset/context/epoch；在可信“本factory尚未分配IO”的guard下完成孤儿撤销。guard不把prepare预占slot误认为IO，且每次回查epoch；恢复完前不会创建ticket/返回session。
2. 固定context保留原canonical asset store对象，不复制资产；其datasetName与同步assertCurrent/onInvalidated函数一旦捕获不换。统一缓存同dataset的authority storage对象给history/recovery/session。初始化失败仅让下次明确调用重试；已捕获旧epoch的factory会在reset前拒绝，不自动转向新dataset。
3. 成功初始化后history只读私有metadata。active会话时读取失败，保留初始化，不reset、不再次孤儿撤销、不close当前session、不删文件或返回空成功。首次history包含受控bootstrap恢复写入，这不冒称为纯只读启动。
4. prepare在首个await前预占独立对象token；只有初始化完成、即将调用NativeSession时才设`ioMayExist`。正常close或该owner的Native confirmed stop才释放。close进行中共享Promise，失败保留同对象可重试；旧callback/旧close不释放新owner。
5. prepare在交付前失败时，没有ticket交给用户或由caller激活。若已有确切session对象，先close该实例；否则尝试显式reset确认partial IO清理。reset未确认就保留partial token，不能声称已停止。
6. partial状态下history固定unconfirmed，绝不为了轮询历史而reset。下次明确prepare或`cleanupUnreturnedPreparation()`可重试同token的reset清理；成功才释放。cleanup本身不清初始化、不恢复audit/重放grant或资产写。owner非partial（含pending/live/close未确认session）时拒绝，必须走该session.close；无owner为无IO的no-op。

UI集成须保留无session却返回`mcp-native-revoke-unconfirmed`的语义，保存此factory cleanup函数供“停止/重试”使用，不能把runtime没有session的idle当Native已停。此接线归主控后续片，本片没有改UI。

## 固定错误

| 情况 | 固定错误 |
|---|---|
| reset/loadContext/初始化恢复未确认 | `mcp-native-recovery-unconfirmed` |
| 初始化成功后history读取/epoch失败 | `mcp-native-history-unavailable` |
| 并发prepare，或试图用partial cleanup清pending/returned owner | `mcp-native-session-occupied` |
| prepare失败且已确认其清理 | `mcp-native-session-unavailable` |
| exact-session close或未交付partial清理未确认 | `mcp-native-revoke-unconfirmed` |

不透传底层诊断、私有路径或payload。旧epoch下未交付session的exact close也失败时，不执行可能停止新dataset listener的全局reset，保持unconfirmed。

## 实际C证据

使用真实McpAuthority/MemoryAuthorityStorage的metadata事务、现有history/recovery与真实NativeSession；其中Native IO仅为显式合成DI。没有使用原生OS密钥或实际listener，全部标**C**。

| 用例/实际动作 | 预期与实际 |
|---|---|
| 并发history + 已预占prepare + history；分别门控reset和recovery | 只一次reset→固定context→真实恢复；恢复前session工厂调用0；完成后同authority、原asset store引用，普通资产get/list调用0。通过。 |
| reset false/throw、loadContext故障后明确再请求 | 不读authority/不交ticket、不造空历史，固定错误；后续可明确重试；构造本身无IO。通过。 |
| 真实Authority预置两grant、pending receipt/preview；恢复第二写失败→再试 | 首次不返回部分历史/成功ticket；已提交撤销不重放，后续仅撤剩余grant；原preview/operation内容保留、总revoke audit各一次。通过。 |
| 当前session active后authority历史读错→恢复读取 | 不reset/recovery/close，不撤当前grant、不清init；后续只读可恢复。通过。 |
| NativeSession分配Promise未回时第二prepare/cleanup | 第二prepare与cleanup均拒occupied；预占slot不使自身bootstrap guard失败。通过。 |
| close ACK失败→新prepare/readonly history→exact close重试 | 新prepare阻止、history无控制IO副作用；重试相同原对象close第二次成功才允许替代。通过。 |
| close ACK仍等待时confirmed callback；两次close并发 | 共享同Promise，ACK settle前不分配新slot；保留writeMayHaveApplied结果。通过。 |
| Native confirmed stop→新session→旧callback/旧close | 只释放原token，不能放开新owner。通过。 |
| 成功init后epoch失效，或失败bootstrap已捕获旧epoch | 不重新load新dataset；不多reset，不分配新ticket；后者连旧factory retry也不碰新dataset。通过。 |
| prepare未返回时失败：reset true / false / throw、并发明确重试 | true只确认清理后报prepare失败；false/throw保partial、history不reset；并发明确prepare共享一次清理、恰一新slot。通过。 |
| prepare未回却早到onStopped；返回后发现epoch变化 | 早callback不提前释放分配；已有确切对象优先exact close；旧epoch清理不确认时也不reset替代dataset。通过。 |
| cleanup无owner / 非partial / partial失败再试 / 与prepare并发 | 无owner无IO；非partial不碰其session；失败保token；成功只reset且authority/audit全等、不清init/重跑恢复；迟到旧callback不释放新token。通过。 |
| 实际NativeSession + 原Authority/History层集成 | 先完成恢复再生成正式pairing结构；使用同私有storage/canonical store，未自动读资产或激活；close释放。通过。 |
