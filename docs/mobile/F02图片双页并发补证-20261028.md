## 原红与窄修

四条初轮均安全拒绝旧保存，完整21行/9Blob与乙保存后逐对象相同、整草稿逐字段保持；但提示是“操作未完成，请重试。/Could not finish. Please try again.”。原图被正常清理后，旧草稿中的附件检查先返回 `attachment-missing`，AssetEditor 只有 `asset-stale` 专门文案，因此落通用错误；泛“重试”没有告诉用户需重新打开。四条原红及截图/raw state/UI值保存在 `test-results/mobile-image-stale/original-four-output/`，未改写成数据覆盖 bug。

获主控授权后，仅在 `workflows.tsx` 的 AssetEditor 映射 **original 存在且 attachment-missing** 到新双语 key `assetFilesUnavailable`：“图片或附件已不可用。请重新打开资料核对后再保存。/An image or attachment is unavailable. Reopen the record and check its files before saving.”。原 asset-stale、创建、cleanup/未知保存优先级不变，没有新增读取当前 payload 的竞态窗口，也没改 CAS、Blob 守卫或清理规则。

另两条 C-assisted B 真实删除本 context 的合成 Blob、保全部原 row/revision 不变，再正式 UI Save：明确文件提示、无“另一处更新”的虚构原因、整稿保持且无写；取消仍无写，finally补回自己的合成文件后正常关闭 context。它们是文件缺失故障对照，不冒充双 UI 竞争或 Native 磁盘故障。
