# F23 桌面手机 CLI 接线回执（2026-10-28）

本片是 Windows Node C 与合成手机 authority 的真实 socket/stdio 合同证据，不是 Android/iOS 实装 N。没有连接 5580/9436/9438，没有操作原资料库、原密码库、CA、9445/9446/9447 服务或 Gradle。原 152 项步骤/预期未修改，F23-02—06 的真实手机批准、后台/长断线、系统网络权限和最终客户端仍须后续实装。

## 完成与接口

- `--mobile-pairing PATH`：复用 `readMobileMcpPairingFile` 与严格 owner 文件读取，向配对文件的精确 `/pair` 提交固定 join 格式和本次 clientNonce；202 仅向 stderr 打印一次八位公开核对码，约 800ms 轮询，受两分钟票据截止/取消约束。手机明确批准后才接受 200；比较码、原 scope 和有效期均须吻合。
- `--mobile-connection PATH`：仅接受新 `keepany-mcp-mobile-connection-v1`。包含 endpoint、单张证书、SPKI、instanceId、grantId/secret、expiresAt 和 scope；没有字段值/密码。与旧 Web request kind 分离，不把手机 localhost 替换成电脑 localhost。
- `writeMobileMcpConnectionFile` 在默认私有目录或显式已存在的安全目录中随机 exclusive 新建持久 profile；Windows 复用严格 DACL/FileID 原生 helper，POSIX 0600/0700、NOFOLLOW/目录链与前后身份检查。不覆盖现有文件，不 delete-on-close，不替用户 chmod。只读导入的原票据不自动删除，过期后用户自行处理。
- `launchMobileMcp` 通过官方 `StreamableHTTPClientTransport` 连接手机，随后用官方 `serveStdio` 代理原四工具。共用 `keepAnyMcpToolContracts`；schema、description、annotations 逐项原样抽取，旧 handler 仅改引用。拒绝额外工具/分页工具面，不在电脑建立第二 authority，不公开审批工具。operationId、patch、previewId 原样传给手机。
- 关闭电脑仅断本连接，不撤销手机 grant；同一前台 session/授权有效期内可由私有 profile 重连。手机重新 start 的新证书不自动接受，须重新显式配对。TLS 继续同时验证本次 CA、正常 IP SAN、SPKI，无全局 CA 或关闭校验。
- `build-mcp-launcher.mjs` 将已有 root devDependency 的官方 client 2.1.0 纳入发行运行依赖；没有 install 到共享 node_modules，没有改 package/lock。

手机端使用顺序为 prepare → 系统导出 → 回 App 显式 activate；导出期间 endpoint/pin 不变。分享窗口仍打开不能视为服务已运行。本片只对接该合同，不把合成 fixture 当手机 UI。

## 首次失败、修复与复验

1. **产品真红**：仅将 `ctx.mcpReq.signal` 传给 SDK `callTool`，调用虽然取消，当前版本 HTTP transport 的 socket 未同步结束，提交栅栏仍有在途请求。最小修复在桌面代理使用 Node `AsyncLocalStorage` 保留每次调用的 signal，并在 transport fetch 合并该 scope、原 Request/init signal 和全局关闭 signal，直接取消对应 TLS。复验确认 socket 归零；释放栅栏不写；另一个并发读取和后续读取正常。没有全局 transactionActive/active-signal，没有改手机 authority/HTTP handler，没有放宽超时或自动重放。
2. **测试限时**：相邻并发文件执行时，真实 Windows owner helper 的“写两份、重启 helper 再读”超过 Vitest 默认 5 秒。首轮 22 通过/1 限时记录保留；该文件系统测试明确 20 秒，随后顺序复验，不改变产品 30 秒网络 deadline。
3. **测试夹具**：额外工具拒绝测试初版直接 JSON.parse 所有初始化响应，但官方 SDK 也可返回有限 SSE；夹具先失败于初始化，不能证明工具拒绝。修夹具同时处理有限 JSON/SSE，再确认 extra 工具确实注入、CLI 返回 `mobile-mcp-tools-invalid` 且无 profile。产品工具白名单没有放宽。
