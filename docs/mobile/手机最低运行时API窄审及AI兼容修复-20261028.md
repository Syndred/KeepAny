## P1 AI根因与最小修改

正式设置测试入口 `apps/web/src/components/AiSettingsPanel.tsx:462` → `packages/ai/src/index.ts:471` generateAiText → generateText。此前同时传：

- 外层timeoutController/setTimeout及createCombinedSignal产生的 `abortSignal`；
- SDK `timeout: { totalMs: timeoutMs }`。

安装的 `ai@7.0.122/dist/index.js:6092` 将abortSignal和totalTimeoutMs送入mergeAbortSignals；2926–2931在两条信号时无fallback直接调用AbortSignal.any。Native注册自己的fetch factory不会绕过SDK前置步骤，所以正式请求会在触及provider/native fetch前失败，而UI只显示脱敏request-failed。

本片只去掉冗余SDK timeout参数，不新增手抄polyfill或全局patch。保留已有：外层30秒默认、1–120秒校验、timeoutController、用户signal组合、finally clearTimeout和dispose、maxRetries0；createLanguageModel仍把相同timeoutMs交给Native factory。SDK未收到总/step/tool timeout时，后续generateText各步骤仅传原combined signal；本方法不注册工具，已查provider及provider-utils发布文件没有另一条本次新增的静态any调用。没有通过降低预算或去掉取消解决兼容。

## Apple CI解耦建议（只读，未改workflow）

当前Core步骤在App compile后、安装/UI前；Core失败会使后续隐式success条件为false，导致8UI也跳过。建议给compile步骤加稳定id，并只给独立安装/UI步骤增加：

```yaml
id: compile_ios # 设置在现有编译步骤
# 现有Core步骤仍保持失败，不设置continue-on-error
# 设置在现有安装/UI步骤：
if: ${{ always() && !cancelled() && steps.compile_ios.outcome == 'success' }}
```

这是两个不同步骤的局部字段示意，不是可整体粘贴的新step。依据 [GitHub状态条件文档](https://docs.github.com/en/actions/reference/workflows-and-actions/expressions#status-check-functions)和[steps outcome文档](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#steps-context)：显式status function覆盖默认success；compile真实成功且workflow未取消时，Core失败不再阻止独立UI。Core仍exit非0、没有continue-on-error，所以UI绿不会把job变绿。compile失败则UI继续跳过；workflow取消/整个35分钟job耗尽也不能靠if恢复执行，应保持取消事实及always artifact。此建议未在GitHub实际执行，本片没有改workflow或触发新run。
