# 原生绑定身份与签名基础

日期：2026-10-27。仅交付 F21 的平台中立状态／签名合同和原生实现基础，保留实验服务边界；不是生产绑定、真实账号或原生设备验收完成声明。

## 完成

- `packages/binding/src/storage.ts`：身份、挑战、绑定、刷新凭据组成同一可 CAS 状态；签名器只暴露 P-256 公钥和 ES256 签名，不用 Native 伪装 CryptoKey。
- `BindingRepository` 继续共用挑战／票据／主体切换／刷新轮换／撤销业务。纯本地修改在 CAS 冲突后重读重跑，不把网络请求放入可重试提交闭包。失败不发布新凭据或删除旧凭据。
- Web 默认延迟加载 Dexie 适配，保留 `keepany-binding-v1`、原表／键／CryptoKey。v3 只增加独立 revision 元数据；有真实 v2 合成库升级测试，不重新生成已有身份或密钥。
- DPoP 的既有字段和验签方式保留。原生 P-256 签名转为 JOSE 64 字节；所有生产调用改用 `deviceSigner()`。旧 Web `deviceKey()` 继续有效，Native 明确拒绝该旧私钥接口。
- Android：Keystore 拥有 P-256 和 AES-256 密钥；整个状态用 AES-GCM 加密，随机 IV、包名／命名空间 AAD，存到 no-backup 目录的 AtomicFile；CAS 在同一进程锁中校验 revision 并原子替换。私钥不导出，错误不附带原始异常或请求。已有密文但密钥缺失／认证失败时拒绝，不生成另一身份冒充。首次确认没有任何旧文件／alias 后，创建 key／写初始状态失败且没有可解密提交时，只清除本次新建材料，允许后续重试；有效提交保留。
- iOS：永久 SecKey 和 `AfterFirstUnlockThisDeviceOnly` Keychain，桥仅导出公钥；无 Secure Enclave 硬要求。状态 CAS 使用进程锁与原子 Keychain 更新。排除备份的安装标记防止继承旧 Keychain 身份；无标记但有旧 Keychain 项、已有安装状态缺失时均失败关闭，不销毁旧凭据或静默重建。首次确认无旧项的状态写失败才清本次未提交 key。Windows 只能交付源，不能宣称已编译或运行。
- `createNativeBindingRepository()` 为同步懒工厂。首次主动调用绑定才初始化，插件故障不阻断本地核心启动；没有 Dexie／SQLite／Preferences 回退。`openNativeBindingRepository()` 保留供显式预热和测试。

## 集成接口（主代理接线）

1. Android MainActivity 注册 `KeepAnyIdentityPlugin.class`；附属实现为 `IdentitySecureStore`、`IdentitySignature`。
2. iOS 项目链接本地 `apps/mobile/ios/KeepAnyIdentity` 包，bridge controller 注册 `KeepAnyIdentityPlugin()`。
3. 动态导入共享设置页前，调用 `registerBindingRepositoryFactory(createNativeBindingRepository)`。本地核心启动不要 await 实验绑定预热。
4. 必须关闭 Capacitor 框架日志，避免框架输出原生 methodData／callback 中的瞬时凭据。插件自身不打印 state、token、签名输入、公私钥或原始错误。

本片不改 MainActivity、Xcode 接线、移动 main、共享设置 UI 或网络策略；这些由主代理另片提交。

## 明确未完成与下一片

- 旧 Web 回环绑定桥不能当作手机内服务；绑定是 build 固定可信 HTTPS issuer／resource origin，适合独立注册的原生请求适配，保持固定路径／方法、禁重定向、无 cookie、真实公开 `htu`／JWKS／thumbprint 校验。它不同于任意 URL 元数据抓取，不无故扩大为任意地址代理或放宽来源限制。
- 共享 UI 的 `officialOrigin === window.location.origin` 是 Web 部署假设；由平台能力和固定配置替代需要独立测试，不能简单删掉检查。本片未改该边界。
- 原生启动注册、原生实际 DPoP、商业合成／真实批准、刷新／撤销传播、杀进程和设备文件故障仍待主代理或设备 lane 验证。当前 TS 原生桥是软件 fixture，不是安全存储／硬件证据。
- iOS 合法卸载后若系统保留旧 Keychain 项，缺安装标记时会拒绝继承；显式重新授权／重置旧设备凭据入口尚未实现。不能仅凭标记文件缺失自动销毁旧凭据。
- 原生状态会为既有网络合同短暂进入 JavaScript 内存；仅保护设备持久存储和私钥桥边界，不承诺抵抗受控同源脚本。iOS 不因使用 SecKey 就宣称硬件不可导出。
- 此状态不进入普通 SQL、Preferences、资料备份、KDBX 或常规同步；从电脑恢复资料不会导入其设备身份。手机 WebView 与电脑 4180 的来源隔离，不能误称已直接读取电脑设备库。
