# F23 原生 HTTP 桥适配分片

本片为 TypeScript 桥接层和共享协议合同，尚未接入手机连接界面、真实 Native TLS 监听器或电脑 CLI；不能核销 F23 手机连接。插件注册不打开端口。延续既有四工具/授权/逐次审批，不变更旧 Web 协议。

- `startNativeMcpTransport` 只接受显式私网 IPv4 或精确127.0.0.1，检查 Native 返回的 HTTPS 地址/端口/路径/实例 UUID/证书格式和 SPKI 格式。真正证书签名、SAN、系统信任与端口归属由 Native IO 和严格客户端各自验证，本片不冒充这些证明。
- 请求保留 Native parser 的实际 Host，单独传入共享 handler；不从发布地址推定。严格事件/UTF8/头部预算，最多4在途，取消或停止使请求 signal 和 storage guard 立即失效。旧实例停止事件不关闭新实例。
- 响应最多8MiB，每个桥块256KiB，按原始字节编码避免中文/emoji断点损坏；Native须缓存到responseEnd才真正发出。响应异常立即cancel，不重放handler，保留“写已发生但ACK丢失”的不确定边界。Cookie/重定向/未知响应头拒绝，实际Native IO负责最终HTTP framing。
- 启动部分失败也停止已创建实例并释放事件订阅；protocol close同步抛错不阻碍Native stop。系统pause/destroy由Native底层关闭，TS接mcpStopped后同步使授权读写guard失败；底层尚待实现及真实N。

## 实际发现与修复

初次10项中的原8项运行7绿/1红：官方 SDK 的初始化响应实际带有限SSE以及`connection`/`x-accel-buffering`，最初全量严格响应头拒绝导致responseEnd未执行。已按HTTP层职责剥离连接/framing及代理缓冲头，保留原SDK有限响应字节；没有放行Set-Cookie或Location。另有合成测试错写服务器名`keepany`，按既有兼容名称`keepany-local`纠正，不改产品协议。原JSON日志保留first/second/third过程。

最终10项本片C与12项私有authority、9项共享HTTP相邻共31项、0失败/跳过，`test-results/native-mcp-transport-final.json`。真实SDK初始化及错误Host拒绝、断开中止/晚结果不发送、匹配实例停止、部分启动失败、公共/歧义地址拒绝、响应秘密Cookie/跳转/超限拒绝、UTF8跨块、同步close异常、ACK失败不重放/新请求可重试、输入UTF8/头预算实际执行。`tsc --noEmit`和两文件`biome lint`通过。

本片没有Native插件替身以外的端口或设备操作，没有读普通资产/密码库/私密fixture；JVM/真实TLS/OS生命周期/双语配对UI/CLI均另记，尚未完成。
