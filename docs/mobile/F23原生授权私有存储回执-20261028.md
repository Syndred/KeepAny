# F23 原生授权私有存储回执

本片从2026-10-27跨日实施，最终检查日期为 **2026-10-28（Asia/Shanghai）**。只实现独立持久 authority 后端；没有注册插件、MCP listener、网络入口或UI，不修改原152合同，不代表 Native MCP 已可连接。

## 接口与存储

- TS：`createNativeMcpAuthorityStorage(datasetName)` 返回现有 `AuthorityStorage`。datasetName须满足当前原生资料库名约束，实例固定该scope，SHA256后才传原生/用于文件名。没有 default scope、普通SQLite、Preferences或Memory fallback。
- 原生插件名 `KeepAnyMcpAuthority`，仅 `initialize({scope})`、`readState({scope})`、`compareAndSet({scope,expectedRevision,payload})`；scope必须64位小写hex。read返回 `{revision,payload}`，CAS返回 `{committed}`。密钥不经JS。Root后续拥有MainActivity/BridgeVC/SPM/入口注册；本片未碰这些文件。
- Android：独立 `keepany-mcp-authority-v1` no-backup目录、每scope独立 AndroidKeystore AES256-GCM key；不复用绑定或KDBX钥。AtomicFile、写前fd.sync、提交后解密回读核revision。进程内统一锁覆盖两个实例的读/CAS。
- iOS：独立 `KeepAnyMcpAuthority-v1` ApplicationSupport目录，excludeBackup、complete文件保护、owner目录/文件权限；Keychain WhenUnlockedThisDeviceOnly/no sync只放每scope32B AES key。CryptoKit AES.GCM、密文临时文件flush后原子replace，提交后解密回读。没有把JSON状态塞进Keychain。
- 二者使用 `KMA1 + nonce + ciphertext/tag`，AAD绑定 `KeepAny/MCP/authority/v1/<scopeHash>`。仅使用JCA/Android OS、CryptoKit/Foundation成熟API，没有自造加密算法。

## 状态与故障合同

三层都只接受4数组 `grants/previews/operations/audit`，拒绝未知字段、原grant secret、preview差异/业务字段值以及password等未开放字段；保留secretHash、ID、字段枚举、版本/patch hash、期限、批准/拒绝、pending/applied回执和脱敏审计。严格类型、重复ID/操作检查、2MiB UTF8状态预算，原生额外有浅层嵌套和密文长度限制。限额拒绝时不自动丢弃审计或回执。

只有文件与独立钥均不存在才创建4空数组。已有文件/钥缺一项、坏密文、错scope或未知版本均fail closed，不能静默建空或清旧状态。首次创建失败仅清理由该次已证明fresh的尝试产生的材料；若已读到真实提交则保留。正常写失败保持原提交；提交后应答丢失属于未知结果，必须重读，不能假称未提交后自动重放。

TS每实例串行update，每次从原生读取revision、只执行一次异步change、等原生CAS完成才resolve；跨实例冲突明确 `mcp-native-conflict`，不重放回调。失败后队列可继续；未知原生诊断只输出 `mcp-native-unavailable`，无状态/钥/字段值日志。root切换active dataset时须关闭旧MCP runtime并以新datasetName建实例，不能把旧实例改成隐式新scope。
