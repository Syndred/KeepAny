## 1. 新导航与功能范围

底栏：**概览／资产／账号／待办／更多**。

- **概览**：即将续费／到期、项目待办、实物状态、最近使用和常用操作。
- **资产**：项目、域名、订阅、实物共用列表入口。按类型筛选，卡片直接显示各类型最有用的信息；花费、日期、分类、标签、搜索仍可使用。
- **账号**：账号与密码共用入口、搜索和详情，解锁后在账号原位置查看／编辑登录资料。保留邮箱／手机号身份、服务账号、关联关系与换绑检查。
- **待办**：手工任务、订阅／维护提醒、周期维护、换绑影响、项目改名／收尾清单和完成历史。
- **更多**：收录、账本、集合、分类／标签、资料引用、备份恢复、回收站、AI、助手访问与设置。功能入口不因手机导航变短而删除。

导航变化是同一批功能的重新分组。新草图的菜单入口有演示页面或操作面板；其演示深度不同，不冒称完整产品已经实现。

## 2. 账号与密码如何合并

### 用户看到的体验

同一个服务只需从“账号”进入一张详情卡：账号名称、网址、登录邮箱／手机号、关联项目与订阅、登录凭据、备注、历史和管理操作。

| 情况 | 列表与详情行为 |
|---|---|
| 只有普通账号资料 | 一直可查看、编辑、建立关系；密码区域提示解锁管理，不把锁定状态当作没有密码 |
| 普通账号已关联KDBX条目 | 解锁后在原卡片显示登录资料，可复制、生成、编辑、查看历史；不跳去另一套相同账号列表 |
| 只存在于KDBX的条目 | 锁定时不暴露条目名称、标识、数量；解锁后显示在“待关联”中，用户可以确认关联或保留独立登录资料 |
| 一个账号有多组凭据 | 保留所有条目UUID，逐组选择，不能按同名／同域名静默合并 |
| 一组凭据关联多个普通账号／资产 | 保留 `linkedAssetIds` 的原语义；以明确关联生成展示，不自动重写原关系 |
| 锁定 | 清除解密详情、临时索引与尚未保存的明文；普通账号资料继续可用，搜索不读密码／私密备注 |

### 数据与保存边界

这是**界面与操作入口整合**。普通账号仍是既有 `asset.kind='account'`；密码／长期密钥、密码历史、密码回收站、附加标识和加密导入草稿仍只在独立KDBX内。已有 `VaultPersistence`、`VaultEntrySummary.linkedAssetIds`、账号关联审核与恢复逻辑继续复用。

匹配优先使用现有显式关联和已有用户核对规则，不因为邮箱相同就推断OAuth／恢复关系，不按服务名称自动去重。缺少／歧义关联需核对；旧备份的账号ID、关系ID、KDBX条目UUID及自定义字段不变。

账号与KDBX不是同一个原子事务。一次“保存”可分步完成，但不能隐瞒部分失败：账号成功而密码失败时，显示“账号已保存，登录资料尚未保存”，允许重试；旧密码保留。需要跨存储恢复时，明文密码不得进入普通SQL日志，复用KDBX内的加密草稿或密文检查点。

删除普通账号、解除密码关联、移除登录资料、两类回收站仍是不同操作，确认时明确范围。合并入口不等于自动删除另一边。

## 3. 资产卡片的信息与数据依据

| 类型 | 卡片直接显示 | 现有数据来源与含义 |
|---|---|---|
| 项目 | 项目状态、项目待办3/5、最近到期、预计费用；进入可看域名／关联账号／外链／宣传资料／工作流 | `status`、`task.assetId/done`、`projectDomains`、关系和账本。没有通用研发阶段／百分比字段，不编造产品开发进度 |
| 域名 | 域名、所属项目、距到期天数、记录到期日、注册商／账号、年费／自动续费记录 | 已有 `projectDomains[].id/name/expiryDate/annualAmount/currency/registrar/accountId/autoRenew`；是项目内记录的汇总视图，首版不新增 domain kind 或重复主记录 |
| 订阅App | 距下次续费天数、账期、每期金额、已记花费、关联项目／账号、试用／优惠／取消状态 | `dueDate/billingAnchor/cycle/interval/amount` 与 `history`。账单日不能直接宣称服务使用权到期；界面写“距续费”，实际授权结束日若另有需求再独立建模 |
| 实物 | 购入多久、购入金额、启用时间、使用／闲置／维修／借出状态、保修记录 | `purchaseDate/itemStartDate/itemLifecycleStatus/status/warrantyDate/itemWarrantyStatus/amount/itemPurchasePriceKnown`；没有购买日就显示未记录，不能从创建时间推断购买年限 |

项目“待办3/5”只统计明确属于该项目的目标任务集合，标签说明分母；既有改名／收尾工作流按其当前round单独展示，不能混成研发完成度。未来通用里程碑若要新增字段，必须另做旧备份往返验证。

日期用用户所在地当天的日历日期与既有纯日期规则计算；未记录、已到期、暂停、已取消有各自状态。剩余天数不能对未知日期显示0，更不能把过去日期当成仍剩余正数。

域名是派生行：点击定位原项目中的该域名；新增／编辑仍写所属项目。卡片统计分别标“4项资产／1个域名”，不能把同一域名同时当独立资产再计一次。共享订阅在全局费用只计一次，项目视图明确列出关联订阅原金额，不伪造分摊。

## 4. 花费的口径

- **已记账支出**：沿用既有账本中明确的支出／续费记录；退款另列，充值和余额不当作花费。按账本ID去重。
- **实物购入金额**：来自已知购入价，单列，不自动混进已有账本支出，避免同一购买记录被重复相加。
- **预计费用**：订阅每期／月均和域名年费单列。域名 `annualAmount=null` 显示未记录，不当0。预计费用不冒称实际扣款。
- **币种**：CNY／USD等分行汇总，不在没有汇率来源时合成一个总数；复用现有整数最小单位、`monthlyMinorUnits` 和货币格式化。
- **日均成本**：本轮不把原价除以使用天数称作总持有成本；维修等费用不全时不显示假精确结果。

草图按2026-10-27的虚构例子展示：购入2年5个月、域名距到期59天、订阅距续费7天、项目待办3/5。示例不是从真实资料读取。
