# F21 原生连接平台适配（2026-10-27）

## 完成与范围

- 开工重新 fetch origin；当时 HEAD 相对 origin/main 为 74 ahead / 0 behind。未覆盖其他代理文件，未更改数据库/绑定/同步/KA1 协议。
- 官方工作区核验与列表改传构建配置的官方服务 origin；不再错误使用手机 WebView 的 localhost origin。构建固定源与绑定授权校验保留。
- Native 自托管账号需要用户输入并确认完整 HTTPS origin，确认前没有登录表单或请求。沿用已安装 BetterAuth 1.7.6 client，通过其现有 `fetchOptions.customFetchImpl` 使用独立平台传输；Web 保持原同源行为。
- 新 `KeepAnyConnections` 原生插件为每个已确认端点创建独立进程内 Cookie jar。Cookie 不经过 JS、不写 Preferences、普通数据库或系统/WebView Cookie jar。重启后重新登录。关闭/更换服务器会清 jar 并取消所属在途请求；切换连接方式同时清 UI 的旧账号与端点，防止出现已关闭会话仍可操作的状态。
- 原生会话只允许既有 auth 登录/注册/登出/get-session 和既有严格同步路由；固定 origin，拒绝重定向/用户信息/查询/额外头，保留默认 TLS 验证。Native 给已确认服务器设置其自身 Origin，服务端 `trustedOrigins`/CSRF 规则未改。没有全局 fetch 或 CookieHandler 补丁。
- 工作区列表新增 `listSessionWorkspaces`，身份先核对，再通过已注册平台 fetch 读取并验证 UUID/读写权限；只提供可读写工作区。移除设置页裸 fetch。
- S3/WebDAV 只在原 transport 构造时注入独立、精确 URL+方法的 fetch；保留签名查询、Basic 来源和全部现有 HTTPS/对象匹配/加密/读回/hash/恢复校验。原生桥按 256 KiB 分块传输密文，上传从应用缓存文件流式发送，下载有界写缓存文件再分块读取；预算保持 100 MiB+1024 字节。成功、错误、取消均清理本轮临时文件，下一次插件载入清理旧密文临时文件。
- Native/未注册连接适配器会明确失败，不回退 Web fetch。未导入凭据到普通配置，插件不记录请求/响应/原始异常/秘密。
