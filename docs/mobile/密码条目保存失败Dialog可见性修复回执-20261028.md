# 密码条目保存失败 Dialog 可见性修复回执（2026-10-28）

## 范围与结论

本片修复 `PasswordVaultPanel` 当前条目编辑器的失败反馈。原 `pwVaultSaveFailed` / `pwVaultConflict` 文案不变，保存失败现在显示在当前 Dialog 的 Save 同一操作区，使用 `role=alert`，并滚动至最近可见位置。错误绑定编辑器 generation；新建、切换、取消、锁库和成功时清除，锁库或取消之后的旧异步回调不得关闭新编辑器或补发旧提示。保存请求独立编号，旧回调不得清掉后续请求的 busy 状态。

没有修改 VaultSession、KDBX、持久化、主密码、KDF、schema 或隐私逻辑，没有自动重试。此次结果是共享 React 实际浏览器 B 条件；**N24 原生错误仍保留，修复尚待新 APK 的原步骤复验**。

## 原红与新源复验

先实际目检 Shell 的 N24 原件：`test-results/native-m0-io-n24/vault-permission-observed-error.png`、`vault-permission-error-draft.png`。编辑 Dialog 保持打开且 Save 可用，失败提示在 Panel 根 `role=status`、视口之外。本片未连接设备，也未重新执行原生权限故障。

采样边界纠正：Shell 后续自 review 指出，中文即时 `vault-synthetic-error-draft.png`（SHA 前缀 `a32d4e`、后缀 `3916f7`）实际有正确两行 toast，但覆盖 Save 上半部；持久 `.password-vault-message` 仍在 modal 外且 y<0。英文 helper 先因双份 notice locator 中止，后续图拍于 toast 消失后，不能证明即时完全没有提示。故 N24 真红准确为：**持久错误不在当前编辑器，短 toast 退场后不可见，且 toast 可遮挡 Save**，不能表述成“两语从未提示”。原 Native 原件、7f9f191a 软件首红及 hash 均保留。

本片 `saveEntry` 的失败分支只设置当前 editor 局部错误，不再调用 `announce`，因此同次编辑保存失败不会另发全局 toast；其他成功及非 editor 消息路径原样保留。软件首红是在等待 toast 消失后确认 Dialog 无 alert、根提示不可见，依然是有效的持久反馈复现。

隔离 Chromium、触控 390×844、中英各一新 context，实际 UI 新建合成密码库、保存 sole entry、锁定并用原主密码解锁。仅在该 context 的公开仓库持久化方法受控拒绝一次，实际 VaultSession 捕获该拒绝；不是 Native I/O / 低空间实证。

| 操作 | 预期 | 旧源实际 | 修复后实际 |
| --- | --- | --- | --- |
| 编辑 Title → Save，持久化拒绝一次 | 当前编辑器可见失败，稿件和旧库保持 | 两语 Dialog 无 alert；根提示 y=-454.61、h=61、viewportRatio=0 | 两语 Dialog alert x=32、y=659.80、w=326、h=48，viewportRatio=1；与 Save 同区 |
| 同稿再次 Save | 实际提交一次，成功后关闭 | 首红在可见性断言停止，未冒称后续通过 | 仅增加一次实际写，cipher/revision 前进，原 UUID 保持 |
| 原主密码重新解密落盘字节 | 完整字段、旧版本历史准确 | 未执行 | 独立只读 VaultSession 解密后，完整 draft 仅 Title 改变；sole entry、原 UUID、唯一 history 的完整旧 draft 均准确 |
| 持久化返回 `vault-stale` | 独立冲突语义，不能当成功 | 未执行 | 当前 Dialog 显示原 `pwVaultConflict`，Save 可重试，cipher/revision 不变；取消再开不带旧错 |
| 写入等待中，正式 Provider 锁库事件 → 迟到拒绝 | 锁态和新编辑器不受旧回调污染 | 未执行 | Dialog 关闭、主密码输入恢复；迟到拒绝不补根错误，cipher/普通 rows 不变；重新解锁新建稿无旧 alert |

旧源首红的基线普通 rows 为空，不能据此声称非空普通资料保护。最终用例补入一条经正式仓库保存的合成 project keeper；最终两语均逐完整 row 的 SHA 比较，失败、成功重试、锁库迟回均保持该普通记录。密码输入始终 masked，未 Reveal。失败后实际 session 原完整 draft 和 history=0 保持；重试后历史严格为一次。
