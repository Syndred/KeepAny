# iOS 空格前缀屏障与统一日历测试适配候选

本片只修改 `apps/mobile/ios/App/KeepAnyUITests/KeepAnyUITests.swift`。基线为 `6e0536c25e7b0e6ffdb86d0cc95b9e314be2d4b1`；没有修改产品、依赖、工作流或已冻结 N28 APK，也未推送。以下是待 Apple 执行的测试层候选，不是 iOS 功能通过回执。

## 实际问题与边界

- 主控已核旧 8a5 实际 UI 为 7/8。英文取消草稿的中篇介绍期望 `Cancelled projectMediumDescription`，实际为 `CancelledprojectMediumDescription`。本片保留原失败和原期望；尚不能确定丢空格发生于 XCTest、WebKit 还是输入事件时序。
- 新统一 DatePicker 是 `type="text"`、`role="combobox"` 的 ISO 输入和 Base UI 网页日历 dialog。旧两个测试硬等 `app.datePickers`，不再对应产品实现；旧原生日历成功不能继承为新组件通过。
- 原完整项目文本用例仍是 14 项文本/多行字段，日期本来不在其编辑范围，预期的 `projectLaunchMonth` / `projectInspectionDate` 仍为空。本片不扩大或删除这些期望。

## 候选修改

### 原生文本输入

已有 LF 精确前缀屏障扩展到 ASCII 空格：按 Unicode scalar 顺序保留文本段、每一个 U+0020 和 U+000A，逐段调用原生 `typeText`。同一控件保持焦点，每段必须精确达到累计前缀才发送下一段。

所有片段共用一次 monotonic 20 秒期限，不为每段重置；每次原生输入前也检查期限，不在已超时后再发送下一片段。失败保留原 PNG、AX、阶段和长度诊断，并执行原完整值精确断言后停止；不 trim、不修字、不重打、不重新定位 caret、不用 JS 写值。没有空格/LF的原单次输入分支及 Select All 清空路径保持不变。

### 真实日历交互

两个日期 case 改名为 `testEnglishDateInputSelectsSharedCalendarDate` / `testChineseDateInputSelectsSharedCalendarDate`，总 UI case 仍为 8 个。

实际步骤为：

1. 正式 Tasks 链接进入，优先寻找 Start date / 开始日期的真实 combobox；WKWebView 类型回退只接受唯一、可达、带字符串 value 的同标签控件，不接受 StaticText。
2. 原生 tap 打开唯一 `Choose date` / `选择日期` 网页 dialog，保留类型、阶段和 AX；原生 Done（若存在）只用于收起键盘。
3. 点击日历的 Today / 今天，仅将显示月定位到设备本地当前 Gregorian 月，并核精确当日 ISO 值和关闭。
4. 重开后实际点击该月 **15 日**的确切可访问日期按钮，核精确 `yyyy-MM-dd` 和关闭；再重开核同一日期的明确 selected 标签，并保存自然截图。
5. 用日历内 Clear dates / 清除日期解除本测试的筛选，核关闭与空值/确切空占位 AX 表示，不污染后续任务用例。

输入及可达日历按钮要求至少 44×44pt，日历与按钮横向不得越过 WebView 边界。仍使用原 10 秒有界等待；没有延长工作流或输入等待预算，没有写入模型/DOM。

15 日标签依据已安装 `react-day-picker@10.0.2` 的 `labels/labelDayButton.js`、`locale/zh-CN.js` 和配套 date-fns `formatLong`：英文含 `15th`，中文含完整星期名，Today/selected 前后缀逐字保留。只复用 API/公开语义，没有复制上游实现或添加依赖。真正 WKWebView 的 AX 类型、日历 label 与操作仍待下一 Apple 证明；若不匹配，测试应保留失败，不回退到任意按钮或旧 UIDatePicker。

### 分类控件

只增加当前框架分类 AX 的受控诊断，最多 12 个同分类标签候选、每个 label/value 最多 160 字符，记录类型与可达性。原分类查找、非空值要求、完整译文和只允许单个尾 LF 的精确校验保持不变；未接受 nil 或任意相邻文字。
