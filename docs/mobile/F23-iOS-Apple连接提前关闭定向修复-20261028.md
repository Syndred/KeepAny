## 定位到的连接观测缺口

1. 测试已知目标为exact127.0.0.1，却使用 `ClientBootstrap.connect(host:port:)`。官方[2.104 Bootstrap](https://github.com/apple/swift-nio/blob/2.104.0/Sources/NIOPosix/Bootstrap.swift)明确该形式的Happy Eyeballs channelInitializer可能针对多个候选运行；原代码复用一个stateful ResponseBytes及promise，并把聚合初始化/连接异常直接抛出，无法可靠保留第一条类型化错误。改为 `connect(to: SocketAddress(ipAddress:...))`，一份探针对应一个固定IP socket，初始化错误直接传播，不走DNS/IPv4-v6竞速包装。
2. 原探针返回只等TCP connect，未等NIOSSL完整验证结束；随后的write可能先看到已关闭通道，掩盖握手失败原因。现在观察官方 `TLSUserEvent.handshakeCompleted`，只有实际验证完成才返回正向Probe。握手与响应各自promise共用exact-once完成状态，初始化/管线错误/早断开/超时都会明确结束，清理先settle再close/group shutdown，不通过无限等待或移除NIO泄漏断言绕过错误。
3. 保存管线第一条错误，catch及write失败优先抛它，避免二次close覆盖；Apple测试日志增加非秘密阶段序列（初始化、注册、TCP active、TLS authenticated、管线错误、inactive）与该类型化错误。日志来自完全合成测试，不输出请求正文、token或私钥。若下一轮仍有真正TLS/服务端问题，这些证据用于继续定位，不把通道关闭本身视为验证成功。

**现有日志不足以证明底层正向TLS一定正常或Happy Eyeballs就是唯一关闭原因。** 本片修复上述可证实的观测/生命周期缺陷，并让下一Apple运行给出首个具体失败；Windows不能替下一轮真实连接结果，不能先写“17项已修好”。

## 断言与安全边界保持

- 未信任证书、错误IP SAN、TLS1.1仍必须在真实握手阶段抛NIOSSL类型错误，错误IP仍要求exact `failedToValidateHostname`，IP SNI初始化仍要求exact `cannotUseIPAddressInSNI`；不改为接受普通EOF/closed/DNS失败。
- 所有正向返回的Probe现在先经过完整TLS认证，随后原HTTP/取消/字节预算/停止重试断言继续执行。生产30秒期限没有改短；第5连接的容量拒绝只允许实际关闭、不允许探针超时，不把其未进入TLS握手与证书负例混淆。
- 客户端仍 `fullVerification`、原单证书信任、nil IP SNI且实际remote IP SAN校验，没有accept-all回调、系统CA修改或校验降级。NIOTLS仅作为测试target的直接依赖，复用同已固定NIO版本。
- 原销毁弱引用检查改为weak holder，仍要求真实释放与stop事件，避免Apple的局部weak变量可变性警告；未删除销毁检查。
