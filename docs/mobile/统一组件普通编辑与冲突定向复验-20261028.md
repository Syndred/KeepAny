## 原红与测试窄修

正式执行英文 project 全字段用例时，首先在第153行字段 key 集合断言失败：Base UI Select 的代理输入被计入 `base-ui-_r_l_-hidden-input`。真实 trace DOM 显示该 INPUT 没有 `type=hidden`，但有 `aria-hidden=true`、`tabindex=-1` 和 1×1 裁切样式。

同一 trace 独立证明 `projectInspectionDate` 为 `INPUT type=text role=combobox`、实际 value 为 `2026-11-01`、没有 `data-value`；旧稿输出中的日期为 `null`。旧 reader 将所有 combobox 当成 Select 读取 `data-value`，导致失真。**原单例先被代理 key 阻断，尚未执行到 changedForm 的日期期望断言**，不能把两项说成同一次已走完的失败。

在 `mobile-fullfield-edit-acceptance.spec.ts` 与 `mobile-ordinary-stale-acceptance.spec.ts` 的 `formValues` 中各改两行：排除真实 `aria-hidden=true` 代理；HTMLInputElement / HTMLTextAreaElement 读取原生 `value`，只有 Select 的 `button[role=combobox]` 读取 `data-value`。源守卫确认除这两行外用例全文未变。英文 project 原用例随后完整通过，保留全部字段 key/value、取消全记录不变、再次保存、刷新同ID及关联历史/文件保护断言。

原失败 screenshot、trace、框架报告完整保存在 ignored `test-results/ui-merge-stale-remaining/fullfield-reader-original-red/`，未覆盖。
