## 已复现缺口与修复

**D-F21-W01 / P2，已修复：Request输入丢自身headers和signal。** 修前`connections.ts:105/109`仅读取`init.headers`和`init.signal`，但返回值声明`typeof fetch`且URL/method/body已接受`Request`。最小触发：建立合法HTTPS对象的Request，添加合成Authorization与AbortSignal，先abort，再传`backupFetch(request)`。实际本片使用esbuild打包真实当前TS（只有Capacitor环境和原生bridge为合成）后执行，结果仍resolved、nativeRequestCount=1、Authorization未转发。预期应AbortError且不发原生请求。证据`test-results/f21-whitebox/request-input-red.json`。

当前正式S3/WebDAV连接器使用`fetch(url, init)`，其原路径未丢头/信号；本片不把该接口缺口夸大为全部当前页面上传都失败。主控确认并授权此两文件修复。

修复只将备份分支与Request语义接齐：`init.headers !== undefined`时用明确给出的头，否则回退Request.headers；signal同理，显式`null`可以解除原Request已取消的信号。现有HTTPS、精确URL+方法固定、头白名单、预算与协议保持。

实际bundle C复验绿：

- 预先abort的Request上传不调用backupWrite或backupRequest。
- Request自带Authorization、PUT方法和包含0/128/255/64的原始字节精确传入正式适配器；没有输出头值到回执。
- init的method/body/空headers与新signal显式覆盖Request；显式null signal也优先。
- Request自身signal在原生调用进行中abort，原请求ID收到cancel且调用方拒绝AbortError；合成迟成功不能返回给已取消调用。
- 未许可POST、init FormData仍明确拒绝，没有扩大接口请求协议。

`request-input-green.json`保存上述布尔结果及C环境。现有`connections.test.ts`新增三条正式合同，原5文件25条＋新增3条实际28/28绿（connections9、service-fetch8、remote-backup7、session-workspaces1、i18n3）。机器记录`request-final.json`。类型检查和所改两文件Biome lint退出0；没有运行产品全套。

## 白盒逐项结论

以下是源码审查；“具备守卫”只表示当前代码路径，不等于对应iOS实际网络成功。

| 检查 | 源码位置与实际判断 | 剩余动态条件 |
|---|---|---|
| 原点/路由 | TS `openSession`使用serviceOrigin，session fetch固定origin且拒凭据/query/hash与未知路由；Swift `target/origin/sessionRoute`再次核对HTTPS、session owner、原点和精确路由，备份仅GET/PUT。TS备份以URL+方法白名单保留签名查询 | 实际iOS HTTPS登录、证书失败、不同端点及非ASCII/显式端口规范化仍需N；没有用静态源码证明TLS请求已成功 |
| TLS/重定向 | Swift `BoundedRequest`使用URLSession默认server-trust处理，其他认证challenge取消；重定向回nil并置failed，不接受302为成功。没有自设信任根或全局URLSession/Cookie补丁 | Apple真实服务器证书/重定向闭环、会话过期仍待；本源来自构建或明确配置，不冒称任意URL元数据DNS-pin合同 |
| 会话/凭据隔离 | Swift每个MemorySession独立cookie数组，最多4会话、同origin拒重复；URLSession为ephemeral、cookieStorage/credentialStorage/cache均nil。按域/path/secure筛发送，响应仅回content-type/content-length，不回Cookie。共享字典/owner/cookie操作回plugin串行queue | Cookie跨响应/退出/重登/重启/后台的实际Apple系统行为未实跑；上限256超出清空会话Cookie，不承诺系统级长期存储 |
| 关闭/迟回应 | closeSession清cookie并删除session，取消owner在途task；完成回调回plugin queue并核对原owner对象仍是当前session，已关闭会话不回填或成功。TS关闭先阻断旧connection，移除sessionFetch引用 | 取消撞上delegate完成有下方R01静态并发风险，不能据此写无竞争结论 |
| 取消 | TS run监听signal，拒AbortError并主动cancel；备份finally再清理。Swift取消标记120秒、cancel task、移除暂存映射；完成时先查cancelled，迟回应拒绝。active只有真正完成回调才释放，最多4，未把JS取消当服务器未收到 | 真实网络写入后取消不可承诺远端回滚；N应验证下载中/上传中/后台关闭，及取消遇IO失败的清理结果 |
| 大文件 | TS分块256KiB；Swift写块/累计文件均有界，最多两暂存文件，sealed后不得继续追加；PUT从文件上传，GET委托逐块有界写文件。Content-Length声明和实际累计各自挡上限。原预算100MiB+1024保留；普通session 8MiB/附件4MiB | TS仍会把上传Blob整体arrayBuffer，下载收集分块并构建Blob；分块不等于JS恒定内存。接近上限时Apple真实内存/低空间/后台未验，不能据C100MiB测试承诺无OOM |
| 临时文件/核心资料 | Swift仅在temporaryDirectory/KeepAnyConnections的transfer-UUID.bin写密文，文件complete保护；不触及核心SQLite/原图/长期KDBX目录。cancel及下次load仅清匹配自己的暂存文件 | 清理removeItem使用try?，为best effort；真实锁屏/文件IO删除失败须N核验，不宣称所有异常都已物理删净 |
| 错误反馈 | Swift invoke和完成失败仅固定native-connections-failed，不回原始异常/URL/秘密。TS无插件明确unavailable、不回退Web；HTTP4xx/5xx仍是真Response交连接器，正式读回/hash/解密成功前不出备份成功凭条 | 本片C/Synthetic bridge不能替代iOS实际权限/超时/存储错误；UI最终翻译和重试还应与N联验 |
| Request method/body | Request.method既有回退；init.method优先。body支持string/Blob/ArrayBuffer/TypedArray，以及Request.clone().arrayBuffer；GET带body拒绝；init FormData/独立ReadableStream等仍明确native-connections-body拒绝 | 这是受限服务传输的现有支持范围，未声称完整替代浏览器任意fetch；对象存储调用仍用既有二进制路径 |

## 编译与异步剩余风险

**已由主控独立确认的Apple编译红，不重复派修：** 第6轮Apple CI运行`40505326600`报原Swift:84 `pluginMethods`推断为`[CAPPluginMethod?]`而协议要`[CAPPluginMethod]`。主控已将当前源码改为显式类型的七个CAPPluginMethod数组；本片未改Swift。是否通过下一轮真实Apple编译，以主控拉取的CI结果为准，不能把Windows读源码当编译成功。

**R01 / 静态并发风险，未复现iOS崩溃：** `BoundedRequest.cancel():54`在plugin DispatchQueue读取`self.task`，`didCompleteWithError:69–70`在每请求独立URLSession delegateQueue写`self.task=nil`/`self.session=nil`。两队列各自串行，但此属性访问未共享同一执行器/锁。最小动态核验：让合法大GET最后一个数据块完成时连续触发cancel或closeSession，用Thread Sanitizer观察这些属性访问，再核对只回一次、active释放、文件删除、不返回迟成功。应由Swift owner采用统一线程约束或同步后在Apple工具链确认；本片只报告源码并发可能性，未伪称已经捕获运行时竞态。

Package.swift固定Capacitor8.5.3，swift-tools 6.2、language mode v5；API/Sendable相关诊断以实际Xcode版本为准。此处没有新增依赖、复制上游算法或改Swift package。R01及大容量/后台/低空间/真正HTTPS会话是明确剩余，未用28项软件绿核销。
