# F21 原生备份限额错误分类修复回执

本片修复 Native11 已实证的错误提示，不把软件层验证当作新 Native 通过。原红与设备状态见 [F21 原生 HTTPS 实装回执](F21原生HTTPS实装回执-20261027.md)，checkpoint `601c3546`。本片未访问设备、控制器、私密 fixture 或任何服务，未导入真实资料。

## 原红与根因

Native11 分别读取固定 `/declared-oversize.ka1`、`/stream-oversize.ka1`，均已安全拒绝；transfer 为零、原库和远端对象不变，但界面错误指向密码/解密。Android `ConnectionsHttp` 把声明超限、累计流超限与网络失败都抛同一 Failure；Swift delegate 取消后也丢掉超限原因。TS 不能据此进入既有 `backup-size` → `remoteSizeError` 映射。

本片先运行新测试：TS 两个稳定限额码场景及三个桥动作的未知错误脱敏共 5 红；JVM 声明、累计流两个独立场景均红，期望 `native-connections-limit`，实际 `native-connections-failed`。损坏 base64 对照场景已绿。修复前 JVM XML 保留在 ignored `test-results/mobile-connections-size/jvm-red.xml`。

## 实现与保留边界

- Android 区分已核验的备份文件字节预算异常 `LimitFailure`，plugin 仅传固定 `native-connections-limit`。其余异常继续固定 `native-connections-failed`，不返回异常文本、URL、认证内容或 TLS 详情。
- Swift delegate 单线程队列记录文件超限原因，在 URLSession 因拒绝响应而回调 cancellation 时保留该分类。原 NSLock、`self.task` 清理、显式取消及 session 归属守卫保留；用户取消仍不会变成成功或文件大小结论。
- TS 只信原生稳定 `code`，不搜索错误消息；三个备份桥动作映射该码为 `Error('backup-size')`，未知错误固定脱敏。原 `RemoteBackupPanel` 已有大小文案映射，无需改 UI。
- 下载限额仍为 `100 MiB + 1024`，桥接块仍最多 `256 KiB`；上传累计预算、流式累计检查、响应关闭、请求槽释放与 finally cancel 保留。
- 上传确认响应的 8 KiB 上限与 session JSON 上限仍受限，但返回通用失败；确认响应过大不能误称用户备份文件超过 100 MiB。损坏 base64、无有效稳定 code 但消息恰好含 limit、TLS/认证/未知异常均不能冒充已核验备份超限。
