## 操作与逐字段合同

每条的相同步骤为：打开合成资料详情 → 编辑 → 展开表单所有折叠组 → 将下表全部字段同时改成不同于原值的内容 → 取消 → 比较完整 before/after-cancel → 重新编辑并核对每个原表单值 → 再次全部改值 → 保存 → 核对完整记录、关系、历史、文件 → 刷新 → 再次打开编辑核对保存值 → 取消并确认没有新写入。

| 类型 | 本轮实际同时改动的全部普通编辑表单字段 | 明确改值示例与预期 |
| --- | --- | --- |
| 项目（17） | 名称、分类、网址、上线月份、下次巡检、联系方式、简短描述、产品标题、推广链接、标签、中等介绍、完整介绍、功能、价格说明、价格类型、联系邮箱、备注 | website→tool；2024-01→2025-05；巡检改 2027-02-01；全部文字/多行文字/两标签均改。域名、原 status、非本类型遗留字段、四类图片引用和文件字节保持。 |
| 账号（11） | 名称、分类、网址、服务商、用户名、联系方式、用途、状态、核验日、标签、备注 | other→social；active→paused；核验日改 2027-02-02；其余均改为明确的新值。普通非邮箱用户名避免引入本轮无意测试的身份生成行为；原附件、遗留非编辑字段保持。 |

测试会从实际 DOM 枚举所有非文件输入与 combobox，要求字段集合恰等于上述清单；每个新值必须与打开时原值不同，防止漏改或只验证子集。项目的四个图片上传控件与其他类型图片命令本轮没有重新上传；按授权复用现有合成引用并逐字节 SHA256 保持验证，不将其冒充本轮图片编辑通过。项目状态/域名、物品借还/生命周期是独立详情操作，不属于这个 Edit 表单，本轮只证明它们不被普通编辑覆盖。

## 首次失败、复验与边界

- 预热脚本最初只在 `.page-header` 内找项目 Edit，而项目按钮位于独立 action bar；改为正式页面第一个精确 Edit 按钮，四个编辑模块预热完成。是测试选择器错误，无产品改动。
- `first-run.txt` 八条均在合成前置被正式仓库 `item-action-required` 拒绝，尚未进入待验 UI：不能用 saveBatch 直接创建借出/idle 物品。保留原失败；改为先合法创建，再调用正式 `recordItemAction` 记录生命周期与借出，保留事件历史。未绕过仓库守卫或直接写 RxDB 内部行。
- 同一 UI 合同复验 `second-run.txt`：**8 passed (42.7s)**，每条 pageerror 空、无横向溢出，双语草稿/保存截图已自查。该数量只说明八条上述具体流程完成，不表示所有功能或所有视觉组合通过。
- `tsc --noEmit` 退出 0；Biome 仅检查本轮新 E2E 文件退出 0。未泛跑全套，无产品修复需要。
- 仅 390 touch 桌面 Chromium 的 B；未操作 Android/iOS、系统 picker、原生软键盘、360/430、额外并发/CAS、故障注入或图片替换。这些不因本轮通过而被覆盖。
