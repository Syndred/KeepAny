# F23 Android 配对准备与前台激活

实际日期：2026-10-28，Asia/Shanghai。接续 `eed99c77` 的受限 TLS IO；原安全预算、解析器、响应缓冲、取消合同不变。本轮只改 Android 底层及定向测试，不改 TS/UI、注册、Manifest 或 iOS，不构建 APK、不操作设备。

## 原因与接口

系统保存/分享界面会触发 Android `onPause`。旧 `start→导出配对文件` 会按原前台安全合同停 listener，使刚保存的文件立即失效。保留 active 状态后台即停；新增两阶段配合主控实现的 UI：先生成并导出，回应用后由用户显式开始等待。

- `prepare({address})`：仅接受显式、实际已分配的受限 IPv4。生成内存临时 TLS 身份；短暂 bind0 取得 OS 端口后立刻关闭探针，不 accept、不处理 MCP、不创建 grant；返回 instanceId/endpoint/certificatePem/spkiSha256 四元组。拒覆盖已有 prepared/active。
- `activate({instanceId})`：只在前台激活当前未过期 prepared；重新检查接口，用相同端口、证书、pin。返回逐字相等的四元组。端口被抢占或接口/期限变化时清理并固定失败，必须重新 prepare；绝不自动选新端口或换证书。重复 activate 拒绝，不停止已 active listener。
- prepared 同时受单调时钟和壁钟的保守到期检查、120s 串行定时清理约束；可跨系统 picker 的 pause 暂留，pause 时不能 activate。active 仍在 pause 立即停；resume 不自动激活。
- reset、显式 stop、destroy 都清 prepared/active、计时器、内存身份并发 mcpStopped；旧实例 stop 幂等、不影响新实例。prepare/activate/start/stop/reset 同一生命周期队列，避免迟到启动或旧 timer 停新实例。`start` 保留为 prepare+activate 快捷接口。
