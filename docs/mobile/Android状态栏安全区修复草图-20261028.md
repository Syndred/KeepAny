# Android 状态栏安全区修复草图

用户在 vivo X100 Pro / OriginOS 6 实际安装后报告顶部按钮被状态栏覆盖。本次沿用已确认的统一组件与主题，只恢复应用内容与系统栏的边界。

```text
原：屏幕顶部 ┌ 系统状态栏 ─────────────────┐
            │ WebView 页头也从这里开始   │ ← 新 WebView 的 cover 模式重叠
            └ 页面内容 ──────────────────┘

修：屏幕顶部 ┌ 系统状态栏 ─────────────────┐
            ├ 原生安全区边界 ─────────────┤
            │ 页头：菜单 / 搜索 / 新增    │
            │ 正文、侧栏和弹窗均在此范围 │
            ├ 原生安全区边界 ─────────────┤
            └ 系统导航栏或手势区域 ───────┘
```

实现选择：复用当前 Capacitor 内置 SystemBars，以 `viewport-fit=contain` 让原生容器留出系统栏和挖孔区域；明确使用推荐的 native insets 处理，并使 Android 边缘布局策略一致。不加机型专用固定像素、不隐藏系统栏、不对每个按钮追加偏移。当前 iOS 已将 WebView 约束在原生 safeAreaLayoutGuide 内，继续保留该约束。

已读当前安装版本 `SystemBars.java`：WebView140及以上且viewport为cover时透传安全区；其它情况给原生容器padding。本应用此前只有底部CSS安全区处理，页头未消费透传的顶部区域。官方说明：[SystemBars](https://capacitorjs.com/docs/apis/system-bars)。这是与用户现象一致的代码原因；模拟器和vivo真机修后结果分开记录。

验收：中英文顶部所有按钮在状态栏下方且可触选，滚动/侧栏/弹窗不侵入系统区域；无多余双重留白；底部导航与键盘仍可使用。资产筛选只高亮当前一项。最终交付重新构建的测试APK，不把旧N26的通过记录当成此次统一UI的新包通过。
