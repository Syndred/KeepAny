# F10-03 归还取消、确认及陈旧提交回执（2026-10-28）

本片按原152表 F10-03 的“归还→取消→确认→查看当前字段/历史→再次归还”实测并修复，不改合同首四列。全部是独立合成 context 的生产 Web B；**不在已冻结 N21，也没有 Android/iOS 实装结果**。

## 先保留真实红

在独立端口4246服务新构建的生产静态产物 `test-results/item-return-confirmation/baseline-web`。通过正式 UI 设置语言→实物列表新增→打开详情→空借用人提交得到错误→填写借用人和预计归还日期→借出成功，再点“归还/Return item”。

两语390×844、hasTouch均实际没有确认 Dialog，直接把完整 raw 中 `loaned/原借用人/预计日期` 改成 `active/空借用人/空预计日期`，原一条 loan 外立即新增一条 return，用户无取消机会。根因是 `page-asset-detail.tsx` 入口直接调用 `recordItem("return")`。

- 真红结果：`test-results/item-return-confirmation/actual-red.json`，2条同条件失败，16.835秒；两语 `after-return-click.png`、trace与完整 before/final records 附件保留。
- 更早 `red.json` 是新测试误用 `en-US` 作为正式 Language Select 的 value；实际 value 为 en，改按可见语言 label 选择后重放。该前置错误保留，不计产品红。

## 窄修

复用现有统一 Dialog 与主题，仅归还先打开确认：文案包含该实物名和借用人，使用新双语 `itemReturnConfirm` key；取消/确认复用现有 key。

打开时冻结完整 Asset；确认把此 expected 交给现有 `recordItemAction/commitItemAction`，继续其最终 CAS 与配对历史事务。未新增仓库协议或状态源。取消不调用记录函数，不清原备注草稿；确认成功才关闭。忙时禁用关闭及按钮，原 in-flight 槽防重复提交；route ID 变化清该确认快照，旧 ID 不能对新页提交。陈旧确认失败留 Dialog 和原固定错误。

既有 `item-lifecycle.spec.ts` 两处真实归还调用只补确认点击，原重复提交的双击移到最终确认按钮，原借还、维护、历史、跨日与备份断言不删除。本片没有重跑该旧长链，也不把维护/KA1旧证据算成本片新通过。
