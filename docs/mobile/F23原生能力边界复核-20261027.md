# F23 原生能力边界复核（2026-10-27）

## 结论与未完成

正式手机包目前**没有实现本机MCP连接**。既有Web的Node loopback启动器/官方SDK通过不能外推手机；本片修复Native入口误导，保留准确“此设备目前不支持本机助手连接”的未支持路径，不能把禁用提示当成完整MCP交付。

F23-01未支持分支已重新完成白盒与合成Capacitor B；真实Android/iOS UI仍待包含本片的新候选。F23-06的原生受控SDK连接、长时断线/重连/离线返回尚未实现或实测，继续保留缺口，不删Web已有能力/合同。

## 正式调用链白盒

- `apps/mobile/src/main.tsx`正式注册SQLite资料集、Preferences、系统文件、metadata、binding、sync与NativeConnections；没有MCP server、adapter或启动器注册。
- `AppShell.tsx`使用共享`McpRuntimeProvider`；助手访问路由为`page-assistant-access.tsx`，设置助手区复用`McpPanel`。
- 原runtime仅有BrowserMcpBridgeClient，没有平台能力判断。McpPanel只根据已选资料启用生成请求，导入随后也可启用；助手访问页提示在设置完成本机授权。生成请求只是范围提案，原代码没有直接假造connected，但未实现的Native连接入口/说明不准确。
- `packages/mcp/src/browser-bridge.ts`实际通过fetch访问受信任的loopback URL；`pairingFile`严格要求`http://127.0.0.1:<port>`。真正server是`packages/mcp/src/bridge.ts`的Node HTTP server，由`apps/mcp-launcher`启动，并带Host/Origin/一次配对/授权约束。手机没有该Node运行路径；桌面127.0.0.1不是手机127.0.0.1。
- 当前Capacitor配置使用打包资产。已安装iOS8.5.3源码`CAPInstanceDescriptor.swift`默认scheme为capacitor；Node bridge的appOrigin只接受HTTP/HTTPS。没有把该白名单放宽以制造手机可用。
- NativeConnections/固定源service-fetch提供受限Auth/Sync/Backup，并非MCP relay，不通过全局fetch补丁或开放所有loopback路径冒充NativeMCP。
- runtime授权/请求/session secret在内存中，没有找到读取普通备份/Preferences自动恢复活跃grant的路径；Node authority持久记录在独立启动器侧。本片不删除这些数据/兼容文件，不改备份格式。

## 首红 → 最小修复

1. 合成Android标志、真实共享React/RxDB资料：选中记录后Create connection request仍enabled。英文390实际红保留在`red`，未虚构Native安装。
2. 经主控授权，runtime加入`localConnectionAvailable`。没有现成NativeMCP adapter注册机制，因此只依据正式`Capacitor.isNativePlatform()`判断当前实现范围，不看URL猜设备。
3. Native的prepare/import在处理文件、建client或发请求之前拒绝。配对审批与迟返回再核对平台；Native不显示scope、expiry或活动授权/审批对话框。可用性切换仅停止内存client并取消本页状态；未删Node authority或普通持久数据，审计快照保留原只读语义。
4. Native设置区明确不可用，禁用请求/配对/范围，旧提案不变为授权、不继续导出；助手访问页不给“连接后即可”的操作暗示。Web原路径保留，AI选中范围入口和本地编辑保持可用。用户文案没有Node/localhost/CORS等实现说明。
