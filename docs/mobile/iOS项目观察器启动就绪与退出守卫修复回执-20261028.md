## 原始失败与定位边界

N25 Apple run `40608679171`／job `122554513404` 的原始 `project-fixture-observer.log` 为 85 B，SHA-256 `ce8c3db67cd82e2de784d16e77ab4553e45e816237cb37aa09bc534f494b8aa8`，只报告固定 `container-unavailable`；exit 文件为 1，没有 summary。原始附件位于已核验的 `ios-ci-n25/contents`，本次未修改它。

原脚本在创建输出及进入轮询前执行一次容器定位，该次失败会直接退出。原分类不能区分单次 resolver 超时、simctl 命令失败或安装期间容器路径暂时缺失，因此不能把其中某一种写成 Apple 已证实根因。这是独立于两语分类 AX 末尾 LF 的观察器阻塞，不能由修复 UI 定位代替。

补充软件红绿：读取 Git 原脚本，对同一真实合成 SQLite 使用首次 resolver-timeout、下一次正常返回的受控 resolver。原脚本实际立即拒绝 `container-unavailable`，未创建输出；修后两次定位成功，完成一次只读查询并捕获空基线，最终完整字段验证仍为 false。证据保留于 `test-results/ios-observer-readiness-n25/red-green.json` 及同目录程序、原脚本副本。这是 Windows 软件 C，不是 simctl／Native 实跑。

## 最小修复

- 初始定位最多 30 秒、15 次尝试。只重试明确的 resolver 超时、命令失败和容器暂缺；错误设备／bundle、异常路径、目录或元数据身份不明等立即失败。单个 resolver 子进程预算为 `min(1500ms, 总剩余时间)`，重试等待同样不越过剩余时间。
- 取消或总截止时间到达时，仍只 SIGKILL 本次创建的 ChildProcess，并等待该对象的 close；不恢复 execFile 的 AbortSignal 默认终止方式，不枚举／终止其他进程。截止后确认清理可能继续等待真实 close，不能把预算理解为允许丢弃子进程。
- 新摘要包含本轮 runId、观察器 PID 与固定启动尝试／错误分类／耗时，绝不输出路径、原始 stderr、字段值或嵌套异常。无法定位时仍失败，不伪造空摘要。
- workflow 生成新 UUID，启动唯一观察器后，先执行最多 45 秒的 baseline-ready gate，再开始 xcodebuild UI。门槛检查本轮 PID／runId／UDID／bundle、simctl 模式、仍存活的精确 PID、完整且 healthy 的摘要、至少一次成功 SQLite 查询、已捕获基线，以及查询前后相同的容器／DB 身份。
- 基线匹配 0 个本轮完整字段 marker 合法；成功查询为 0、缺基线、旧 nonce／PID、部分摘要、错误身份、fatal 状态或观察器退出均不能通过。gate 只宣布 baseline-ready，明确保留后续完整字段验证待完成。

原只读精确数据库路径、SQL／JS 双重 marker 限定、首次保存→改名同 ID／完整其他字段断言、容器代际守卫及最终 `verification.complete=true` 门槛不变。若 UI 已执行，其原始 xcodebuild exit 仍优先；原 EXIT trap 只停止并 wait 自有观察器 PID。准备门槛失败则不执行 UI，不会被后续空摘要当绿。
