# iOS 观察器子进程测试预算拆分

## 原始失败与范围

主控交接的真实 CI `544`（run `40588460862`，verify job `122486122570`）仅新观察器组合 case 因 Vitest 默认 5 秒超时失败，其余 1339 成功、17 skip。旧写法把 sqlite/simctl × deadline/ready-state abort 四个真实子进程按顺序放进一个测试；两个 1500ms deadline 已占至少 3 秒，再加进程启动、关闭与 runner 负载，不能把整个组合稳定视为单个 5 秒工作。本片未在 Windows 复现该 CI 负载，不据此推断生产 CLI 的期限失败。

只修改 `scripts/observe-ios-project-fixtures.test.mjs`：四组合各独立 `test`，均继续使用默认 5 秒，没有增加单项或全局预算。逐项保留真实 child、TERM handler、准确 owned SIGKILL、实际 close、4500ms 自救未触发、原错误类别和耗时断言，并显式断言传给 CLI 的 timeout=1500。原有其他测试入口和业务断言不动；产品脚本、workflow、152 表及 README 不改。

## 本机实际验证

- 全文件：36/36，8.06s。原 33 项变为 36 项仅因一个组合拆为四项，不代表新增三条产品能力。
- 定向 Biome lint、Node syntax、`git diff --check` 通过。
- 独立自有 Node/Vitest runner 仅绑定 CPU affinity mask=1、maxWorkers=1，未修改父进程、系统或其他进程的 affinity。四项实际耗时：sqlite deadline 1528ms、sqlite ready-abort 105ms、simctl deadline 1557ms、simctl ready-abort 191ms；runner exit 0、4/4 成功，总计 4.09s。该轮的 32 skipped 来自 `-t force-kills` 定向过滤，完整矩阵仍为 36/36，没有新增 skip。

Windows 对 SIGTERM 的语义不同；这里只证明本机真实子进程与精确 SIGKILL/close 生命周期、单 CPU 下四项独立预算。POSIX 忽略 TERM 的真正行为和原 CI 红→绿仍须下一 Apple 执行，不能提前称已关闭。
