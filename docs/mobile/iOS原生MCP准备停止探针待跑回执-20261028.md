## 正式路径与预期

1. 从英文正式资产页新建最小项目，仅填写名称。独立随机名称前缀为 `iOS MCP prepare fixture `，不混用 full-fields observer 的项目白名单。保存后必须等该唯一项目链接出现。
2. More → Assistant access，先确认 `No active local connection`，再经 `Configure local access` 进入正式设置。
3. 必须存在原生地址输入框 `This device’s private IPv4 address`；unsupported 无此控件、初始化失败或错误状态均不能算成功。勾选仅本次项目，填写 `127.0.0.1`。
4. 核对实际 checkbox AX：可读字段仅 Name 勾选，其他可读字段及所有可编辑字段未勾；除正式提醒/AI设置的独立 checkbox 外，其余资产中只有本次 marker 被选中。Name 等读/写同名控件按正式 DOM 顺序及数量核对，不能因查到一个同名控件就推断只读。
5. 点击真实 `Prepare pairing file`。45秒观察限内必须出现完整 Ready 文案：`The pairing file is ready. Export it through the system, then start waiting for your computer. The ticket expires in two minutes.` 不接受 unsupported、PrepareFailed、StopUnconfirmed 或任意 alert 替代 Ready。
6. 确认真实 `Save or share file` 链接存在、`Start waiting for computer` 存在且禁用；没有 `Access granted` 或 waiting 状态。**不点击系统导出链接，不点击 Activate**。
7. 明确点击 `Stop connection`，要求配对文件链接、Activate、Ready文案及 Stop 按钮均消失，并恢复可点击 Prepare；停止不确认时保留 Stop，不能通过本断言。
8. 再经 More → Assistant access，确认仍是 `No active local connection` 且没有 Access granted。结束应用。

正式设置页没有“0”授权计数；本条记录实际已有的“无有效连接”、prepared Ready 状态和无 Access granted，不制造数字提示。Ready 只代表正式原生 prepare 调用链完成，不能声称已开启监听器、完成电脑配对或真实 SDK 请求。
