## 两语实际流程与触控

英文、简体中文分别从现有 QA10 的 All 界面从头执行，均实际通过以下相同流程：

1. 顶部菜单打开侧栏，等待抽屉矩形稳定，核四个主入口完整可见且至少44px，关闭侧栏。
2. 顶部搜索打开并实际聚焦，输入唯一合成 item 名称，出现其准确 ID 结果。实际 Android IME frame 可见、WebView 高度缩小；键盘状态保留自然截图。用一次 Android BACK4 关闭 IME，确认 URL 不变，再由顶部按钮关闭搜索。
3. 顶部加号进入 Intake 后返回，没有选文件、导入或恢复。All 的 Add asset / 新增资产只打开 BaseUI 类型对话框后取消，没有 Continue/Save。
4. 依次进入 Projects、Items、Subscriptions、Ledger；每步 pathname 与预期一致，资产一级导航恰有一个 aria-current，未选项没有同色背景或选中阴影。WebView history Back 与一次完整 document reload 后仍唯一高亮。
5. 再打开侧栏，实际点击 Assets 返回 All；底栏五项在实际视口内。两语均包含这一步，没有跳过原 N27 的失败位置。

每语正式 smoke 有14个已确认的 ADB 合成触控，共28个；安全归原另有3个，合计31个。每次触控均重新采集实际目标 App 的窗口/视图层级、WebView 物理 bounds、status/navigation/IME frame，再校验完整44px框、九个不同内点、画布视口与系统矩形不相交，中心点只发一次并等待真实 ADB 子进程退出。它们是模拟器物理坐标输入，不是人手触摸。

四次侧栏打开合计核16个主入口，全部为44px并完整可见。圆角控件使用1/4、1/2、3/4的九个内点，未降低44px整框要求；实际系统区域相交规则仍严格。底栏可见性用 visualViewport 与最多0.5 CSS像素的浮点边界，避免把 innerHeight 的整数取整误认为遮挡，不能用该容差掩盖真实系统矩形相交。
