## 最小修复

复用 `scripts/phase0/generate-legal-artifacts.mjs` 生成根 `SBOM.spdx.json`、`NOTICE.md`、`docs/02-依赖版本与许可证快照.md`，固定实际安装版本与原LICENSE字节。机器输出723项、直接运行57、开发21、包根目录缺许可证正文39。SBOM语义差异只有新增core-js及pdfjs已有记录的sourceInfo更新；无删除，JSON较多行变化来自后续SPDX编号顺移。历史34版本、32份材料的原索引、README均未改；生成摘要准确区分该历史索引与当前缺正文集合。

生成器首跑在真实本树遇ENOENT：pnpm列出pdfjs补丁虚拟目录及core-js虚拟目录，但这两个direct dependency的实际构建链接指向隔离安装，两条虚拟路径不存在；其余721元数据路径存在。获准增加窄回退：仅原路径ENOENT且名称属于根direct依赖，才读取root `node_modules/<name>/package.json`；继续严格匹配原pnpm项name/version。非ENOENT、transitive缺失、无效名称或版本不符仍失败。输出稳定的root相对链接路径，不将toolchain绝对路径写入清单。

PDF实际安装目录只读执行当前仓库patch的 `git apply --reverse --check` 成功，未执行应用/撤销；完整当前patch确已生效，目录名字hash不能代替内容检查。没有安装、重装或改共享node_modules、锁、PDFpatch、apps/packages。
