# F23 原生运行时与手机界面接线

## 实现

手机入口已在确认两个原生插件可用后注册 PlatformMcpAdapter。每次打开连接固定当前 Native dataset epoch、同一个 localRepository 与既有McpAssetStore适配器；资料集切换使guard立即失效。没有第二套普通资产状态、Node本地authority替代或密码库读取。

React运行时复用现有scope/字段/时长卡片和原write批准Dialog：准备ticket→系统导出精确回执→用户显式激活→电脑提案核对码→手机明确批准→已授权。只打开监听不显示已授权；prepared后台可暂存但不监听，active离开前台停止。原Web请求kind、准备/下载/配对导入和四工具行为保持。

每次异步使用generation，退出/过期/变化关闭本次资源，旧回调不能复开。停止或耐久撤销未确认保留同session对象，明确重试；不丢ACK就伪报成功。当前授权的pending不确定写可在手动和后台关闭时显示；不给模型重放写操作。审批失败只固定脱敏用户文案，模态内有错误及明确Stop出口，原前后值/版本判断保留。历史backend `e8160d91`本片未接入冷启界面，相关验收仍待。

## 实际发现与修复

另一代理在独立冻结真实Provider/Dialog、合成adapter的B中发现：取消prepare后，迟到session.close失败被旧generation吞掉并丢引用；旧expiry停止后等待audit，迟回的错误污染新prepared；批准失败只在modal外有提示。

已分别以cleanupRef保留确切迟到对象/阻止未经确认新准备、旧stop后续generation guard、按previewId绑定的模态内alert及Stop出口修复。错误copy改为操作未确认/访问状态未确认，不拿本地authority错误建议检查launcher。原红/过渡绿保留在`test-results/native-mcp-runtime-review/`。
