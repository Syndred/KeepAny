# F23 iOS 配对导出与监听激活分流

接续主体提交 `37bc03d3` 及[原生TLS实现回执](F23-iOS原生TLS传输实现回执-20261028.md)。主控发现正式系统导出/分享可能触发App暂停：先启动listener再导出，会被安全生命周期停止，旧配对文件随下次pin变化失效。本片按新的双阶段合同，只修改自有 `KeepAnyMcpTransport` 包及新增本回执；TS/UI/注册、Android与系统权限仍由各owner负责，没有操作5580或任何私密控制器。

## 新接口与状态

- `prepare({address})`：保持实际UP接口枚举、canonical RFC1918/exact127限制；只用POSIX `socket→bind(port0)→getsockname→close` 获得端口，**不调用listen**。生成一次内存ECDSA identity、UUID及四元组。prepared本身不接收MCP请求、不创建grant，不声称已经开始等待连接。
- `activate({instanceId})`：前台才能调用，重验实际本机IP并绑定原端口；成功返回与prepare逐字相同的 `instanceId/endpoint/certificatePem/spkiSha256`，不返回void。原端口被占或接口消失便清prepared、发mcpStopped并明确失败，用户须重新生成/导出；不会偷偷换端口、URL或pin。
- `start({address})`保留为同一串行lifecycle内prepare+activate快捷API，供既有C探针调用，未把它当正式导出后的UI流程。active或尚有效prepared存在时均拒绝覆盖式新start/prepare；错误instance不影响有效状态。
- prepared仅内存，固定120秒TTL，单调时钟；真实DispatchSource timer主动清理，同时每次prepare/activate/stop/pause检查到期。暂停不会延长TTL。过期清identity引用并发对应mcpStopped；不能在导出旧文件后无限等待才激活。
- resignActive/background只停止active（关闭listener/连接，发mcpStopped），可保留未到期prepared；恢复前台只恢复gate，不自动激活。terminate/destroy/reset/显式stop清prepared和active。start/reset/prepare/activate及计时器清理同一lifecycle队列，旧timer按UUID检查，不会删掉新prepared。

原4slot、TLS1.2+、30秒总期限、HTTP成熟解析/预算、Start/Write缓存→End提交、错误清缓冲与不可自动重放均沿用。准备阶段没有监听器，30秒请求期限从真正接受TCP连接才开始；120秒prepared生命周期是不同期限，不互相替代。

## 新检查与待Apple执行

保留原9项SwiftPM源码合同，只把测试helper改为同test target可复用，新增5项：

1. prepare端口实际拒连，系统pause后仍拒连；只有显式activate成功且四元组全部相同，真实严格TLS配对POST可用；随后active pause实际停端口，不自动重新activate。
2. prepare后由独立socket占用其原端口，activate明确失败/清预备态；新prepare换UUID/pin，旧stop不影响新prepared，再正式activate可用。
3. 注入内部单调时钟，在119秒pause后推进至exact120秒，activate拒绝且新prepare可用。此项是**C层clock-injection边界**，不是实际设备等待两分钟；生产bridge不暴露时钟/TTL选项，仍真实120秒timer。
4. reset与显式stop清prepared并发对应stopped，旧实例不可激活/重放，新prepared仍可用。
5. 真实释放core对象后prepared清理、stopped可见，原预备端口仍未监听。
