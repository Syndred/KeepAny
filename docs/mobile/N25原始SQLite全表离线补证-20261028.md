## WAL 与采集边界

10份旧 `-wal` 只有105B，内容是旧 cat/run-as 的“文件不存在”诊断，**并非有效 WAL**；本次保原字节、标明分类，没有删掉或补造 WAL。其余13份具合法 WAL header，实际查询由 SQLite 处理已提交帧。

再将23份 main 文件另复制为**不带 sidecar**的独立私有对照，六份读出与带 WAL 结果不同：两份 image-success、两份 vault-before 的 blobs/records，以及两份 vault-success 的 passwordVault。这证明这些真实 WAL 不能忽略，仅查 main 会漏已提交变更。不是把无 WAL 的旧状态当最终状态。

现存 host 文件在离线期间稳定、内部可读，且新全表 witness 与旧业务摘要相符；**不能回溯证明旧三文件顺序复制在设备采集瞬间原子一致**。旧工具未提供该门槛，本次不追补、不称物理 DB 文件字节相等，也不新增 Native/真实低空间通过。没有为了补证重新触发故障。
