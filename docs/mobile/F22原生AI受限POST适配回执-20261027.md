# F22 原生 AI 受限 POST 适配回执

本片对应 Native12 已确认的 AI 红，提供软件实现与定向验证；未运行设备、服务、私密控制器或付费 provider。正式 Native13 尚待主控冻结和原设备 owner 复验，不能把下列 C/JVM 结果核销为 N。

## 原红与实现

[Android 候选定向复验](Android候选定向复验-20261027.md) checkpoint `a0d9b590` 已记录：正式设置 Test connection、普通范围只选 P1 后明确发送，均为真实 HTTPS OPTIONS204/no-CORS、POST0，无回答；CORS=true、TLS=false。先前仅风险判断已经由该设备回执更新为真实红。

`packages/ai/src/index.ts` 新增 `registerAiFetchFactory`，每次生成只把已校验 connection 的冻结快照与期限交给平台 factory。手机启动注册 `createNativeAiFetchFactory`；不修改全局 fetch，Web 默认仍用现有 fetch，未注册或原生不可用时不假装成功。SDK 仍处理全部11个 provider 协议与响应，`maxRetries:0`、无工具、无遥测及上层审核/schema 保留。

新增独立 `aiOpen/aiWrite/aiRequest/aiRead/aiCancel`：

- Android 使用现有 OkHttp 默认 TLS/主机名验证；iOS 复用受限 URLSession delegate。目标只由当前明确 connection/provider/model 构造，方法固定 POST；不跟随重定向，不借登录 Cookie、系统凭据或备份对象权限。
- 正文上限16MiB UTF-8、响应8MiB、桥块≤256KiB、单活跃。现有图片14,000,000个 base64字符上限未缩小。标准 Request继承 body/headers/signal，init 显式覆盖优先，包括 signal:null；字节正文先做快照。
- 仅允许现有 provider 所需认证、版本、beta、JSON及 SDK metadata headers，单值/总量受限，拒绝 Cookie/Host/Origin/代理头和 CR/LF。协议响应保持真实 HTTP 状态和原始字节，401等交给 SDK，坏 JSON/业务结构由原 SDK及上层 schema 拒绝。
- 用户期限1–120秒；原生同时有独立期限计时，真正取消 Call/URLSession task，并过期释放未提交正文及已收响应。AI 取消记录独立于 session/backup，错ID不能污染另一个通道。取消、未知异常和超时使用固定脱敏错误；SDK不记录原诊断。
- AI 输入/输出只在内存中暂存，不调用 backup 文件暂存、SQLite、Preferences或日志。既有 `loggingBehavior:'none'` 保留。释放引用并尽力清理可变字节缓冲；不承诺运行时所有内存副本的物理擦除。不会读取 KDBX/主密码/全库；独立密码 AI 仍只接受上层本次明确授权输入。

## HTTP loopback 范围

HTTPS 优先。按既有 `readUrl` 合同，所有 provider 都保留用户明确配置的 HTTP exact-loopback：hostname 只能为 `localhost`、`127.0.0.1`、`[::1]`，同时仍按各provider固定POST路径；LAN HTTP、近似域名、其他loopback地址、凭据/查询/片段均拒绝。主控最终源码review指出初稿误限Ollama后，本片三层均纠正，并补compatible及Anthropic实际SDK正例、JVM三地址路径正例。不能把手机localhost偷换为开发机地址。

Android Manifest 指向新 network security config：base cleartext=false，仅三个精确域例外、无子域、无新增 CA。iOS 只增加相同三个 `NSExceptionDomains`，无 arbitrary loads、全局 local networking 或 TLS降级。依据：[Android 域配置](https://developer.android.com/privacy-and-security/security-config)、[Apple 个别IP例外](https://developer.apple.com/documentation/BundleResources/Information-Property-List/NSAppTransportSecurity/NSExceptionDomains)。这是已写策略，实际 OS/本机 Ollama 服务连接仍待验，不宣称已有手机 Ollama 服务。

## 待验与交接

Windows 无Swift编译器，本轮 Swift 只有源码自审，待新Apple CI编译及iOS设备。Android13需原设备 owner 对相同 no-CORS HTTPS地址实做 Test connection/P1明确发送、取消/超时、失败后本地功能和秘密不落普通存储/日志；不能仅按该软件回执核销。HTTP loopback实际OS连接、各真实provider线上、iOS LAN权限/后台生命周期也未外推。
