# F23 桌面TLS与私有文件基础回执

日期：2026-10-28。本片是电脑CLI后续接手机前台HTTPS MCP所需的Node基础，**不是手机监听/配对/CLI接线已完成，也不是Android/iOS/物理设备实装验收**。本批没有连接5580/9436/9438、运行Gradle、读取原主密码/私密fixture、操作CA/hosts/现有HTTPS服务。设备继续归原生专项owner。

## 已实现API与调用边界

```ts
createMobileTlsFetch({
  endpoint: string,       // canonical https://private-IPv4[:port]/mcp or exact 127.0.0.1
  certificatePem: string, // exactly one explicitly paired self-signed certificate
  spkiSha256: string,     // 64 hex characters, leaf SubjectPublicKeyInfo SHA-256
}): { fetch: typeof fetch; close(): void }

readMobileSecretFile(absolutePath: string): Promise<{ text: string }>
```

- TLS工厂只为本次连接建立独立`https.Agent`，正常`rejectUnauthorized:true`，仅此agent的CA；先执行Node正常hostname/IP SAN校验，再校验实际leaf SPKI。禁TLS session缓存，close销毁本agent和所有在途socket；没有全局CA、全局fetch补丁、`rejectUnauthorized:false`或仅pin替代SAN检查。
- 仅接受RFC1918 IPv4或精确127.0.0.1，HTTPS canonical endpoint为`/mcp`；只允许同一origin的POST `/pair`与`/mcp`，拒查询/hash、外源、URL userinfo、Cookie、显式credentials include、Host不匹配、跳转及危险framing headers。Node IO没有ambient Cookie jar，不会把Request默认same-origin模式变成浏览器Cookie行为；Bearer等明确请求头、Request自身signal/body正常继承。
- 请求UTF-8上限1,000,000B、响应UTF-8上限8MiB，既检查声明也检查真实流。最多4个在途；30秒总截止包括读请求体和响应；abort/close真实销毁TLS连接，无自动重放。拒压缩响应并请求identity，避免解压后绕过预算。错误只用固定code，不保留原错误cause，不自行输出URL、认证或body到stderr。
- 保留有限响应body/content-type，Node HTTP parser处理真实chunked framing；官方SDK的JSON和有限SSE两种握手/工具请求已实测。**不提供GET长时SSE/订阅、后台保活或自动重连**；最终CLI仍须保留MCP取消通知/operationId语义，不能把断流当撤销已提交写入。HTTP响应内容交给SDK，未来CLI外层也必须只记固定错误，不能直接打印SDK完整诊断。
- 私有文件reader不解析schema、不写文件、不chmod、不消费/删除文件，只返回UTF-8文本。root负责新格式/nonce/过期/手机明确批准和一次性secret核销。手机每次start的短期内存证书轮换及重新配对属于原生owner实现与实装条件，本工厂只持这次显式输入，不承诺cold自动连接。

## 文件读取与复用

没有复用权限较宽的旧`request.ts`。只为已审计`node-private-files`添加typed `readMobileSecret`包装和Windows同名新op；旧readRequest/readState不改语义。

- Windows：原helper严格同用户owner-only DACL（保留可信SYSTEM）、NTFS FileID、hardlink/reparse/ADS拒绝及逐级祖先目录保留句柄继续复用。新op在同一个只读句柄上读≤64KiB、严格UTF-8并返回FileID，share仅READ，读取期间不允许WRITE/DELETE；前后Private校验。reader持有父链lease，并比较读取前inspect、实际读取句柄identity、读取后inspect，拒真实替换与ABA读错对象。
- POSIX：绝对路径；逐级目录非symlink，父目录同用户0700；同一个O_NOFOLLOW描述符读取普通文件，同用户、nlink1、0600；先限size，实际最多读65537B即拒超限，前后dev/ino/size/mtime/ctime/权限以及目录链identity校验。没有将POSIX描述符说成Windows式强制禁止rename；只能对实际读句柄与检查时点的替换/变化失败关闭，不能承诺监测同用户恶意修改后完全恢复元数据的所有瞬时事件。
- 本机为Windows，因此新POSIX权限分支测试明确skipped，未作为已运行POSIX证据。没有替用户修权限；不满足条件一律固定`mobile-mcp-file-unsafe`，不回显路径或秘密。
