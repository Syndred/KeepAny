# KeepAny 试用指南

[English](#english) · [返回 README](../README.md)

先用一个虚构项目走完“项目 → 账号 → 订阅 → 待办 → 备份恢复”。本地试用无需账号、官方服务或模型 API Key。

## 1. 启动本地版

请从 [GitHub Releases](https://github.com/Syndred/KeepAny/releases) 下载带 `Pre-release` 标记的 `KeepAny-…-portable.zip`。阅读该版本说明和校验值，不要下载源码 ZIP 代替便携包。

先安装 [Node.js 22 或更新版本](https://nodejs.org/)。便携包不要求 Git、pnpm，也不需要安装项目依赖。解压到固定文件夹，保留其中的 `web` 与启动文件：

| 系统 | 启动 | 停止 |
|---|---|---|
| macOS | 双击 `start.command` | 双击 `stop.command` |
| Linux | 包目录中执行 `./start.sh` | 执行 `./stop.sh` |
| Windows | 双击 `start.bat` | 双击 `stop.bat` |

打开 **http://127.0.0.1:4180/**，使用常规浏览器配置。启动器只监听本机，不上传资料，不自动加入示例；关闭标签页不会停止服务。

同一浏览器配置、同一地址会继续显示原本的资料。若这个地址以前用过 KeepAny，想要空白试用，请自行创建独立浏览器配置。日常资料不要仅放在隐私模式中，其存储可能在关闭后被清除。

若提示缺少 Node，请安装后重新打开终端或启动文件。若提示端口占用，先确认是否有 KeepAny 正在运行；不要随意结束不认识的进程。需要换端口进行开发测试时，该端口会有自己的独立资料。

## 旧版本升级

1. 在旧版创建并**实际下载**加密 `.ka1`，在干净浏览器配置中核对恢复；保留备份密码。如有密码库，也保留其主密码。
2. 保存或取消正在编辑的内容，关闭旧 KeepAny 标签及 PWA 窗口，使用原包停止脚本或启动终端停止原服务。
3. 解压新版并启动。继续使用原浏览器配置和 **http://127.0.0.1:4180/**，不要为了更新而清除站点数据。若提示端口占用，先检查旧服务是否仍运行；不要让两份包同时争用端口。
4. 若看到「新版已准备好」，保存当前修改后点击「更新应用」。重新打开后检查资料与对应版本说明。

旧 PWA 可能仍缓存前一版本；所有历史版本的升级路径尚未验证。若界面仍旧或资料异常，先保留备份，确认启动的是新包与原地址，再反馈版本和复现步骤，不以清库作为默认处理。

## 2. 看懂资料之间的关系

空白「概览」中点「用示例资料开始」，进入设置后再点「加入示例资料」，即可查看虚构的项目、邮箱、托管订阅与设备；也可手动进入「设置 → 其他选项 → 加入示例资料」。若想看英文示例，先切换到 English，再加入示例；切换语言只改变界面，不翻译已有资料。

用你自己的虚构项目再走一遍：

1. 在「项目」创建“我的测试网站”，网址用 `https://example.com`。
2. 在「账号」创建“测试邮箱”，暂不录入真实凭据。打开项目详情，使用「添加关联」将它连到项目，写明用途，例如“联系邮箱”。
3. 在「订阅」创建“测试托管”，填写金额、币种、周期和续费日期，关联到项目及相关账号。
4. 在「待办」建立“检查域名续费”，关联测试项目并选日期。打开账号详情查看「变更影响」，按已记录的关联生成检查待办。
5. 刷新页面，用顶栏搜索找到项目，再打开关系图查看关联。

你应能看到资料保留、关联可追溯、续费日期与待办可找到。完成检查只记入本机历史，不会修改第三方服务，也不会真的扣款。

## 3. 下载并验证备份

1. 打开「收录与备份」，设置至少 12 位的备份密码。
2. 点「创建备份」，等待生成后，再点「保存备份文件」，确认下载得到 `.ka1`。
3. 保存密码和文件。在另一份干净的浏览器配置中打开同一应用地址。
4. 在「收录与备份」选择恢复文件，输入备份密码，核对预览后确认恢复。
5. 刷新并核对项目、账号、订阅、关系、待办及图片。确认恢复可用后保留这份备份。

备份恢复会合并资料；同 ID 内容冲突或同步来源不同可能被拒绝，所以首次验证使用干净配置。已有资料无需为了测试而清空。同步不是备份。

若有本机密码库，`.ka1` 包含库的密文；恢复后仍须**原密码库主密码**解锁。备份密码与主密码是两件事，均无法由后台找回。独立 `.kdbx` 还可在密码库页面导出，详见 [密码库说明](密码库使用说明.md)。

## 4. 可选密码库与 AI

密码库是独立加密 KDBX，不是普通账号字段。可先用虚构条目试试创建、锁定、解锁及导出；不要把真实密码粘贴到普通项目描述或收录表单中。

普通本地操作不需要 AI。若配置模型，请先看服务提供商、地址和使用范围。独立密码库的全文 AI 识别会发送本次清单全文，可能包含密码和备注；已有全库与主密码不发送。只想本机识别时用本机导入路径。任何识别结果都先核对再保存，不把模型输出当成真实账户信息。

## 常见疑问

| 现象 | 先检查 |
|---|---|
| 打开后资料不见了 | 浏览器配置与地址是否相同；`localhost`、`127.0.0.1` 和不同端口的资料彼此独立 |
| 更换包以后是否需要迁移 | 同浏览器同地址使用原存储；更新前先下载并验证备份，按该版本说明更新 |
| 断网能否使用 | 便携服务器在本机运行，本地管理不依赖官方云；AI与其他外部连接需要能访问所选服务 |
| 能否在手机／别的电脑直接打开 | 便携服务器只监听本机，不提供局域网访问；跨设备需备份迁移，官方托管尚未开放 |
| 找不到自动填充、邮件或后台通知 | 当前未提供密码自动填充、邮件提醒、关页推送或跨设备密码同步 |
| 遇到错误 | 记下版本、系统、浏览器和步骤，保留备份，用虚构资料在 [Issues](https://github.com/Syndred/KeepAny/issues) 反馈；安全问题按 [SECURITY.md](../SECURITY.md) |

这是早期测试版。Linux 与 Windows 启动器随包提供，其实际验证范围以发布说明为准；真实手机、所有浏览器、低存储和突发断电等条件未全部验证。

## English

[Back to README](../README.en.md)

Try a fictional project through **project → account → subscription → task → backup and restore**. The local app does not need an account, official service, or model API key.

### Start the local app

Download the `KeepAny-…-portable.zip` marked `Pre-release` from [GitHub Releases](https://github.com/Syndred/KeepAny/releases). Check its release notes and checksums. The source ZIP is not the portable app.

Install [Node.js 22 or newer](https://nodejs.org/). You do not need Git, pnpm, or project dependencies. Extract the package to a folder you can keep. Leave the `web` folder and launch files together:

| System | Start | Stop |
|---|---|---|
| macOS | Double-click `start.command` | Double-click `stop.command` |
| Linux | Run `./start.sh` in the package folder | Run `./stop.sh` |
| Windows | Double-click `start.bat` | Double-click `stop.bat` |

Open **http://127.0.0.1:4180/** in a normal browser profile. The launcher listens only on your computer and does not upload or seed records. Closing the tab does not stop the server.

The same browser profile and address show the same records. If you used KeepAny here before and want a clean trial, create a separate browser profile yourself. Private browsing is temporary and should not be your only everyday data store.

If Node is missing, install it and reopen the terminal or launcher. If the port is occupied, check whether KeepAny is already running; do not end an unfamiliar process. Different ports have separate browser stores.

### Updating an existing installation

1. Create and **download** an encrypted `.ka1` from the old version. Verify restore in a clean profile; keep the file and backup password. Keep the vault master password too, if you have a vault.
2. Save or cancel current edits. Close old KeepAny tabs and PWA windows, then stop the old server with its own stop script or startup terminal.
3. Extract and start the new package. Keep the same browser profile and **http://127.0.0.1:4180/**. Do not clear site data to update. If the port is occupied, check whether the old server is still running.
4. If **An update is ready** appears, save your edits before selecting **Update app**. Reopen and check records against the release notes.

An old PWA may still cache an earlier version; not every historical upgrade path has been verified. If the interface stays old or data looks wrong, keep the backup, check the package and address, and report the versions and steps. Do not clear your store as a default fix.

### Connect a project's records

Choose English in **Settings** first. In an empty **Overview**, select **Start with sample records**, then **Add sample records** in Settings; **Settings → More options → Add sample records** is the alternative. Changing language changes interface copy, not your existing records.

1. Create “My test website” in **Projects**, using `https://example.com`.
2. Create “Test email” in **Accounts**, without real credentials. Open the project and choose **Add connection** to connect the account. Give it a purpose such as “Contact email”.
3. Create “Test hosting” in **Subscriptions**. Set an amount, currency, cycle, and renewal date, then link the project and account.
4. Create “Check domain renewal” in **Tasks**, linked to the project. Open the account's **Change impact** section and create a checklist from its recorded connections.
5. Refresh, find the project through the top search, and open its connection graph.

Records should persist and you should be able to find the connections, renewal date, and tasks. A completed check is a local record; it does not update other services or charge a payment method.

### Download and verify a backup

1. Open **Import & backup** and enter a backup password of at least 12 characters.
2. Select **Create backup**, then **Save backup file**. Confirm that a `.ka1` file was downloaded.
3. Keep the file and password. Open the app at the same address in a new, clean browser profile.
4. Select the file for restore, enter the password, review the preview, and confirm.
5. Refresh and check projects, accounts, subscriptions, connections, tasks, and images. Retain the verified backup.

Restore merges records. Conflicting IDs or a different sync identity can stop it, so use a clean profile for your first restore test. You do not need to clear existing records. Sync is not a backup.

If you have a local password vault, `.ka1` includes its encrypted contents; the **original vault master password** is still required. The backup password and master password are separate and cannot be recovered by a server. You can also export a separate `.kdbx` from the vault page.

### Optional vault and AI

The vault uses a separate encrypted KDBX store. Try create, lock, unlock, and export with fictional entries first. Do not put real passwords in ordinary project descriptions or intake forms.

Local management does not need AI. If you connect a model, review its provider, destination, and data scope. The vault's full-text AI import sends the current list, which may contain passwords and notes, but not your existing vault or master password. Choose local import to keep recognition on your computer. Review all candidates before saving.

### Common questions

| What happened? | Check this |
|---|---|
| My records are missing | Use the same profile and address. `localhost`, `127.0.0.1`, and different ports each have their own store |
| I downloaded a newer package | The same profile and address retain the existing store. Back up and verify recovery before updating; follow that release's notes |
| I am offline | Local management does not need official cloud services. AI and external connections need access to the service you selected |
| I want another device | The server is local only, without LAN access. Transfer through backup and restore; official hosting is not available yet |
| I need autofill or email reminders | Password autofill, email reminders, closed-page push, and cross-device password sync are not provided |
| I found a problem | Report the version, OS, browser, and steps with fictional data in [Issues](https://github.com/Syndred/KeepAny/issues). Use [SECURITY.md](../SECURITY.md) for security reports |

This is an early preview. Linux and Windows launchers are included, but their verified environments are listed in the release notes. Physical phones, every browser, low-storage conditions, and sudden shutdowns have not all been verified.
