## 已完成的本地实现

- 资产、关系、分类、待办及历史统一写入 RxDB + Dexie；TanStack Query 不充当第二资产源。CSV 批次有持久日志，失败可回滚；墓碑/恢复保留记录。图片确认后写入，损坏文件阻止确认，离开引用时清理孤儿文件；备份包含被引用图片。
- 备份先本机导出归档，再用密码加密；恢复先预检后确认。`tests/e2e/local-core.spec.ts` 在 Chromium 中按正式 UI 创建项目、账号、订阅、连接和待办，点击“保存备份文件”触发浏览器下载，取实际 `.ka1` 文件，打开全新浏览器上下文恢复，刷新后逐项读回。此结果比此前开发接口取 blob 的证据更强；仍未在 Ego 原生下载管理器或真实移动设备手工取回文件。
- Web 拆为独立路由和按需详情/工作流 chunk。生产构建入口约 386.70 kB（gzip 125.94 kB），原单包约 1,072.91 kB（gzip 341.72 kB）；PWA 总预缓存仍约 1,097 KiB。示例数据改为一个可恢复批次，避免分条写入留下半套示例。
- 服务端使用工作区权限、期望版本、持久操作 ID 和墓碑。拉取合同返回原始 `operationId`，003 SQL 迁移按旧 accepted 操作回填；JSON 状态也兼容回填。v2 信封把客户端可预知的记录版本放入 AEAD 认证上下文，服务端全局 `sequence` 只作游标；拉取按外部变更元数据验证，旧 v1 只有序号恰好匹配实际提交序号才可读取。真实 PostgreSQL 17.11 + Hono HTTP 本机双客户端测试覆盖冲突、重放、墓碑、分页、跨工作区和密文附件读回。独立 Compose 的启动、健康检查、push/pull、401 与重启读回已过；2026-09-28 Docker 恢复后另起临时 PG，在随机 schema 实际重跑 003、004、005、重复迁移与两连接池共享 proof 判重/撤销，均通过。临时库结果不等于生产升级。
- Web 设置页提供手动自托管同步：工作区密钥只保留当前页面内存，生成后须确认已另存；本机 RxDB 是单一资产源，Dexie 按服务端、固定自托管账户与工作区持久保存待推送操作、确认基线、游标和拉取恢复日志。浏览器丢失应答后重开会重试同一操作 ID，令牌轮换不清空待推送；误填另一密钥/epoch 会在网络请求前拒绝。UI 显示仅本机、待同步、同步中、本次完成、冲突、失败六种状态，并允许逐条冲突选择。现有图片引用会整体阻断该轮同步并明确提示，因为 Web 尚未实现密文附件传输；不会静默漏传。只在用户按下同步时连接自有服务，未接官方 bound 同步。
- 绑定消费端固定 issuer/JWKS、RS256、`aud=keepany-binding`、签名、`kid`、精确 `sub`/`bindingId`、实例摘要及 60 秒时限。设备 P-256 私钥不可导出并保存在本机 IndexedDB，刷新使用 DPoP 证明和持久随机请求 ID 的短时恢复；本地测试覆盖验签、切换确认、原子持久化与重试。设置页仅在配置固定 issuer/本机桥时显示只读绑定入口；桥只转发四个绑定 POST 与 JWKS GET，保留商业 issuer 用于票据与 DPoP 验证。跨进程合成 Plus 账号的账号页面批准、状态 `active`、只读令牌续期、账号页面撤销、本地状态 `revoked` 与清凭据均已在隔离 Chromium 跑通。同步服务 `bound` 模式另验 `aud=keepany-sync-bound`、设备指纹、请求证明和读写范围；`self-host` 静态 Bearer 仅在显式模式下使用。
- MCP 独立 Node 进程与浏览器之间有受作用域限制的 loopback 桥原型；配对码/会话/请求 nonce、Origin/Host、字段投影、隐藏字段保留和撤销重查见 `docs/adr/0002-mcp-bridge.md`。隔离 Chromium 已实际跨源验证预检、许可来源配对、非许可来源拒绝和受限字段读回。它尚未接到正式 Web UI 与可信启动器，不能被描述为用户现可用。

## 阻塞与边界

- KeepAnyAdm 本机合成账号联调时工作树仍有未提交改动，需在固定已提交版本和真实受控账号上重跑。浏览器受限回环桥没有可信安装/启动器、端口发现或生产同源安全配置；本机续期凭据仍是敏感存储。商业挑战票据不能当同步 Bearer，已签发访问令牌也没有被 Web 资产同步运行器消费。
- `bound` 模式已改为 PostgreSQL 绑定状态短租约与共享唯一 proof 判重；无状态、过期、撤销或数据库故障均拒绝。冻结的商业 `binding-http-v1.0.0` `/state` 需要设备私钥和 refresh token，尚无资源服务端可信状态 feed，也没有写入器；当前状态表为空时全部拒绝，不能声称商业实时撤销或启用官方云同步。可信写入器须保留撤销墓碑，推进 epoch 和 token_valid_after，不得删除后重建；005 数据库触发器禁止回退、同 epoch 更换身份/范围和删除墓碑。未提供生产 issuer、JWKS、R2、PostgreSQL、HTTPS/账号凭据，因此不部署官方云服务。
- v2 AEAD 的记录版本和外部元数据核对已修正，跨记录全局序号不再参与预封装 AAD。旧快照若只有全局序号、没有可信记录版本，同记录 v2 变更会拒绝，须可信重建基线。Web 目前是用户手动输入工作区密钥和自托管 Bearer 的单账户流程；无设备密钥配对、后台自动同步、图片附件传输或真实物理双设备验收，不能把本机两个 RxDB 客户端测试当成正式云同步完成。
- 本机双客户端不等于两台物理设备；本机 S3 HTTP mock 不等于真实 R2/S3。服务端无法证明上传内容已加密，哈希不代替客户端 AEAD 认证。MCP 桥已做隔离浏览器 CORS 测试，仍需可信启动器、正式 Web UI 与真实用户资料进程联调。
- 本轮 Ego 原生 UI 因 Mac 锁屏不可用，隔离 Chromium 是浏览器验收来源；没有绕过浏览器安全界面。真实设备、用户调研、生产数据、完整许可证兼容性及法律审查均未完成。

## 下步

1. 在不修改冻结商业 HTTP 合同的前提下设计并接入可信状态 feed/写入器，短租约更新须保留撤销墓碑、推进 epoch 与 token_valid_after；在固定商业源码版本与受控真实账号上复跑。为回环桥提供可信启动器与端口发现。
