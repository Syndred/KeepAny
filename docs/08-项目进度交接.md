## 已完成的本地实现

- 资产、关系、分类、待办及历史统一写入 RxDB + Dexie；TanStack Query 不充当第二资产源。CSV 批次有持久日志，失败可回滚；墓碑/恢复保留记录。图片确认后写入，损坏文件阻止确认，离开引用时清理孤儿文件；备份包含被引用图片。
- 备份先本机导出归档，再用密码加密；恢复先预检后确认。`tests/e2e/local-core.spec.ts` 在 Chromium 中按正式 UI 创建项目、账号、订阅、连接和待办，点击“保存备份文件”触发浏览器下载，取实际 `.ka1` 文件，打开全新浏览器上下文恢复，刷新后逐项读回。此结果比此前开发接口取 blob 的证据更强；仍未在 Ego 原生下载管理器或真实移动设备手工取回文件。
- Web 拆为独立路由和按需详情/工作流 chunk。生产构建入口约 384.81 kB（gzip 125.31 kB），原单包约 1,072.91 kB（gzip 341.72 kB）；PWA 总预缓存仍约 1,091 KiB。示例数据改为一个可恢复批次，避免分条写入留下半套示例。
- 服务端使用工作区权限、期望版本、持久操作 ID 和墓碑。真实 PostgreSQL 17.11 + Hono HTTP 本机双客户端测试覆盖同版本冲突、成功/失败重放、墓碑不复活、分页、跨工作区拒绝、加密信封与经本机 S3 HTTP mock 的密文附件读回。另构建独立 Compose，启动、健康检查、push/pull、401 和容器重启读回已过；测试机器 Docker daemon 后续无响应，最终资源清理微调没有再次实库复跑。
- 绑定消费端固定 issuer/JWKS、RS256、`aud=keepany-binding`、签名、`kid`、精确 `sub`/`bindingId`、实例摘要及 60 秒时限。设备 P-256 私钥不可导出并保存在本机 IndexedDB，刷新使用 DPoP 证明和同一请求 ID 的短时恢复；本地测试覆盖验签、切换确认、原子持久化与重试。同步服务 `bound` 模式另验 `aud=keepany-sync-bound`、设备指纹、请求证明和读写范围；`self-host` 静态 Bearer 仅在显式模式下使用。
- MCP 独立 Node 进程与浏览器之间有受作用域限制的 loopback 桥原型；配对码/会话/请求 nonce、Origin/Host、字段投影、隐藏字段保留和撤销重查见 `docs/adr/0002-mcp-bridge.md`。它尚未接到正式 Web UI，不能被描述为用户现可用。

## 阻塞与边界

- KeepAnyAdm 正并行修改设备绑定：`/bindings/device` 已要求公开 P-256 JWK，`/refresh` 和 `/state` 使用 DPoP；这部分在读取时仍是商业仓库未提交工作树。核心端只有本地签名 fixture，没有真实商业用户批准、可信服务端转发或云权益读回。商业挑战票据不能当同步 Bearer；续期令牌本地敏感存储仍需安全审查。
- `bound` 模式使用运营方预置映射，缺商业 `/state` 实时核验、动态撤销传播和多实例共享 DPoP 重放存储；已签发访问令牌在剩余最多 60 秒内可能离线有效。未提供生产 issuer、JWKS、R2、PostgreSQL、HTTPS/账号凭据，因此不部署官方云服务。
- 本机双客户端不等于两台物理设备；本机 S3 HTTP mock 不等于真实 R2/S3。服务端无法证明上传内容已加密，哈希不代替客户端 AEAD 认证。MCP 桥仍需可信启动器、正式 Web UI 和真实浏览器 CORS/进程联调。
- 原生 Ego UI 控制被系统采集错误阻断；没有绕过浏览器安全界面。真实设备、用户调研、生产数据、完整许可证兼容性及法律审查均未完成。
