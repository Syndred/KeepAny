# 10 远端加密备份配置

KeepAny 的“收录与备份”页可手动把本机完整归档加密后上传到用户自备的 S3 兼容对象存储或 WebDAV 文件地址。上传后会从同一位置读回，核对密文长度和 SHA-256，并用本次密码解密及检查归档。恢复时先读取、核对和预览，再由用户确认写入现有本机仓库。本功能不是自动同步，也不会代替本机 `.ka1` 文件备份。

## 准备存储地址

- **S3 兼容存储**：在可信的对象存储管理工具中，为同一个对象键准备 PUT 上传和 GET 读取预签名 HTTPS URL。两个 URL 的域名和路径必须相同；查询参数可以不同。上传需要两条有效链接。稍后恢复只需重新取得该对象的有效 GET URL。当前页面不生成预签名 URL，也不接收长期 S3 密钥；签名不能要求本页面未发送的自定义请求头。
- **WebDAV**：填写指向单个文件的 HTTPS URL，而非目录 URL。该地址应允许 PUT 创建或覆盖文件，并以 GET 200 返回原始文件字节。需要登录时填写用户名和应用密码，页面以 HTTP Basic Authorization 发送；请使用专用的低权限账户/应用密码。
- 两种方式目前都要求 HTTPS 域名；IP、`localhost`、`.local` 和 `.internal` 地址由现有连接器拒绝。最终是否可连通仍取决于浏览器、DNS、证书、存储权限和跨域设置。

浏览器直接向存储地址发请求。存储服务需要允许 KeepAny 当前页面的 Origin 执行 PUT、GET 和预检 OPTIONS；WebDAV 还要允许 `Authorization` 请求头，上传时允许 `Content-Type`。S3 的 CORS 配置通常列出 GET/PUT 和当前页面 Origin，由服务处理浏览器 OPTIONS 预检。应以实际浏览器的预检结果验证服务商配置，不应把命令行上传成功视为浏览器可用。

## 上传、保存与恢复

1. 在“收录与备份”填写至少 12 位的备份密码，选择存储方式并填写地址；WebDAV 可再填登录资料。
2. 点击“加密上传并核对”。只有远端读回的密文哈希、长度、解密和归档检查全部通过，页面才显示上传已核对。
3. 点击“保存校验凭条”。凭条 JSON 只记录格式、版本、密文哈希、长度和创建时间，不含密码、存储 URL 或登录资料。请把凭条与远端对象键/文件地址的记录妥善保留，并单独保管密码。若覆盖同一对象，旧凭条不再匹配新内容。
4. 恢复时重新填写密码与存储地址，粘贴凭条或选择凭条文件；S3 可只填新的 GET URL。点击“读取并预览远端备份”，确认条数后再点击“确认”。恢复沿用本机 `.ka1` 的归档预检、同 ID 冲突阻断和恢复日志；错误密码、损坏密文或凭条不匹配不会进入确认状态。

除用户主动下载凭条外，页面不会把 URL、WebDAV 用户名/应用密码、备份密码或凭条写入本机持久存储；刷新页面后需重新填写。预签名 URL 的查询参数相当于临时凭据，不应贴到工单、日志或公开截图。当前密文大小限制约 100 MiB；大附件和真实服务配额需按具体存储验证。

## 已验证与待验证

隔离 Chromium 通过了 S3 预签名 URL 和 WebDAV 两条正式 Web 流程：本机项目加密上传、HTTP 读回、凭条下载、错误密码/篡改拒绝、全新浏览器导入凭条并恢复；英文 1280px、中文 390px 页面已目检。网络由受控 HTTPS 请求拦截模拟，未使用真实 S3/WebDAV 服务或真实双设备。真实服务的 CORS、签名头、证书、配额、长时离线及生产部署仍需独立验收，见 [项目进度交接](08-项目进度交接.md)。
