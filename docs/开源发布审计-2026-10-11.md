## 许可证材料与严格门槛

当前许可证索引实际为 32 个缺包根正文版本：27 项保存精确上游正文，5 项保存精确 MIT 声明及明确标注的规范补充，0 项未知授权／材料未解决。共 30 份材料＝17 份上游正文＋1 份 SPDX MIT 模板＋12 份原始包／源码声明证据。旧文档中 31／26 是过时数量。

普通索引校验通过，只确认已保存材料的 SHA-256、来源字段、包数量和引用一致；发布门槛必须另行执行：

```bash
node scripts/phase0/verify-third-party-license-materials.mjs --release
```

严格模式遇到未知／冲突声明、未解决项、缺失证据或失配哈希即失败；有精确 MIT 声明与完整标注材料的 `declared-with-supplement` 可通过材料核查。还需按实际公开产物保留已有版权与 NOTICE；不能把这条命令当成整体兼容性结论。AGPL 本地核心与独立付费托管的划分不取消实际分发代码的许可义务，也不要求为普通开源项目额外取得律师签字。

五个精确 npm 包都声明 MIT，缺正文不等于没有许可授权。本轮将原 tarball 与 manifest 的 SHA-1／SHA-512 完整性值逐一核对，保存未经修改的 package.json 与 README、精确版本／许可／作者字段；两个 Better Auth 另保存精确源码提交 README。SPDX 官方 MIT 标准模板从固定提交 `31ba1a50e5397e00a304dbadc76531740e89ee48` 保存，类型明确为 `license-standard`，未冒充该包上游 LICENSE，未用相邻版本／默认分支补证。

MIT 模板要求保留原版权与许可通知；原包未提供完整版权通知，现保留原始公开作者元数据和 README 声明，版权方／年份保持未断言，规范文本中的模板占位符保持原样。没有把 `author` 强行当作版权方，也没有编造或删改上游通知。本文不宣称标准模板能替代一个原本存在但被遗漏的版权通知。[SPDX MIT 正文](https://spdx.org/licenses/MIT.html)

## 功能验收执行顺序与未验环境
