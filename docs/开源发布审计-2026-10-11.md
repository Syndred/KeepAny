## 许可证材料与严格门槛

当前许可证索引实际为 32 个缺包根正文版本：27 项保存精确上游正文，5 项保存精确 MIT 声明及明确标注的规范补充，0 项未知授权／材料未解决。共 30 份材料＝17 份上游正文＋1 份 SPDX MIT 模板＋12 份原始包／源码声明证据。旧文档中 31／26 是过时数量。

普通索引校验通过，只确认已保存材料的 SHA-256、来源字段、包数量和引用一致；发布门槛必须另行执行：

```bash
node scripts/phase0/verify-third-party-license-materials.mjs --release
```

严格模式遇到未知／冲突声明、未解决项、缺失证据或失配哈希即失败；有精确 MIT 声明与完整标注材料的 `declared-with-supplement` 可通过材料核查。还需按实际公开产物保留已有版权与 NOTICE；不能把这条命令当成整体兼容性结论。AGPL 本地核心与独立付费托管的划分不取消实际分发代码的许可义务，也不要求为普通开源项目额外取得律师签字。

五个精确 npm 包都声明 MIT，缺正文不等于没有许可授权。本轮将原 tarball 与 manifest 的 SHA-1／SHA-512 完整性值逐一核对，保存未经修改的 package.json 与 README、精确版本／许可／作者字段；两个 Better Auth 另保存精确源码提交 README。SPDX 官方 MIT 标准模板从固定提交 `31ba1a50e5397e00a304dbadc76531740e89ee48` 保存，类型明确为 `license-standard`，未冒充该包上游 LICENSE，未用相邻版本／默认分支补证。

MIT 模板要求保留原版权与许可通知；原包未提供完整版权通知，现保留原始公开作者元数据和 README 声明，版权方／年份保持未断言，规范文本中的模板占位符保持原样。没有把 `author` 强行当作版权方，也没有编造或删改上游通知。本文不宣称标准模板能替代一个原本存在但被遗漏的版权通知。[SPDX MIT 正文](https://spdx.org/licenses/MIT.html)

## Git 历史与公开数据检查

- 审计开始时共 633 个可达提交；Gitleaks 实际扫描 627 个有可扫描 diff 的提交，181.34 MB。使用官方 `v8.30.1` macOS arm64 发布包，下载文件 SHA-256 与官方 checksums 文件一致，工具只置于临时目录。
- 扫描采用 `gitleaks git --redact --no-banner --log-opts=--all`。298 个告警全部逐类落实：70 个构建 SHA-256／资源清单，219 个编译产物中的 i18n 时长 key，5 个对应源码 i18n key，4 个明确的合成单测凭据。编译项逐条比对原提交字节列附近的已知文案 key，未发现未分类项。

## 功能验收执行顺序与未验环境

`747c184` 基线配置中有 106 个 E2E 文件；固定 `release/web` 回归选择 33 个文件，固定同步另选择 2 个文件。本轮新增公开试用流程后的最终数量及执行结果以主验收报告为准。文件数不是测试项数，也不能简单把两个执行结果相加当作不同功能。

1. `pnpm typecheck`、当前改动 lint、`pnpm test`。配置隔离的 `KEEPANY_TEST_DATABASE_URL` 后，真实 PG 的客户端、迁移、多用户会话、bound-state CAS 等测试才执行；未配置将跳过 6 项，不计通过。数据库必须是可删除随机 schema 的测试实例。
2. `pnpm build`，保存最终构建后执行 `node scripts/verify-local-release.mjs`，确认分发文件逐字节一致；随后以最终产物打包，不能把构建通过等同于打包身份一致。
3. `pnpm exec playwright test --config playwright.release.config.ts`：固定包中英页面／弹窗、字段／间距、资产／关系／财务／分类、本机 AI 替身、密码／智能导入／草稿、实际加密备份／干净恢复、PWA 离线等正式入口。
4. `pnpm exec playwright test --config playwright.sync-release.config.ts`：同一固定包、真实隔离 PG 和本机 HTTP 的两项同步。没有测试数据库会直接拒绝启动，属于保护，不算通过。
5. `pnpm exec playwright test --config playwright.config.ts`：补齐源码全集中的 CRUD、重复提交、关系删除、滚动返回、订阅续费／关联、实物借还／维护、任务提醒、图片、外链导入、远端备份模拟、工作区恢复及其他条件弹窗。此配置会复用已有开发服务；本轮要使用新隔离端口与服务器，避免测到旧进程。
6. `KEEPANY_PWA_UPGRADE=1 pnpm exec playwright test tests/e2e/pwa-upgrade.spec.ts`：固定旧包到当前包，同源旧控制标签、未保存草稿、项目／原图和离线图标。默认跳过；应记录本轮实际执行结果。
7. `KEEPANY_STORAGE_QUOTA_ACCEPTANCE=1 pnpm exec playwright test --config playwright.quota.config.ts`：独立诊断。Chromium 配额 override 成功不等于真正触发 `QuotaExceededError`；没有发生原生错误时，真实低存储恢复仍保持未验。阶段 0 基准可设置独立 `KEEPANY_BENCHMARK_OUTPUT` 后运行，不能覆盖原历史文件。
8. 用陌生用户实际收到的测试包，在隔离浏览器以中英 390px 与桌面视口走“导入项目→关联账号→记录订阅→维护待办→实际下载备份→新来源恢复”，并回读加载的 JS／CSS 与包哈希；停止测试服务并移除合成数据所在隔离上下文。

源码全集默认条件跳过包括：无 PG 的自部署／会话／官方合成同步；无固定 issuer＋本机桥的绑定及移除弹窗；未显式开启的 PWA 升级和配额故障；源码配置未设置生产离线标志时的离线用例。`subscription-cycle` 和 `asset-delete-race` 的部分源码 fault injection 在 preview 模式主动跳过，Windows 下依赖 `ps` 的跨进程用例跳过。CI 当前执行单测、构建、固定包和两项固定同步，没有源码全集、真机、配额或全供应商真实模型测试。

实验功能的本机合成通过，不能扩大为真实用户／服务验收。生产 HTTPS、真实双设备、公开 HTTPS 到 MCP loopback、Windows／Linux MCP 包、真实对象桶与 CORS、真实通知权限／系统通知、全部模型供应商真实 API、设备撤销及密钥轮换、浏览器清理／断电恢复仍需分别记状态；未完成的官方云、购买、后台同步和实验 MCP 入口继续保持未开放。
