## 技术选择目标

| 层 | 采用 | 具体责任与复用方式 |
|---|---|---|
| 工程 | pnpm workspace、TypeScript、Node 24 LTS | 核心monorepo；锁文件与CI固定版本，不追随自动大版本升级 |
| Web | React、Vite、TanStack Router、PWA | 独立资产应用；不依赖商业官网运行 |
| 组件 | shadcn/ui、Tailwind CSS | 复制所需组件并保留许可；统一token，保留已认可视觉，不使用默认后台皮肤 |
| 交互 | Motion、dnd-kit、React Flow | 页面/卡片动效、分类侧栏拖动、账号关系图 |
| 表单 | React Hook Form、Zod | 编辑、导入预览、校验；一份领域schema供应用层复用 |
| 本地数据 | RxDB + 免费Dexie RxStorage | IndexedDB持久化、响应式查询、自定义复制；无云也能读写 |
| 网络状态 | TanStack Query | 额度、服务状态、连接测试；不持有第二份资产主状态 |
| 国际化 | i18next、react-i18next、Intl | zh-CN/en；日期、币种、数量、通知文案统一 |
| 服务端 | Hono + Better Auth + PostgreSQL | 可选自部署多用户身份与隔离；Better Auth 使用其官方 PG 适配器和固定 SQL 迁移，现有同步记录使用参数化 SQL 与事务。Drizzle 尚未接入，不把规划当作已安装依赖。 |
| 托管 | Supabase PostgreSQL + Cloudflare R2 | 前者存结构记录/密文信封，后者存加密附件；对象存储不是同步数据库 |
| 异步任务 | pg-boss + 常驻Node worker | 检查、导入解析、通知；不假定长任务能在Workers持续运行 |
| 文件 | Uppy、Sharp、PapaParse、fflate | 上传队列、非私密服务端图片处理、CSV、流式归档；私密图片先在客户端处理再加密 |
| 收录 | metascraper、Tesseract.js | URL元数据/OCR候选项，用户确认入库；不是通用自动化登录 |
| AI/MCP | AI SDK、官方MCP TypeScript SDK | 模型适配与工具协议；产品权限仍由KeepAny实现 |
| 质量 | Vitest、Playwright | 领域边界测试、真实浏览器端到端与截图 |

RxDB免费Dexie适合首先验证，不承诺其性能等于高级存储插件。附件不以base64塞入资产文档：客户端二进制附件仓库与资产元数据分离。浏览器能力差异在阶段0实测后锁定IndexedDB Blob或OPFS实现；不让付费插件成为自部署必需项。

## 计划代码目录

```text
KeepAny/
  apps/web/             # 用户资产应用
  apps/sync-server/     # 公开的基础同步服务
  apps/worker/          # 用户授权的检查/通知
  packages/domain/     # 资产、关系、周期、待办规则
  packages/local-db/   # RxDB schema、迁移、查询、同步适配
  packages/crypto/     # 已有加密库封装、密钥流程
  packages/connectors/ # ExternalLink、S3、WebDAV等适配
  packages/ui/         # UI组件和token
  packages/i18n/       # zh-CN/en
  packages/contracts/  # 同步和连接器协议
```

以上是最初目录规划，不能据此认定每项已建立。当前 `apps/web`、`apps/sync-server` 与领域、本机仓库、加密、连接器及协议包已有代码，另有绑定桥与 MCP 启动器；`apps/worker`、`packages/ui`、`packages/i18n` 尚未建立，UI 与词典仍放在 `apps/web/src`。核心不运行PHP/Go资产系统作为隐藏依赖；参考/移植业务规则与直接安装库分开记录，见03及12。

## 必须自己实现的部分

统一资产模型、关系语义、变更影响清单、导入去重确认、跨模块体验、同步冲突呈现、授权边界。成熟库提供基础能力，不会自动解决这些产品规则。

## 可部署结构

Web静态资源可部署Cloudflare或用户服务器；Hono API与worker部署Node容器；数据库和S3提供商通过配置替换。首期浏览器PWA，不同时建设桌面壳和原生移动端。云盘先作备份目的地，实时同步走专用协议。

2026-09-30 用户再次明确先完善网页端，本轮不启动桌面迁移。上述服务部署仍是可选架构：当前本地使用不要求 PostgreSQL、商业账号或同步服务，互联网部署与正式云服务不能由本机交付包代替。

## 已替代的早期方案

不再以“必须登录Supabase后才能使用”为核心；不使用ShipAny承载开源资产应用；不把Realtime通知视为离线同步完成；不把加密存储、RLS或HTTPS当成端到端加密。
