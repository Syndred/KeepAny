# 开发与验证

使用Node.js 22+、pnpm 11.10.0。先读README和当前交接，检查git状态并fetch；只在无覆盖风险时快进。

- 普通资料由RxDB本机仓库持有；密码和长期AI密钥只进入独立KDBX。
- 数据schema、存储键、KA1/KDBX及旧兼容标识不得因清理或更名改写。
- UI文案用zh-CN/en键；沿用统一主题，先画草图并确认方案，再实现布局。
- 改动前按需求写覆盖ID、前置资料、入口/步骤、状态、预期与方法；结果绑定实际编译候选。
- 功能、白盒、视觉、主控本人实际操作与独立复核分别记录。未验、失败、版本不匹配均不能称完成。
- 使用隔离虚构资料；修前失败与修后复测证据放仓库外或忽略的test-results，不能删用例、放宽预期或重试凑绿。
- UI至少实际检查中英390/768/1280/1920及反馈尺寸，覆盖展开、错误、焦点、禁用和长内容等适用状态。共享控件换容器须重新验证。

常用命令：

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm build:preview
pnpm verify:preview /absolute/path/to/compiled-candidate.zip
```

浏览器交付检查须显式设置KEEPANY_PREVIEW_DIRECTORY或KEEPANY_PREVIEW_ARCHIVE之一，使用最终编译候选。日常入口为daily.yml；完整发布检查由verify.yml手动运行。历史冻结档案校验已退出当前CI；真实路由恢复、密码历史及当前候选布局等业务回归继续保留。机器检查只能证明列出的身份/结果/几何，不能证明人工视觉已完成。

仓库只保存代码、必要测试、当前指南和许可。截图、日志、ZIP、历史交接及本次验收报告不再提交。用户使用确认后再正式打包发布。
