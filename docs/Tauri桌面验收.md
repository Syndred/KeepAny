# KeepAny Tauri 桌面验收

以拉取后的 `98a03235` 为起点。验证使用打包产物和虚构资料。桌面壳复用现有界面，桌面窗口尺寸、系统文件选择器及两种语言需要实际检查。原有页面布局本轮无改动。

| ID | 前置资料与用户入口 | 预期与验证方式 |
| --- | --- | --- |
| DT01 | 干净 Windows x64，运行 EXE 安装器并从开始菜单打开。关闭后再打开，启动第二次 | 无需 Node.js、浏览器页签或本地服务。应用正常启动，重复启动聚焦当前窗口。核对二进制身份、实际窗口和安装路径 |
| DT02 | 干净 macOS，分别在 Apple Silicon 和 Intel 打开 DMG，拖入 Applications，启动后退出重开 | 应用能在对应硬件独立运行。核对 DMG 架构、系统版本、签名状态、实际窗口和重开结果 |
| DT03 | 独立空库。概览加入示例资料，再在资产页新增虚构记录并进入详情。取消一项编辑，提交一次空名称，保存有效编辑，刷新并重开 | 核对空、单条与多条、长内容、焦点、加载、取消、失败、保存和持久化。打开中英文窗口截图观察系统框架与现有内容 |
| DT04 | 账号入口创建测试 KDBX，录入虚构登录。复制、锁定、重开并解锁 | 剪贴板得到本次选中的虚构值。锁定时隐藏凭据，重开仍要求解锁。白盒核对只保留加密 KDBX |
| DT05 | 有测试资产和 KDBX。分别从备份页及账号入口导出 KA1/KDBX；取消一次、保存一次；用错误密码预览，再在空测试资料中恢复 | 原生保存对话框打开，取消无写入，成功文件读回一致，写入失败能重试。使用系统文件选择器导入，恢复后核对资产和密码库 |
| DT06 | 资产或账号有测试 HTTPS 地址，用鼠标和键盘打开；尝试非 HTTP(S) 地址 | 外部网页由系统默认浏览器打开，桌面窗口及其资料仍在；非法协议无法获得应用权限。白盒核对导航限制、单实例、IPC 权限与 CSP |
| DT07 | Windows 和 macOS 两条构建路径，由同一干净提交运行 | 锁定依赖，生成 EXE 与两种 DMG；校验文件存在、SHA-256 与源码提交，CI 上传为构建产物 |
| DT08 | 已有浏览器资料及可用的 KA1/KDBX 备份。使用虚构旧版备份模拟从浏览器迁移 | 桌面启动时从独立存储打开，导入经预览确认，浏览器来源保留 |

每项需记录实际、证据路径、候选提交与 SHA-256、判定。功能、视觉、白盒、主控用户体验和独立复核分别记录。打包及校验值可由 CI 检查。签名、真机安装、系统文件对话框和人工视觉单列。
