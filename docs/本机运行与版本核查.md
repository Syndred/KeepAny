SSH 身份认证、fetch、push 均已实际通过；积压提交推送后的远端为 `7ca7c99`。GitHub 网页访问和 SSH 仓库权限分别验证；`gh` 未登录不影响当前 SSH 操作。后续提交与最终远端状态见项目进度交接。

## 避免旧包误交付

1. 运行 `pnpm build`。
2. 将 `apps/web/dist` 内容复制进 `release/web`，保留旧版本带哈希的资源，避免未关闭旧页的延迟加载失败。
3. 运行 `node scripts/verify-local-release.mjs --record-retained` 和 `node scripts/verify-local-release.mjs`，确认当前文件逐字节一致且旧资源都有摘要记录。
4. 只启动一个 4180 服务。`./release/start.command` 会检查已记录进程，重复启动不应增加服务；`./release/stop.command` 核对命令后才停止进程。
5. 保存当前编辑后正常刷新保留的 Chrome 页面；检查页面实际加载的 `script[src]`，与 `release/web/index.html` 的入口文件名一致。仅验证文件存在或 HTTP 200 不算页面已更新。
6. 在新版固定包进行隔离资料的实际创建、编辑和备份恢复验收，再记录结果。

本轮启动服务已转入后台，日志为 `release/.local-server.log`，不用常驻可见终端。没有运行中的旧 KeepAny 预览服务；Codex 历史终端面板的关闭受应用控制限制，不能声称已删除其历史面板。
