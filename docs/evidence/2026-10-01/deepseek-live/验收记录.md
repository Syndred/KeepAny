## 真实验收暴露的问题与修复

- `a01467f`：导入提示要求未知文本为 null，与 schema 冲突。复用 Zod 将受限可选文本 null 转空串、标签 null 转空数组；有限 missingFields 白名单过滤为可核对的核心缺项。未知类型、金额精度、币种、日期及来源验证仍严格，首次失败没有写入。
- `5588ae2`：新 DeepSeek 模型默认思考，JSON 请求的1600输出预算全部消耗为 reasoning，content 为空。复用 AI SDK 官方 providerOptions，在已知 DeepSeek 原生模型的 JSON 请求禁用 thinking；普通问答及其他提供方不变，不扩大预算。依据 [DeepSeek 官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。
- `bdb6afb`：查找／提醒可选字段的 null 采用同一有界规范化；空查询不会自动匹配对象，目标名必须明确或由用户选择。
- `9bba337`：所选资料先用既有 `inputFromMinorUnits` 将 USD 最小单位1250转为主单位字符串12.50；项目、账号及未知实物价格发送 null。保持原七字段边界，不新增备注、联系方式或账期；模型不能从缺失账期推算每月费用。固定包请求回归断言仅发送所选订阅、金额12.50和原七字段。
- 未新增依赖或复制上游代码，继续用 SDK、Zod、RxDB、现有审核／金额／时区／提醒实现。
