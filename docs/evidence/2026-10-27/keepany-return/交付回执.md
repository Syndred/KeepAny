## 首次失败与修正边界

1. 本轮开始前的 `1939e30` 已有 1 个重型加密单测预算不足和 12 个与当前 UI 不符的断言失败。仅按既有模式调整重流程测试预算，更新重复控件、分类、关联入口和图全览／阅读方式的测试前提；不修改加密参数或放宽字号、遮挡、居中标准。详见 [基线分析](baseline-ci-diagnosis.md)、图及原断言专项证据。
2. Node 合成备份夹具在 Dexie 先加载时缓存空 IndexedDB 依赖。顺序复现先失败，显式绑定既有模拟 API 后实际读写通过；统一三处夹具，产品运行时不变。见 [因果复现](node-fixture-cached-dependency-repro.json) 与 [定向结果](node-fixture-targeted-result.json)。
3. `7ef1b99` 全套中的 3 个页面失败显示入口模块 `ERR_ABORTED`、空 root，取消来源没有证实。批量操作改用实际返回／侧栏导航，保留原首次冷启动、明确刷新与末尾 KDBX 冷重开边界，原字段／原图／备份及几何断言不变。最终 19 个不同相关场景通过；不将测试路径修正表述为已定位并修复产品启动缺陷。见 [独立复核](navigation-fixture-review.json)。
4. `65636db` 有 1 个鉴权测试距严格过期窗口仅 0–1 秒，真实时间推进可使 bootstrap 提前被拒。复用 Date-only 固定钟，并显式推进 2,100ms；真实 HTTP、签名、定时器及原拒绝／调用数断言保留，产品鉴权不变。定向 2 项与最终 928 项通过。见 [修正说明](bound-auth-clock-targeted.json) 与 [完整单测](unit-clock-full-result.json)。

失败候选及取消结果保留，不计为通过。CI 浏览器检查改为逐项输出，所有分支推送和 PR 的整套检查保留；版本 tag 复用同一已成功源码，避免相同版本再次重复全套。官网仍保留同 SHA 成功门禁。

本轮教训：改名应以品牌、链接、安装和历史数据升级专项为主；重复扩大验证范围导致耗时过长。今后按实际改动影响选验证项，真实失败先最小复现和定向修复，不反复启动相同全套。
