# 密码表单与多登录标识验收（2026-10-04）

本轮关闭用户提出的眼睛按钮误点、备注折叠、多登录方式、多个小号及按钮相贴问题。复用既有 React 表单、Button、Radix Dialog、i18n、KDBX 和 AI 引用验证，无新依赖或复制上游代码；KeepAnyAdm 未改。

## 结果与交互

- 普通新建／编辑、导入审核卡和片段填写复用同一登录标识组件；一个主账号可添加20个其他邮箱、用户名或手机号，逐项删除。空的附加输入行不写入；标识保持大小写与有效前后空格，只消除精确重复。
- 备注直接显示，已移除「更多信息」折叠。空网址由「添加网址」打开，已有网址可直接编辑；邮箱／App无需填写网址。
- 普通条目和导入审核卡均提供「新增同平台账号」，只带入名称和网址，账号、密码、备注及其他标识留空；导入新卡默认未选，补齐并核对后勾选保存。新建小号不触发AI。
- 眼睛按钮原来通过transform垂直居中，全局active样式替换transform导致按下时移走，松手落到输入框。改为独立44×44点击区与固定布局，显隐按钮离开密码label；单行、多行、普通生成按钮都有实际指针验证。
- 密码范围的所有操作区统一16px，保留4px阴影空间；原文片段到填写按钮16px，收起的填写按钮到下一问题20px。保存中顶部与底部关闭按钮一致禁用，保存完成后正常关闭。

## 加密与AI边界

其他标识保存为独立KDBX的受保护JSON字段 KeepAny.UsernameAliases，随历史、导出、重开及恢复保留。身份／重复规则仍取精确主账号与网址／名称，不能因为共享登录标识自动合并小号。密码、备注、别名没有写入普通资产、MCP、日志或常规同步。

全文AI输出可带其他标识的精确原文引用，仍验证长度、行／字符范围、唯一子串和重叠。旧输出兼容；失败记录不消耗来源。手工添加标识不会扩大原文可见范围，已验证身份也不能暴露密码／备注及JSON编码形式。整批别名参与域名泄漏过滤，包括不发送到域名整理的手工条目。本轮模型为合成服务，没有重新发送真实清单或读取原全库；不宣称真实AI每项分配准确。
