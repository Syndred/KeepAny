# KeepAny 本地可运行版

这是开源核心的**本地版**，使用已构建的 `release/web/`，可在浏览器内管理资产、关系、待办、图片并导出／恢复加密备份。本目录随仓库一起保存；不需要商业账号、Docker 或 PostgreSQL。

密码库现可创建本机加密库，使用主密码解锁，保存／生成／复制密码、恢复历史或回收站、修改主密码和导入／导出 KDBX。账号详情可进入关联密码；旧外部引用保留。整站 `.ka1` 包含加密密码库，恢复后还需原密码库主密码。自动填充与跨设备密码同步尚未提供。实现和验证见 [密码库决策](../docs/adr/0016-本机密码库与KDBX备份.md) 与 [项目交接](../docs/08-项目进度交接.md)。

## 启动和停止

在 macOS 的仓库根目录运行：

```bash
pnpm install --frozen-lockfile   # 首次使用或 node_modules 不存在时执行
./release/start.command
```

打开固定地址 **http://127.0.0.1:4180/**。此命令运行已打包的正式 Web 文件，不执行 `pnpm dev`，也不在启动时重新构建。需要已安装 Node.js 与 pnpm；依赖安装按锁文件进行。若此地址被占用，启动会失败，避免意外换源后看不到原浏览器资料。

```bash
./release/stop.command
```

启动命令在当前终端保持运行；另开终端执行停止命令。停止本地服务不会删除资料。不要把含私人资料的浏览器配置或备份文件提交到仓库。

## 资料位置与升级

资产保存在**使用该地址的浏览器配置文件**中，由 RxDB/Dexie IndexedDB 与本机二进制仓库管理；不是保存在 `release/web/`、服务进程或 PostgreSQL。不同浏览器、隐私窗口或不同端口有独立资料。不要清除站点数据、卸载浏览器配置文件或只凭服务重启判断资料已经备份。

升级前在应用“收录与备份”中创建加密 `.ka1`，点击**保存备份文件**，确认文件已经实际下载并妥善保管密码。停止服务后更新仓库和 `release/web/`；继续用同一浏览器配置文件和 **4180 端口**启动。已打开的旧标签页不会被强制刷新：先保存或取消当前编辑，再刷新该页；如仍显示旧版，再刷新一次，随后核对记录和原图。新版出现“更新应用”提示时，也应先结束当前编辑再点击。不要清除站点数据，也不要换端口或浏览器配置文件。交付包保留本轮升级所需的旧版哈希资源，以供未关闭的旧标签页继续加载。

若原资料在旧的开发地址（如 5173/4173），需在旧地址先下载 `.ka1`，然后在 4180 的干净浏览器配置中预览并确认恢复。恢复后刷新、核对记录和原图。同步不是备份；`.ka1` 不包含工作区密钥，若另行使用实验性同步，密钥须单独保管。

本地版不开放官方云同步、购买或后台自动同步。设备密钥轮换、生产安全审查、真实设备及云端验收尚未完成；当前浏览器的本地读写和加密备份可以独立使用。完整状态见 [项目进度交接](../docs/08-项目进度交接.md)。
